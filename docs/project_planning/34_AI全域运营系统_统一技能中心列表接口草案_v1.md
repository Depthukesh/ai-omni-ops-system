# AI全域运营系统统一技能中心列表接口草案 v1

## 1. 文档目的

本文档用于把统一技能中心从详情接口继续补齐到列表接口层，用于第一阶段：

- 指导统一技能中心列表页对接
- 指导后端分页、筛选、搜索接口设计
- 统一列表页与详情页之间的数据边界

## 2. 接口定位

本接口面向统一技能中心列表页。

建议它承担以下职责：

- 返回能力包列表
- 支撑搜索、筛选、分页和排序
- 返回足够的摘要信息，供列表页直接展示

不建议列表接口一次性返回详情页全部资产对象。

## 3. 主查询接口建议

### 3.1 接口路径

```http
GET /api/admin/skill-packages
```

### 3.2 使用场景

- 统一技能中心列表页
- 能力包选择弹窗
- 模块默认能力包绑定下拉选择器

## 4. 查询参数建议

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | `string` | 否 | 搜索能力包名称、标识、技能名称 |
| `moduleKey` | `string` | 否 | 按挂载模块筛选 |
| `status` | `string` | 否 | 按状态筛选 |
| `scope` | `string` | 否 | 按作用域筛选 |
| `providerType` | `string` | 否 | 按默认 Provider 类型筛选 |
| `hasBrandOverride` | `boolean` | 否 | 是否存在品牌覆盖 |
| `enabledOnly` | `boolean` | 否 | 是否只看启用状态 |
| `page` | `number` | 否 | 页码，默认 `1` |
| `pageSize` | `number` | 否 | 每页数量，默认 `20` |
| `sortBy` | `string` | 否 | 排序字段 |
| `sortOrder` | `string` | 否 | `asc` / `desc` |

## 5. 推荐筛选项

第一阶段建议优先支持：

- `keyword`
- `moduleKey`
- `status`
- `scope`
- `page`
- `pageSize`
- `sortBy`
- `sortOrder`

可在 P1 再补：

- `providerType`
- `hasBrandOverride`
- `enabledOnly`

export interface SkillPackageListResponse {

## 7. 列表项 DTO 草案

```ts
export interface SkillPackageListItemDTO {
  id: string;
  packageKey: string;
  packageName: string;
  description?: string;
  status: "DRAFT" | "ACTIVE" | "DISABLED" | "ARCHIVED";
  scope: "PLATFORM" | "BRAND" | "USER";
  moduleSummaries: ModuleListSummaryDTO[];
  currentVersionNumber?: string;
  defaultProviderSummary?: {
    providerType: string;
    providerName?: string;
    modelName?: string;
  };
  brandOverrideCount: number;
  userOverrideCount: number;
  promptCount: number;
  updatedAt: string;
}
```

### 7.1 `moduleSummaries`

```ts
export interface ModuleListSummaryDTO {
  moduleKey: string;
  moduleName: string;
}
```

## 8. 列表页字段映射建议

列表页建议直接展示：

- `packageName`
- `packageKey`
- `moduleSummaries`
- `status`
- `currentVersionNumber`
- `defaultProviderSummary`
- `brandOverrideCount`
- `updatedAt`

不建议第一阶段在列表页展示：

- 全量 Prompt 内容
- 全量 references
- 全量 scripts
- 全量知识绑定

## 9. 排序建议

建议至少支持：

- `updatedAt desc`
- `packageName asc`
- `status asc`
- `currentVersionNumber desc`

默认建议：

```text
sortBy=updatedAt
sortOrder=desc
```

## 10. 搜索建议

第一阶段搜索范围建议限制在：

- `package_name`
- `package_key`
- `skill_name`

这样既能满足常用搜索，又不会一开始把查询做得过重。

## 11. 错误码建议

| 错误码 | 场景 |
|---|---|
| `INVALID_PAGE_PARAM` | 分页参数非法 |
| `INVALID_SORT_FIELD` | 排序字段不支持 |
| `INVALID_FILTER_PARAM` | 筛选参数不合法 |
| `FORBIDDEN` | 当前用户无权限查看 |

## 12. 第一阶段最小实现集合

第一阶段建议先保证：

- 分页
- 关键词搜索
- 状态筛选
- 模块筛选
- 更新时间排序

这五项一旦跑通，统一技能中心列表页就已经可用。

## 13. 与其他接口的边界

### 与详情接口

- 列表接口只返回摘要对象
- 详情接口负责返回完整资产和版本信息

### 与选择器接口

- 如果后续下拉选择场景很多，可以再拆一个轻量接口
- 第一阶段可先复用列表接口，加 `pageSize` 和轻量字段模式

## 14. 最终结论

统一技能中心列表接口的第一阶段目标，不是做一个复杂检索中心，而是先稳定支撑：

- 查找能力包
- 筛选能力包
- 快速进入详情页

先把列表页跑顺，再逐步补高级筛选和更多统计字段，节奏最稳。
