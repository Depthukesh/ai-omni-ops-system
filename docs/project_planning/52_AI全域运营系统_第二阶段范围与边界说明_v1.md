# AI全域运营系统 第二阶段范围与边界说明 v1

## 1. 文档目的

本文档用于正式定义第二阶段启动范围，回答 3 个问题：

- 第二阶段本轮先做什么
- 第二阶段本轮明确不做什么
- 第二阶段如何在不影响现有网站运行的前提下推进

---

## 2. 第二阶段总目标

第二阶段当前优先目标定义为：

- **知识库与能力包深度联动**

更具体地说，是把第一阶段仍偏桥接的知识挂载能力，推进为：

- 能力包与知识空间的独立关系层
- 后台可维护的知识关系治理页面
- 后续检索策略、默认知识空间和运行时装配的稳定基础

---

## 3. 本轮纳入范围

本轮第二阶段 first pass 纳入以下内容：

### 3.1 数据层

- 新增独立关系表：
  - `SkillPackageKnowledgeSpace`
- 关系字段 first pass 包括：
  - `packageId`
  - `packageKey`
  - `packageName`
  - `knowledgeBaseId`
  - `relationType`
  - `priority`
  - `retrievalMode`
  - `isRequired`
  - `enabled`
  - `remarks`

### 3.2 后端层

- 新增后台关系服务：
  - `SkillPackageKnowledgeSpacesService`
- 新增后台关系接口：
  - 列表
  - 按能力包查询
  - 按知识库查询
  - 创建
  - 修改
  - 删除
- 延续第一阶段约定：
  - 数据库优先
  - `mock-data` 兜底

### 3.3 前端层

- 在后台“模块中心 / 能力包治理”中新增：
  - `知识关系` 子页
- 新增能力包知识关系列表、筛选、创建、编辑、删除
- 保留第一阶段能力包详情页内已有的 `KnowledgeBinding` 区块，不做破坏性替换

### 3.4 文档层

- 第二阶段启动文档包
- 数据库归档同步更新
- 变更记录同步更新

---

## 4. 本轮明确不纳入范围

为避免第二阶段一开始范围失控，本轮不纳入以下事项：

### 4.1 不做运行时检索链路重构

当前不做：

- 真实 RAG 检索执行链路改造
- Prompt 执行时自动按 `SkillPackageKnowledgeSpace` 装配知识上下文
- 知识召回、重排、切片策略的运行时落地

说明：

- 本轮先把治理层和关系真源补齐
- 运行时接线留到第二阶段后续批次

### 4.2 不替换第一阶段通用桥接层

当前不删除、不停用：

- `KnowledgeBinding`

说明：

- 第一阶段桥接层仍继续服务模块、Prompt、工作流步骤和能力包详情页 first pass
- 第二阶段只是为能力包知识关系新增更长期、专用的治理层

### 4.3 不进入多品牌 override 正式化

当前不做：

- `brandOverrides`
- `userOverrides`
- `BRAND_OVERRIDE / USER_OVERRIDE` 的完整运行时生效链路

说明：

- 关系类型字段先预留
- 真正的品牌/用户覆盖能力后续单独推进

### 4.4 不进入 Provider 独立域

当前不做：

- 独立 `ProviderBinding` 正式表
- 版本快照与知识关系联动回放

---

## 5. 交付边界

本轮交付完成的标准是：

- 后端 `SkillPackageKnowledgeSpace` 关系表可用
- 后台 `知识关系` 子页可直接增删改查
- 数据库可用时走 PostgreSQL
- 数据库不可用时仍可回退 mock 演示
- 不影响现有前端业务模块与第一阶段已完成功能

---

## 6. 与第一阶段的衔接关系

第二阶段本轮不是推翻第一阶段，而是在第一阶段基础上继续前进：

- 第一阶段提供：
  - `KnowledgeBase`
  - `KnowledgeBinding`
  - `SkillPackage`
  - 统一技能中心详情页
- 第二阶段本轮新增：
  - `SkillPackageKnowledgeSpace`
  - 独立关系治理页

因此当前阶段关系是：

- 第一阶段解决“先有知识底座与桥接能力”
- 第二阶段本轮解决“能力包知识关系开始独立真源化”

---

## 7. 开发原则

第二阶段本轮继续遵守以下工程原则：

- 以 `docs/project_planning` 为开发依据
- 不影响现有网站功能运行
- 每完成一块，该块功能要可用
- 文档、数据库归档、变更记录同步更新
- 完成后执行 `prisma generate`、前后端 `tsc --noEmit` 和 diagnostics 检查

---

## 8. 本轮结论

第二阶段本轮可以定义为：

- **第二阶段知识主线启动**
- **优先完成能力包知识关系独立层 first pass**

这是当前最稳、最能延续第一阶段成果、同时对现有网站影响最小的切入点。
