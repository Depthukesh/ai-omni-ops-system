# AI全域运营系统 知识库页面与接口对照表 v1

## 1. 文档目的

本文档用于把知识库方向已经规划出来的页面和接口进一步对齐成一张对照表，用于：

- 指导知识库第一阶段前后端联调顺序
- 指导知识库页面开发排期
- 判断哪些页面已经有接口草案，哪些还没有

## 2. 使用说明

阅读方式建议为：

- 先看页面
- 再看对应接口
- 再看依赖主表
- 最后看优先级

## 3. 知识库页面与接口对照表

|---|---|---|---|---|---|

## 4. 当前已经形成草案的接口

目前已经明确草案的接口包括：

- `GET /api/admin/knowledge-spaces`
- `POST /api/admin/knowledge-spaces`
- `GET /api/admin/knowledge-spaces/:spaceId`
- `GET /api/admin/knowledge-spaces/:spaceId/documents`
- `GET /api/admin/knowledge-bindings`
- `GET /api/admin/knowledge-bindings/by-target`
- `POST /api/admin/knowledge-bindings`
- `PATCH /api/admin/knowledge-bindings/:bindingId`
- `DELETE /api/admin/knowledge-bindings/:bindingId`

## 5. 当前已经形成草案的页面字段

目前已经明确字段清单的页面包括：

- 知识空间列表页
- 知识空间详情页
- 文档列表页

## 6. 当前仍待补齐的接口空白

知识库第一阶段后续最值得继续补的接口空白有：

- 知识空间保存接口完整 DTO

## 7. 推荐联调顺序

### 第一步

- 知识空间列表页
- 新建知识空间
- 知识空间详情页

### 第二步

- 文档列表页
- 绑定关系页
- 新增绑定关系

### 第三步

- 检索配置页签
- 能力包知识关系页

### 第四步

- 同步任务
- 检索日志

## 8. 最小闭环建议

如果知识库第一阶段只先做一个最小闭环，建议是：

1. 能创建知识空间  
2. 能查看知识空间详情  
3. 能查看文档列表  
4. 能建立模块或能力包绑定  
5. 能控制绑定启用状态和优先级  

做到这 5 点，知识库第一阶段核心闭环就已经建立起来。

## 9. 最终结论

这张页面与接口对照表的价值，在于把“哪些知识库页面已经能做、哪些接口已经有、哪些地方还缺口”一眼看清楚。

知识库后续开发时，建议始终以这张表作为联调和排期的辅助底稿。
