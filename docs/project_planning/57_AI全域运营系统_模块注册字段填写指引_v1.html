AI全域运营系统 模块注册字段填写指引 v1

1. 文档目的

本文档用于说明“新建模块”弹窗里每个字段到底是什么、哪些必须手工填写、哪些当前可不填、哪些已经改成后台真实选择器，以及哪些后续仍需继续真源化。

2. 当前总体原则

  • 必填手工录入：当前必须由用户手工填写，否则模块定义不完整。
  • 系统直接可选：当前已经做成固定下拉或布尔开关，用户直接选即可。
  • 推荐填写：当前不是强制，但建议补齐，便于后续治理和接线。
  • 当前可不填 / 兼容补充：当前阶段可以先留空，或在真实选择器之外补充历史值。

3. 基础信息区

3.1 必填手工录入

  • moduleName：模块名称，中文展示名。
  • moduleKey：模块标识，建议英文短横线命名。
  • entryRoute：入口路由，例如 /wechat。

3.2 系统直接可选

  • moduleType：模块类型，当前直接从固定枚举中选择。
  • moduleStatus：模块状态，当前直接从固定枚举中选择。
  • phasePriority：阶段优先级，当前直接从固定枚举中选择。

3.3 推荐填写

  • description：模块说明，用于说明模块做什么。
  • sortOrder：排序，用于列表和菜单排序。

3.4 当前可不填

  • icon：图标标识，没有统一图标 key 时可先留空。

4. 展示与可见性区

4.1 系统直接可选

  • isPlatformVisible：平台端可见。
  • isBrandVisible：品牌端可见。
  • isAdminVisible：管理端可见。

这三个字段当前已经是固定开关，不需要用户自由填写。

4.2 推荐填写

  • featureFlags：功能开关，当前仍需手工填写，每行一个；后续应和统一功能开关配置中心对齐。

5. 权限与依赖区

5.1 当前已升级为结构化优先

  • requiredPermissions：所需权限。
  • requiredCapabilities：依赖能力域。

这是模块注册最关键的运行约束字段。当前已支持优先从已注册模块中复用建议项，如果建议项还不够，再按每行一个手工补充。

5.2 当前已升级为结构化优先

  • requiredProviders：Provider 依赖。
  • requiredTables：表依赖。
  • requiredStorages：存储依赖。
  • requiredThirdPartyPlatforms：第三方平台依赖。

requiredProviders、requiredTables、requiredStorages、requiredThirdPartyPlatforms 当前都已支持优先从已注册模块沉淀项中复用，如果建议项里没有需要的值，仍然可以继续按每行一个手工补充。其中 requiredProviders 仍按依赖类型理解，如 text、image、video；requiredStorages、requiredThirdPartyPlatforms 仍属于可不填字段，只有模块确实依赖时再补。

6. 任务与流程区

6.1 当前已升级为结构化优先

  • taskTypes：任务类型。

6.2 推荐填写

  • mediaTypes：媒体类型。
  • workflowTypes：工作流类型。

taskTypes、mediaTypes、workflowTypes 当前都已支持从已注册模块沉淀项中复用，如果当前建议项里没有需要的值，仍然可以继续按每行一个手工补充。

6.3 当前可不填

  • publishTargets：发布目标。

7. 默认绑定区

这一组是当前最容易误解、也是这轮继续推进的字段。

  • defaultSkillPackages：默认能力包。
  • defaultKnowledgeSpaces：默认知识空间。
  • defaultProviderPolicies：默认 Provider 策略。

defaultSkillPackages 已接入后台能力包真实列表，当前按 packageKey 保存；defaultKnowledgeSpaces 已接入后台知识库真实列表，当前按 slug 保存；defaultProviderPolicies 当前按 Provider + 策略模板 做 first pass 选择，当前按 策略模板:providerId 保存，例如 PRIMARY:provider_openai。

为了兼容旧数据和暂未纳入选择器的值，界面仍保留“手工补充”输入框，因此这一组现在是“优先用真实选择器，必要时再手工补充”。后续真正还要继续收口的是 defaultProviderPolicies，它目前是基于 Provider 列表派生策略模板，还不是真正独立的 Provider Policy 域。

8. 备注区

  • remarks：备注，当前可不填。

主要用于补充上下游说明、临时限制、交接备注，不影响系统直接运行。

9. 当前最小填写建议

如果当前只是想先把模块注册起来，建议至少填写以下字段：

  • moduleName
  • moduleKey
  • moduleType
  • moduleStatus
  • entryRoute
  • requiredPermissions
  • requiredCapabilities
  • taskTypes

10. 当前结论

  • 真正必须用户自己填的，主要是模块基础信息、权限依赖、任务类型。
  • 已经可直接选的，是模块类型、模块状态、优先级、可见性。
  • 当前可以先不填的，是图标、备注、发布目标等。
  • 所需权限、依赖能力域、Provider 依赖、表依赖、存储依赖、第三方平台依赖、任务类型、媒体类型、工作流类型已进入“结构化建议项 + 手工补充”阶段。
  • 默认能力包、默认知识空间已经进入真实选择器阶段。
  • 默认 Provider 策略当前为 first pass，已升级为 Provider + 策略模板 选择，后续仍应升级为独立策略选择器。
