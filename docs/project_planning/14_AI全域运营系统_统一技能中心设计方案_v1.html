AI全域运营系统统一技能中心设计方案 v1

本方案用于明确统一技能中心的产品定位、信息架构、数据分层原则与迁移路线，让“技能中心”成为后续能力包治理的统一入口。

核心结论 为什么统一 信息架构 页签结构 数据层原则 迁移路线

1. 核心结论

建议： 产品入口统一为“技能中心”，Prompt 不再作为平行中心存在；但在领域模型与数据库对象上，仍保留 Skill、Prompt、references、scripts、knowledge、Provider 的边界。

统一技能中心的本质不是“技能列表页”，而是“能力包管理中心”。

2. 为什么要统一

继续分开的问题

  • 用户理解成本高
  • 配置入口重复
  • 技能与 Prompt 关系不直观
  • references、scripts、knowledge、Provider 入口继续碎片化
  • 品牌覆盖与用户覆盖入口分散

统一后的收益

  • 产品入口更清晰
  • 能力配置链路更完整
  • 更方便挂接知识库与 Provider 治理
  • 更符合能力包平台化思路

3. 数据层原则

前台和后台只解释一个“技能中心”，但底层对象不建议粗暴合表。
  • SkillPackage：能力包聚合根
  • Skill：能力定义对象
  • PromptAsset：提示词资产对象
  • ReferenceAsset：参考资料对象
  • ScriptAsset：脚本资产对象
  • KnowledgeBinding：知识绑定对象
  • ProviderBinding：Provider 策略绑定对象

4. 统一技能中心的信息架构

列表页

负责发现、筛选、状态查看。建议字段包括技能名称、所属模块、技能状态、当前版本、是否启用、最近更新时间、绑定品牌数、默认 Provider、是否有覆盖。

详情页

负责查看、配置、版本管理、绑定关系管理。建议区域包括基本信息、Prompt、references、scripts、knowledge、Provider、版本、品牌覆盖、用户覆盖。

5. 推荐页签结构

  • 概览
  • Prompt
  • 参考资料
  • 脚本
  • 知识
  • Provider
  • 版本
  • 品牌覆盖
  • 用户覆盖

各页签承载重点

  • 概览： 技能名称、描述、模块、状态、激活版本、默认 Provider、默认知识空间
  • Prompt： system prompt、user prompt 模板、版本、差异对比、回滚
  • 参考资料： references 文档、来源、使用说明
  • 脚本： scripts、参数、调用说明、适用步骤
  • 知识： 绑定知识空间、检索范围、检索优先级、绑定步骤
  • Provider： 默认 Provider、fallback、品牌级覆盖、模型白名单
  • 版本： 能力包版本、变更说明、激活状态
  • 品牌覆盖 / 用户覆盖： Prompt、Provider、知识与偏好覆盖

6. 权限与可见性建议

  • 可见性层级：平台可见、品牌可见、用户可见
  • 角色层级：平台管理员、品牌管理员、普通运营用户
  • 平台管理员管理平台默认能力包
  • 品牌管理员配置品牌覆盖
  • 普通用户仅查看和使用可见能力

7. 迁移路线建议

  1. 先统一命名：对内对外优先使用“技能中心”
  2. 再统一入口：后台管理台和前台能力配置入口逐步收敛
  3. 最后统一对象映射：梳理 Skill / Prompt / references / scripts / Provider 的旧归属，并迁入能力包结构
第一阶段要求： 不必立即重构全部前后台，只需要把命名、信息架构、页面结构、数据边界和迁移路线先定下来。
