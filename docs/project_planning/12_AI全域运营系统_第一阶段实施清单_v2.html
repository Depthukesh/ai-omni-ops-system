  • 规划文档 中存在 备份 目录
  • 架构分析报告在项目 docs 与 规划文档 中存在副本

3. 工作线 A：主仓与文档收束

目标是把主仓、规划区、备份区、项目文档区的关系一次讲清楚。

  • 明确 ai-omni-ops-system 为唯一开发主仓
  • 明确 规划文档 是方案评审区，而非代码主文档区
  • 明确 规划文档/备份 的只读定位
  • 建立规划文档总索引
  • 盘点重复文档与副本关系
建议输出件：规划文档索引、主仓与文档边界说明、副本关系清单。

4. 工作线 B：模块注册机制 v1

目标是建立统一对象 ModuleDefinition，让新增模块不再依赖临时口头约定接入。

字段组 推荐字段
基础字段 moduleKey、moduleName、moduleType、moduleStatus、entryRoute、icon、sortOrder
权限与开关 requiredPermissions、featureFlags、isPlatformVisible、isBrandVisible、isAdminVisible
依赖字段 requiredCapabilities、requiredProviders、requiredTables、requiredStorages
执行字段 taskTypes、mediaTypes、workflowTypes、publishTargets
装配字段 defaultSkillPackages、defaultKnowledgeSpaces、defaultProviderPolicies

第一批必须先对齐品牌增长、小红书、抖音、公众号、设计五个工作台。

5. 工作线 C：能力包机制 v1

目标是把 Skill、Prompt、references、scripts、知识绑定、Provider 策略重新放回一个统一能力包视角。

核心定义： SkillPackage 不是简单等于 Skill，而是能力单元、依赖资产、执行策略和绑定关系的聚合根。
  • 聚合根：SkillPackage
  • 子对象：PromptAsset、ReferenceAsset、ScriptAsset、KnowledgeBinding、ProviderBinding、SkillPackageVersion
  • 第一阶段需完成对象图、绑定关系、覆盖规则和 Skill / Prompt 映射关系说明

6. 工作线 D：统一技能中心方案 v1

目标是把技能、Prompt、references、scripts、knowledge、Provider 等碎片化入口统一收敛为单一产品入口。

产品入口统一为“技能中心”，但领域模型中仍保留 Skill 与 Prompt 的边界。

推荐页面结构

  • 技能列表页
  • 技能详情页
  • Prompt 页签
  • 参考资料页签
  • 脚本页签
  • 知识页签
  • Provider 页签
  • 版本页签
  • 品牌覆盖与用户覆盖页签

7. 工作线 E：超级 service 拆分路线 v1

WorksService 推荐拆分顺序

  1. 第一批：html-render-domain、publish-domain、image-domain
  2. 第二批：copy-domain、workflow-orchestration
  3. 第三批：video-domain

ReportsService 推荐拆分顺序

  1. 第一批：report-generation-domain、insight-domain
  2. 第二批：strategy-domain、campaign-domain

本阶段重点不是立刻开拆，而是先形成职责清单、边界图、批次顺序和拆分风险说明。
