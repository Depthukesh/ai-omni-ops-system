AI全域运营系统 SkillPackage 拆表建议 v1

本建议用于把 SkillPackage 数据结构草案推进到数据库拆表层，指导 Prisma schema 和数据库主表设计。

1. 拆表原则

  • 主对象和资产对象分表
  • 绑定关系单独成表
  • 版本快照独立成表
  • 覆盖层独立成表
  • 多对多关系使用关联表

2. 建议表清单

  • 主表： skill_packages、skill_definitions、skill_package_versions
  • 资产表： prompt_assets、reference_assets、script_assets
  • 绑定表： knowledge_bindings、provider_bindings
  • 覆盖表： brand_skill_package_overrides、user_skill_package_overrides
  • 关联表： skill_package_modules、skill_package_workflow_steps

3. 第一阶段最小落地

P0： skill_packages、skill_definitions、prompt_assets、provider_bindings、skill_package_versions、skill_package_modules

P1： reference_assets、script_assets、skill_package_workflow_steps

P2： knowledge_bindings、brand_skill_package_overrides、user_skill_package_overrides

4. 索引建议

  • skill_packages.package_key 唯一索引
  • prompt_assets.package_id + prompt_key 组合索引
  • provider_bindings.package_id + provider_type + priority 组合索引
  • skill_package_versions.package_id + version_number 组合索引
  • brand_skill_package_overrides.package_id + brand_id 唯一索引

5. 结论

第一阶段不建议把所有内容都塞进一个 config_json 字段里，更合理的是主对象独立、高频资产独立、低频复杂覆盖先在覆盖表中 JSON 化存储。
