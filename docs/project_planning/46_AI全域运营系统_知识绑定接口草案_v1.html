AI全域运营系统 知识绑定接口草案 v1

本草案用于统一知识空间与模块、能力包、Prompt、工作流步骤之间的绑定接口边界。

第一阶段目标： 先稳定支撑建立绑定、查询绑定、控制优先级和启用状态，不把复杂检索逻辑塞进绑定接口。

1. 主接口

查询绑定： GET /api/admin/knowledge-bindings

按目标查询： GET /api/admin/knowledge-bindings/by-target

创建绑定： POST /api/admin/knowledge-bindings

更新绑定： PATCH /api/admin/knowledge-bindings/:bindingId

删除绑定： DELETE /api/admin/knowledge-bindings/:bindingId

2. 创建请求示例

export interface CreateKnowledgeBindingRequest {
  knowledgeSpaceId: string;
  bindingType: "MODULE" | "SKILL_PACKAGE" | "PROMPT" | "WORKFLOW_STEP";
  targetId: string;
  targetKey?: string;
  priority: number;
  retrievalMode: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired?: boolean;
  enabled?: boolean;
}

3. 返回结构

export interface KnowledgeBindingDTO {
  id: string;
  knowledgeSpaceId: string;
  knowledgeSpaceName?: string;
  bindingType: "MODULE" | "SKILL_PACKAGE" | "PROMPT" | "WORKFLOW_STEP";
  targetId: string;
  targetKey?: string;
  targetName?: string;
  priority: number;
  retrievalMode: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired: boolean;
  enabled: boolean;
}

4. 业务校验

  • 同一个 knowledgeSpaceId + bindingType + targetId 不应重复创建
  • priority 必须为正整数
  • 停用的知识空间不建议允许新建绑定
  • MODULE、SKILL_PACKAGE 等绑定应校验目标对象是否存在

5. 结论

只要先把知识绑定的增删改查和优先级控制跑通，知识空间就可以开始和模块、能力包、工作流逐步接轨，而不会影响现有业务链路。
