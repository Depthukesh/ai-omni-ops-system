# AI全域运营系统 能力包注册与关系自动同步说明 v1

## 1. 文档目的

本文档用于说明当前后台里与能力包相关的几个面板：

- `能力包注册`
- `模块绑定`
- `技能绑定`
- `知识关系`

分别哪些字段已经做成：

- 必填
- 系统可选
- 系统同步
- 推荐填写
- 可选兼容

以及目前“一键补齐 / 自动同步”到底是以什么为真源。

---

## 2. 当前总体原则

当前能力包治理不再建议继续靠自由文本硬填，而是按下面优先级处理：

1. **优先读取系统真源**
   - 模块注册中心
   - 能力包注册中心
   - 技能主数据
   - 知识库主数据
   - 技能资产绑定
2. **能自动补齐的关系，优先一键补齐**
3. **不能自动补齐的，再允许手工兼容**

---

## 3. 能力包注册面板

### 3.1 必填

- `packageName`
  - 能力包名称
- `packageKey`
  - 能力包标识

### 3.2 系统可选

- `status`
  - 状态
- `scope`
  - 作用域

### 3.3 系统同步

- `moduleKeys`
  - 所属模块

说明：

- 当前已经不建议只写逗号文本
- 优先从模块注册中心勾选真实模块
- 仍保留文本框用于兼容历史值

### 3.4 推荐填写

- `description`
  - 说明
- `sortOrder`
  - 排序
- `workflowStepKeys`
  - 工作流步骤

### 3.5 当前可选 / 兼容

- `currentVersionId`
- `tags`
- `defaultKnowledgeSpaceIds`
- `defaultProviderPolicyIds`
- `remarks`

说明：

- 这些字段当前仍有一部分是兼容字段
- 后续应继续和独立关系表或主数据真源对齐

---

## 4. 模块绑定面板

### 4.1 当前已支持的自动同步

#### 正向补齐

真源：

- 模块注册里的 `defaultSkillPackages`

动作：

- 如果模块摘要里声明了默认能力包
- 但模块绑定关系表中还没有真实关系
- 系统支持：
  - 一键补齐全部默认关系
  - 只补齐某个模块

#### 反向回填

真源：

- 模块绑定关系表中
  - `bindingType = DEFAULT`
  - `isDefault = true`
  - `enabled = true`
  的记录

动作：

- 如果关系表里已经存在默认挂载
- 但模块注册中的 `defaultSkillPackages` 还没声明
- 系统支持：
  - 一键回填全部模块摘要
  - 只回填某个模块

### 4.2 当前结论

- 模块注册和模块绑定关系表已经形成双向对照
- 这是目前最接近“自动把前端真实模块关系同步到后台”的 first pass

---

## 5. 技能绑定面板

### 5.1 当前已支持的自动同步

真源：

- `skillAssetBinding`

动作：

- 如果 `skillAssetBinding` 里已经声明了：
  - 某个技能属于哪些能力包
- 但能力包技能关系表里还没有真实关系
- 系统支持：
  - 一键同步全部技能关系
  - 只同步某个技能

### 5.2 同步规则

- `PRIMARY / isPrimary = true`
  - 会优先映射为：
    - `bindingType = DEFAULT`
    - `isDefault = true`
- 其他绑定
  - 当前 first pass 映射为：
    - `bindingType = OPTIONAL`
- `enabled`
  - 优先沿用绑定记录中的值
- `sortOrder`
  - 优先沿用绑定记录中的值

### 5.3 当前结论

- 技能绑定面板已经不是纯手工挂技能
- 当前已开始以技能资产绑定作为系统真源做 first pass 同步

---

## 6. 知识关系面板

### 6.1 当前已支持的自动同步

真源：

- 能力包主数据里的 `defaultKnowledgeSpaceIds`

动作：

- 如果能力包已经声明了默认知识空间
- 但知识关系表中还没有真实关系
- 系统支持：
  - 一键同步全部知识关系
  - 只同步某个能力包

### 6.2 当前同步规则

- 自动补齐生成的关系默认写入：
  - `relationType = DEFAULT`
  - `retrievalMode = HYBRID`
  - `enabled = true`
  - `isRequired = false`

### 6.3 当前结论

- 知识关系已经开始从能力包主数据的桥接字段沉淀为独立关系表
- 这是知识主线 second phase 的 first pass 真源化

---

## 7. 关于“能否自动把前端真实模块及关系同步到后台”

答案是：**可以，但当前采用的是“结构化真源同步”，不是去解析前端页面 DOM”。**

也就是说，当前同步逻辑不是：

- 读取浏览器页面长什么样
- 再去猜关系

而是优先读取系统里已经存在的结构化真源：

- 模块注册
- 能力包注册
- 技能资产绑定
- 知识库主数据
- 能力包默认知识空间

这是更稳妥的方式，因为：

- 不会受前端页面排版变化影响
- 不会把展示层误当成业务真源
- 更适合后续做 API 化和批量治理

---

## 8. 当前还没完全自动同步的部分

下面这些目前还没有完全真源化：

- `能力包注册` 里的 `defaultProviderPolicyIds`
- `能力包注册` 里的 `currentVersionId`
- 更细粒度的“前端板块 -> 能力包 -> 技能 -> 知识”全链路自动回写
- 冲突处理：
  - 同一个模块出现多套默认挂载候选
  - 同一个技能出现多套互斥能力包候选

---

## 9. 当前已加入的冲突提示

为了避免“一键补齐”把原本已经有冲突的数据继续放大，当前后台已开始把下面这些情况单独列为待人工处理：

### 9.1 模块绑定

- 同一模块下：
  - 同一个能力包重复挂载
  - `isDefault = true` 但 `bindingType` 不是 `DEFAULT`
  - 模块摘要中的 `defaultSkillPackages` 与关系表默认挂载不一致

### 9.2 技能绑定

- 同一技能下：
  - 同一个能力包重复挂载
  - 技能资产绑定里的主绑定与关系表默认挂载不一致
  - `isDefault = true` 但 `bindingType` 不是 `DEFAULT`
  - 主绑定候选过多

### 9.3 知识关系

- 同一能力包下：
  - 同一个知识库重复挂载
  - 能力包默认知识空间与关系表默认知识关系不一致
  - 存在启用中的强制覆盖关系

---

## 10. 下一步建议

建议下一轮优先做：

1. 冲突检测面板
2. 同步来源标记
3. 同步后差异确认

例如：

- 哪条关系来自模块摘要
- 哪条关系来自技能资产绑定
- 哪条关系来自手工新增
- 哪条关系存在冲突，需要人工确认
