AI全域运营系统 第二阶段迁移与风险清单 v1

本文档定义第二阶段启动批次的迁移顺序、主要风险和回退边界，确保变更集中在后台治理域且可控。

1. 推荐迁移顺序

  1. 更新 Prisma schema 与迁移 SQL
  2. 执行 npx prisma generate
  3. 补后端 service / controller / module
  4. 补前端服务层与独立关系页
  5. 同步项目文档、数据库归档、变更记录

2. 主要风险

重点风险：Prisma 双向关系不完整、schema 与迁移 SQL 不一致、前后端 payload 结构不一致、与第一阶段 KnowledgeBinding 概念混淆。
  • 补齐 KnowledgeBase 反向关系字段
  • 迁移中同步补索引与外键
  • 前端根据能力包元数据自动补齐 packageKey / packageName
  • 明确区分第一阶段桥接层与第二阶段治理层

3. 回退策略

  • 页面层：临时隐藏 知识关系 子页入口
  • 接口层：保留代码但不在前端调用
  • 数据层：数据库不可用时回退 mock-data.skillPackageKnowledgeSpaces

4. 验证清单

  • npx prisma generate
  • npm --workspace apps/server exec tsc --noEmit
  • npm --workspace apps/web exec tsc --noEmit
  • 后台 知识关系 页可打开、筛选、新增、编辑、删除
  • 第一阶段能力包详情 Knowledge 区块仍可正常使用
