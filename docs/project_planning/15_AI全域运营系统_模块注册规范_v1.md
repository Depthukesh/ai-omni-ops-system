# AI全域运营系统模块注册规范 v1

## 1. 文档目的

本文档用于定义系统未来新增模块、改造现有模块时必须遵循的统一注册规范。

目标是解决两个问题：

- 让现有工作台与未来新模块都能按同一模板接入
- 让模块接入不再依赖临时口头约定

## 2. 核心原则

模块注册必须遵循以下原则：

1. 先注册，后接入  
2. 先定义边界，后开发页面  
3. 先声明依赖，后绑定能力  
4. 先说明任务与媒体合同，后进入工作流  

## 3. 统一注册对象

建议定义统一注册对象：

- `ModuleDefinition`

这个对象不代表页面组件，而代表“一个可被平台识别、授权、装配、治理的模块单元”。

## 4. 字段分组

## 4.1 基础字段

- `moduleKey`
- `moduleName`
- `moduleType`
- `moduleStatus`
- `entryRoute`
- `icon`
- `sortOrder`
- `description`

说明：

- `moduleKey` 必须全局唯一
- `moduleType` 用于区分工作台、领域能力、底座能力等角色
- `entryRoute` 用于指向入口路由

## 4.2 权限与可见性字段

- `requiredPermissions`
- `featureFlags`
- `isPlatformVisible`
- `isBrandVisible`
- `isAdminVisible`

说明：

- `requiredPermissions` 用于控制访问权限
- `featureFlags` 用于控制实验开关或阶段开关
- `isPlatformVisible / isBrandVisible / isAdminVisible` 用于区分不同端的显示

## 4.3 依赖字段

- `requiredCapabilities`
- `requiredProviders`
- `requiredTables`
- `requiredStorages`
- `requiredThirdPartyPlatforms`

说明：

- 这些字段用于描述模块的底座依赖，而不是由代码里隐式耦合

## 4.4 执行字段

- `taskTypes`
- `mediaTypes`
- `workflowTypes`
- `publishTargets`

说明：

- 如果一个模块会触发任务、生成媒体、参与工作流或发布动作，这些都必须在注册时声明

## 4.5 装配字段

- `defaultSkillPackages`
- `defaultKnowledgeSpaces`
- `defaultProviderPolicies`

说明：

- 这些字段用于把模块与能力包、知识空间和 Provider 策略绑定起来

## 5. 必填字段与扩展字段

## 5.1 必填字段

以下字段建议作为模块注册的必填字段：

- `moduleKey`
- `moduleName`
- `moduleType`
- `moduleStatus`
- `entryRoute`
- `requiredPermissions`
- `requiredCapabilities`
- `taskTypes`
- `featureFlags`

## 5.2 推荐字段

以下字段建议优先补齐，但允许分阶段完善：

- `requiredProviders`
- `requiredTables`
- `mediaTypes`
- `workflowTypes`
- `defaultSkillPackages`

## 5.3 扩展字段

以下字段允许在未来扩展：

- `requiredStorages`
- `requiredThirdPartyPlatforms`
- `defaultKnowledgeSpaces`
- `defaultProviderPolicies`

## 6. `moduleType` 推荐枚举

建议统一枚举如下：

- `WORKBENCH`
- `DOMAIN`
- `PLATFORM_CORE`
- `ADMIN_TOOL`
- `EXTERNAL_BRIDGE`

含义如下：

- `WORKBENCH`：用户直接使用的业务工作台
- `DOMAIN`：可复用的领域能力模块
- `PLATFORM_CORE`：平台底座能力
- `ADMIN_TOOL`：后台管理工具
- `EXTERNAL_BRIDGE`：外部系统或外挂桥接模块

## 7. `moduleStatus` 推荐枚举

- `PLANNING`
- `ACTIVE`
- `DISABLED`
- `ARCHIVED`

## 8. 注册样例

以下是公众号工作台的注册样例结构。

```ts
const wechatWorkbench: ModuleDefinition = {
  moduleKey: "wechat-workbench",
  moduleName: "公众号工作台",
  moduleType: "WORKBENCH",
  moduleStatus: "ACTIVE",
  entryRoute: "/wechat",
  icon: "wechat",
  sortOrder: 40,
  description: "用于公众号文章、图片、HTML 和发布工作流",
  requiredPermissions: ["wechat:workspace:read", "wechat:workspace:write"],
  featureFlags: ["wechat-workbench"],
  isPlatformVisible: true,
  isBrandVisible: true,
  isAdminVisible: true,
  requiredCapabilities: ["copy-domain", "image-domain", "html-render-domain", "publish-domain"],
  requiredProviders: ["text", "image"],
  requiredTables: ["Task", "MediaAsset", "Work"],
  requiredStorages: ["oss"],
  requiredThirdPartyPlatforms: ["wechat-official-account"],
  taskTypes: ["WECHAT_ARTICLE_AI", "WECHAT_IMAGE_AI", "WECHAT_HTML_AI"],
  mediaTypes: ["wechat-cover", "wechat-body-image", "wechat-html"],
  workflowTypes: ["wechat-content-workflow"],
  publishTargets: ["wechat-api"],
  defaultSkillPackages: ["wechat-article-generator", "wechat-image-designer", "wechat-html-renderer"],
  defaultKnowledgeSpaces: ["brand-wechat-knowledge"],
  defaultProviderPolicies: ["brand-wechat-provider-policy"],
};
```

## 9. 第一批必须落图的模块

第一批建议至少完成以下模块注册样例：

- 品牌增长工作台
- 小红书工作台
- 抖音工作台
- 公众号工作台
- 设计工作台

## 10. 新模块接入模板

未来新增模块时，必须至少回答以下问题：

### 模块身份

- 模块名称是什么
- 模块类型是什么
- 模块入口是什么

### 依赖关系

- 依赖哪些平台底座能力
- 依赖哪些领域能力
- 依赖哪些 Provider
- 依赖哪些第三方平台

### 执行合同

- 会创建哪些任务
- 会生成哪些媒体
- 会参与哪些工作流
- 会发布到哪些目标

### 装配关系

- 默认绑定哪些能力包
- 默认绑定哪些知识空间
- 默认绑定哪些 Provider 策略

## 11. 第一阶段要交付到什么程度

第一阶段不要求完整开发注册后台，但必须完成：

- [ ] 字段字典
- [ ] 枚举定义
- [ ] 5 个工作台样例
- [ ] 新模块接入模板

## 12. 最终结论

模块注册规范的目的不是增加流程负担，而是让系统后续可以像 USB 一样插拔扩展。

只有所有模块先完成统一注册，后面的：

- 能力包绑定
- 知识空间绑定
- Provider 治理
- 任务治理

才能真正标准化。
