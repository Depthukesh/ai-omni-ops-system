AI全域运营系统第一阶段可直接开工任务清单 v1

本清单用于把第一阶段文档体系最终收口成一张“现在就可以开工”的任务表，明确输入、输出、适合负责角色和验收标准。

开工任务 最值得先启动的 6 项 暂不建议开工

1. 可直接开工任务

  • T1： 建立规划文档总索引。建议角色：架构 / 文档。输出：规划文档总索引。
  • T2： 输出主仓与文档边界说明。建议角色：架构 / 文档。输出：主仓与文档边界说明。
  • T3： 确认统一技能中心命名口径。建议角色：产品 / 架构。输出：命名口径确认结论。
  • T4： 输出技能中心列表页字段清单。建议角色：产品 / 前端。输出：列表页字段清单。
  • T5： 输出技能中心详情页页签结构。建议角色：产品 / 前端。输出：页签结构确认稿。
  • T6： 输出 ModuleDefinition 字段字典。建议角色：架构 / 后端。输出：字段字典。
  • T7： 完成 5 个工作台注册样例。建议角色：架构 / 后端。输出：样例清单。
  • T8： 输出 SkillPackage 对象关系图。建议角色：架构 / 后端。输出：能力包对象关系图。
  • T9： 输出品牌覆盖与用户覆盖规则。建议角色：架构 / 产品。输出：覆盖规则说明。
  • T10： 确认 WorksService 第一批拆分对象。建议角色：架构 / 后端。
  • T11： 确认 ReportsService 第一批拆分对象。建议角色：架构 / 后端。
  • T12： 输出第一阶段实施优先级确认稿。建议角色：架构 / 项目管理。

2. 最值得先启动的 6 项

  1. T1 建立规划文档总索引
  2. T2 输出主仓与文档边界说明
  3. T3 确认统一技能中心命名口径
  4. T5 输出技能中心详情页页签结构
  5. T6 输出 ModuleDefinition 字段字典
  6. T8 输出 SkillPackage 对象关系图
判断依据： 这 6 项最能先把第一阶段的入口、对象和结构钉住，对后续所有开发最有帮助。

3. 当前不建议直接开工的事项

暂缓事项： 知识库正式开发、Provider 治理正式开发、WorksService / ReportsService 大规模代码拆分。

原因是第一阶段底座规则仍需先确认，贸然进入高风险开发容易返工。
