AI全域运营系统 知识库主数据层设计草案 v1

本草案用于明确我方系统自己的知识库主数据层，确保后续知识库能力接入时，品牌归属、模块绑定和能力包关系始终掌握在主系统中。

核心结论： 先建设我方知识库主数据层，再把外挂产品作为可替换执行层接入，而不是先把外部产品塞进主链路。

1. 四层结构

  1. 容器层：KnowledgeSpace
  2. 内容层：KnowledgeDocument、KnowledgeChunk
  3. 向量与检索层：KnowledgeEmbedding、KnowledgeRetrievalLog
  4. 绑定与接入层：KnowledgeBinding、KnowledgeSourceSyncTask

其中 KnowledgeSpace 是聚合入口，KnowledgeBinding 是和模块、能力包、工作流接轨的关键挂点。

2. 核心对象

KnowledgeSpace： 承担知识空间归属、权限边界和默认检索配置。

KnowledgeDocument： 记录原始知识文档与来源。

KnowledgeChunk： 记录检索最小内容块。

KnowledgeBinding： 负责把知识空间挂到模块、能力包、Prompt 和工作流步骤上。

KnowledgeSourceSyncTask： 为飞书、网页、API、外部知识库同步预留任务模型。

3. 关键结构示例

export interface KnowledgeSpace {
  id: string;
  spaceKey: string;
  spaceName: string;
  scope: "PLATFORM" | "BRAND" | "MODULE" | "USER";
  ownerBrandId?: string;
  ownerUserId?: string;
  moduleKeys: string[];
  sourceMode: "MANUAL" | "SYNCED" | "HYBRID";
  visibility: "PRIVATE" | "BRAND_SHARED" | "PLATFORM_SHARED";
  status: "DRAFT" | "ACTIVE" | "DISABLED" | "ARCHIVED";
}
export interface KnowledgeBinding {
  id: string;
  knowledgeSpaceId: string;
  bindingType: "MODULE" | "SKILL_PACKAGE" | "PROMPT" | "WORKFLOW_STEP";
  targetId: string;
  priority: number;
  retrievalMode: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired: boolean;
  enabled: boolean;
}

4. 多品牌规则

  1. 平台公共知识
  2. 品牌公共知识
  3. 品牌模块知识
  4. 用户私有临时知识

默认检索优先级建议为：用户私有临时知识 → 品牌模块知识 → 品牌公共知识 → 平台公共知识。

5. 与现有系统的关系

  • 和 Brand 关联：通过 ownerBrandId 承担品牌归属
  • 和 ModuleDefinition 关联：通过 KnowledgeBinding(bindingType = MODULE) 挂默认知识空间
  • 和 SkillPackage 关联：通过 KnowledgeBinding(bindingType = SKILL_PACKAGE) 建立稳定挂点
  • 和工作流步骤关联：按步骤精细绑定知识空间

6. 第一阶段最小落地

P0： KnowledgeSpace、KnowledgeDocument、KnowledgeBinding

P1： KnowledgeChunk、KnowledgeEmbedding、KnowledgeTag

P2： KnowledgeRetrievalLog、KnowledgeSourceSyncTask

接入原则： 第一步只新增后台知识库管理能力，不改现有前台创作流程；后续仅在新步骤里灰度接入知识检索。

7. 最终结论

知识库方向最重要的不是先选哪个外挂产品，而是先把空间归属、文档归属、品牌边界、模块绑定、能力包绑定和工作流步骤绑定统一到我方系统中。这样后续无论接哪种外挂引擎，都不会影响现有网站运行，也不会丢掉平台化主动权。
