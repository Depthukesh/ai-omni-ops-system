# AI全域运营系统 第一阶段数据库落地优先表清单 v1

## 1. 文档目的

本文档用于把前面关于模块注册、能力包、版本、关系表的规划，进一步收束成“第一阶段数据库落地优先表清单”，用于：

- 指导第一阶段数据库建表顺序
- 指导 Prisma schema 拆批实施
- 避免一次性同时改太多表导致风险失控

## 2. 排序原则

第一阶段建议按以下原则排表优先级：

- 先落主对象表
- 再落高频资产表
- 再落高频关系表
- 最后落低频扩展表

判断标准主要看三点：

- 是否直接支撑统一技能中心和模块注册中心
- 是否直接影响接口开发
- 是否属于第一阶段必需能力

## 3. P0 优先表清单

### 3.1 模块注册相关

- `module_definitions`

用途：

- 承担模块注册主表
- 支撑模块注册中心列表和详情
- 支撑菜单、权限、路由、能力依赖的统一注册

### 3.2 能力包主对象相关

- `skill_packages`
- `skill_definitions`

用途：

- 承担统一技能中心主对象
- 支撑详情页顶部摘要和概览页签

### 3.3 高频资产相关

- `prompt_assets`
- `provider_bindings`

用途：

- 支撑 Prompt 页签
- 支撑 Provider 页签
- 支撑实际模型选择规则

### 3.4 版本与关系相关

- `skill_package_versions`
- `skill_package_modules`

用途：

- 支撑版本管理
- 支撑能力包与模块挂载关系

## 8. 第一阶段最小可运行数据集

如果目标是先把统一技能中心和模块注册中心跑起来，最小数据集建议为：

- `module_definitions`
- `skill_packages`
- `skill_definitions`
- `prompt_assets`
- `provider_bindings`
- `skill_package_versions`
- `skill_package_modules`

只要这 7 张表先落地，第一阶段核心页面和核心接口基本都能对接。

## 10. 风险控制建议

为了避免第一阶段数据库改动过大，建议：

- 先按批次落表，不要一次性全上
- 先保证 P0 表的增删改查可用
- P1、P2 表允许延后
- 对版本表和关系表优先加索引

## 11. 最终结论

第一阶段数据库落地的核心不是“表越全越好”，而是先让最关键的 7 张表支撑：

- 模块注册中心
- 统一技能中心列表页
- 统一技能中心详情页
- 版本管理
- 模块与能力包挂载关系

先把这些跑通，再继续补 references、scripts、knowledge 和覆盖层，会更稳。
