AI全域运营系统 ModuleDefinition 注册后台表单字段草案 v1

本草案用于把模块注册表推进到后台录入表单层，指导模块注册中心的页面设计、字段命名和校验规则。

1. 表单分区建议

  • 基本信息
  • 展示与可见性
  • 权限与依赖
  • 任务与流程
  • 默认绑定
  • 审计与备注

2. P0 必填字段

字段名展示名称控件建议说明
moduleKey模块标识单行输入框全局唯一，英文短横线命名
moduleName模块名称单行输入框面向用户的中文名称
moduleType模块类型下拉框WORKBENCH / DOMAIN / ADMIN_TOOL
moduleStatus模块状态下拉框PLANNING / ACTIVE / DISABLED / ARCHIVED
entryRoute入口路由单行输入框如 /wechat
requiredPermissions所需权限标签输入 / 多选访问模块所需权限
requiredCapabilities依赖能力域标签输入 / 多选如 copy-domain、publish-domain
taskTypes任务类型标签输入 / 多选模块可能产生的任务类型

3. 校验规则建议

强校验： moduleKey 唯一、只能使用英文小写/数字/短横线，entryRoute 必须以 / 开头。

业务校验： ADMIN_TOOL 类型模块的 entryRoute 建议以 /admin/ 开头；若配置了 defaultSkillPackages，这些能力包应能在技能中心查到。

4. 第一阶段最小表单集合

P0： 基本信息、权限与依赖、任务与流程、默认能力包绑定

P1： 展示与可见性、审计与备注

P2： 默认知识空间、默认 Provider 策略、更多发布目标配置

5. 结论

第一阶段不需要做成很重的配置平台，只要先把标准化录入、查看、编辑模块定义的页面跑通，模块注册机制就能真正落地。
