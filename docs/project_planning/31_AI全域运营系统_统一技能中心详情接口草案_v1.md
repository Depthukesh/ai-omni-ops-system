# AI全域运营系统统一技能中心详情接口草案 v1

## 1. 文档目的

本文档用于把《统一技能中心详情页字段清单 v1》进一步下钻成接口草案，用于第一阶段：

- 指导后端详情接口设计
- 指导前端详情页数据对接
- 统一详情页各页签的数据返回边界

## 2. 接口定位

本接口面向统一技能中心详情页。

建议它承担以下职责：

- 返回一个能力包的完整详情
- 支撑顶部摘要区与九个页签的数据展示
- 支撑第一阶段的版本查看、Prompt 管理、Provider 查看

不建议第一阶段直接让它承担所有编辑动作。

编辑动作建议拆成独立更新接口，避免一个大接口承担过多写操作。

## 3. 主查询接口建议

### 3.1 接口路径

```http
GET /api/admin/skill-packages/:packageId
```

如果后续统一以 `packageKey` 作为外部标识，也可以补一个：

```http
GET /api/admin/skill-packages/by-key/:packageKey
```

### 3.2 适用对象

- 后台统一技能中心详情页
- 后续能力包审计页
- 后续版本对比页的基础数据读取

## 4. 查询参数建议

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `includePrompts` | `boolean` | 否 | 是否返回 Prompt 列表 |
| `includeReferences` | `boolean` | 否 | 是否返回参考资料列表 |
| `includeScripts` | `boolean` | 否 | 是否返回脚本列表 |
| `includeKnowledge` | `boolean` | 否 | 是否返回知识绑定 |
| `includeProviders` | `boolean` | 否 | 是否返回 Provider 绑定 |
| `includeVersions` | `boolean` | 否 | 是否返回版本列表 |
| `includeBrandOverrides` | `boolean` | 否 | 是否返回品牌覆盖 |
| `includeUserOverrides` | `boolean` | 否 | 是否返回用户覆盖 |

第一阶段建议默认：

- `includePrompts=true`
- `includeProviders=true`
- `includeVersions=true`

其他部分可按需懒加载。

- `versions`

- `references`
- `scripts`
- `knowledgeBindings`
- `brandOverrides`

## 8. 第一阶段最小返回集合

第一阶段建议先稳定返回：

- `package`
- `skill`
- `moduleSummaries`
- `prompts`
- `providerBindings`
- `versions`

可延后返回：

- `workflowStepSummaries`
- `references`
- `scripts`
- `knowledgeBindings`
- `brandOverrides`
- `userOverrides`

## 9. 错误码建议

| 错误码 | 场景 |
|---|---|
| `SKILL_PACKAGE_NOT_FOUND` | 能力包不存在 |
| `SKILL_PACKAGE_ARCHIVED` | 能力包已归档，不允许查看详情 |
| `FORBIDDEN` | 当前用户无权限查看 |
| `INVALID_INCLUDE_PARAM` | include 参数不合法 |

## 10. 后续写接口建议

不建议把详情读取接口和编辑接口混用。

建议后续拆出：

- `PATCH /api/admin/skill-packages/:packageId/basic`
- `PATCH /api/admin/skill-packages/:packageId/prompts/:promptId`
- `PATCH /api/admin/skill-packages/:packageId/providers/:bindingId`
- `POST /api/admin/skill-packages/:packageId/versions`
- `POST /api/admin/skill-packages/:packageId/activate-version`

## 11. 最终结论

统一技能中心详情接口的第一阶段目标，不是一次性返回所有复杂对象，而是先稳定支撑详情页最核心的 5 块：

- 顶部摘要
- 概览
- Prompt
- Provider
- 版本

在这个基础上，再逐步把 references、scripts、knowledge、品牌覆盖和用户覆盖补进去，会更稳。
