AI全域运营系统 第一阶段测试与验收报告 v1

本文档用于说明第一阶段成果如何测试、如何验收，以及什么结果可以视为第一阶段收尾通过。

1. 测试目标

  1. 第一阶段核心底座已经可以正常使用
  2. 后台管理入口已经形成最小可维护闭环
  3. 数据库优先 / mock 兜底策略仍然成立
  4. 新底座没有明显影响现有业务模块运行

2. 测试前准备

安装依赖：

npm install

首次初始化数据库：

npm run db:init

刷新 Prisma Client 与表结构：

npm run prisma:generate
npm run prisma:db:push

启动服务：

npm run dev:server
npm run dev:web
说明：后端默认健康检查一般可访问 http://127.0.0.1:3011/api/health；前端地址以终端输出为准。

基础编译检查：

npx prisma generate
npm --workspace apps/server exec tsc --noEmit
npm --workspace apps/web exec tsc --noEmit

4. 回归测试建议

第一阶段收尾时，必须至少做一轮非回归检查。

  • 品牌增长
  • 小红书
  • 抖音
  • 公众号
  • 设计工作台
  • 个人中心
  • 后台登录与管理入口
最低要求：每个模块至少确认页面能打开、关键列表能加载、没有新增的接口 500 或页面崩溃。

5. 验收分级

P0

例如：无法启动、能力包详情无法打开、模块注册中心无法保存、保存后数据全部丢失。

规则：有任一 P0，不得收尾。

P1

例如：first pass 区块功能不稳定、刷新后摘要不同步、关系页可读不可写。

规则：原则上收尾前应修复；如延期，必须明确写入阶段文档。

P2

例如：文案不一致、样式细节问题、预留页签尚未完成。

规则：可转入第二阶段。

6. 第一阶段通过标准

  • 模块注册中心可正常 CRUD
  • 能力包主对象、模块关系、技能关系可正常读写
  • 统一技能中心 basic / prompts / providers / knowledge / references / scripts / versions 可正常操作
  • 知识库与知识绑定底座可正常使用
  • 前后端 TypeScript 校验通过
  • 无新增 P0
  • 既有主要业务模块无明显回归
结论：满足以上条件，就可以把第一阶段按“核心底座收尾”正式收口。
