# AI全域运营系统 第二阶段对象与数据扩展清单 v1

## 1. 文档目的

本文档用于列出第二阶段本轮涉及的新增对象、字段和数据层扩展，明确：

- 新增什么对象
- 复用什么对象
- 哪些对象仍然保持第一阶段状态不变

---

## 2. 本轮新增核心对象

### 2.1 `SkillPackageKnowledgeSpace`

用途：

- 表示某个能力包与某个知识空间之间的长期关系

定位：

- 第二阶段能力包知识治理专用关系层

推荐表结构：

- `id`
- `packageId`
- `packageKey`
- `packageName`
- `knowledgeBaseId`
- `relationType`
- `priority`
- `retrievalMode`
- `isRequired`
- `enabled`
- `remarks`
- `createdAt`
- `updatedAt`

当前关系约束：

- `@@unique([packageKey, knowledgeBaseId, relationType])`
- 按 `packageKey + enabled + priority` 建索引
- 按 `knowledgeBaseId + enabled + priority` 建索引

### 2.2 视图对象 `SkillPackageKnowledgeSpaceView`

用途：

- 供后台页面直接展示关系信息，不必再次手工拼接知识库名称

附加字段：

- `knowledgeBaseName`
- `knowledgeBaseSlug`
- `knowledgeBaseStatus`

---

## 3. 本轮复用的既有对象

### 3.1 `KnowledgeBase`

继续复用为：

- 知识空间主档

本轮新增关系：

- `KnowledgeBase` 与 `SkillPackageKnowledgeSpace` 建立一对多关联

说明：

- 本轮不重做知识库主对象
- 仅补第二阶段能力包关系层

### 3.2 `SkillPackage`

继续复用为：

- 能力包主对象

本轮关系用途：

- 为 `SkillPackageKnowledgeSpace` 提供 `packageId / packageKey / packageName` 来源

说明：

- 当前 first pass 仍保持反规范化写法，把能力包基础信息冗余到关系表
- 这样做可以减少后台治理页查询复杂度，也与第一阶段关系表风格一致

### 3.3 `KnowledgeBinding`

继续复用为：

- 第一阶段通用桥接层

当前不变：

- 模块知识绑定
- Prompt 知识绑定
- 工作流步骤知识绑定
- 能力包详情页内的桥接式知识维护

说明：

- 第二阶段本轮不删除它
- 只是在能力包治理维度新增一条更稳定的专用关系层

## 4. 字段含义清单

### 4.1 `relationType`

当前预留值：

- `DEFAULT`
- `OPTIONAL`
- `BRAND_OVERRIDE`
- `USER_OVERRIDE`

当前实际使用建议：

- 本轮先以 `DEFAULT`、`OPTIONAL` 为主
- `BRAND_OVERRIDE`、`USER_OVERRIDE` 仅保留结构预留，不在运行时生效

### 4.2 `retrievalMode`

当前预留值：

- `SEMANTIC`
- `HYBRID`
- `MANUAL`

当前含义：

- `SEMANTIC`
  - 语义召回优先
- `HYBRID`
  - 关键词 + 语义混合
- `MANUAL`
  - 仅人工选定或特定流程主动引用

### 4.3 `priority`

用途：

- 控制同一能力包下多个知识空间的排序与默认优先级

当前规则：

- 数值越小优先级越高
- 默认值使用 `100`

### 4.4 `isRequired`

用途：

- 标记当前知识空间是否属于能力包运行或治理中的必带知识来源

当前规则：

- `true` 表示必选
- `false` 表示可选补充

### 4.5 `enabled`

用途：

- 控制关系是否启用

当前规则：

- 已停用关系不参与默认治理视图
- 但仍保留历史记录和后台编辑能力

## 5. 数据写入策略

### 5.1 数据库优先

当满足以下条件时，优先读写数据库：

- `DATABASE_URL` 已配置
- PostgreSQL 可连接
- `SkillPackageKnowledgeSpace` 表已存在

### 5.2 mock 兜底

当数据库不可用或迁移尚未执行时：

- 回退到 `apps/server/src/common/mock-data.ts`

说明：

- 这样可以保证后台治理页在开发期和演示期持续可用

### 5.3 seed 初始化

本轮建议在 `mock-data` 中保留最少 2-3 条演示关系：

- 品牌增长分析能力包 -> 品牌资料知识库
- 公众号文章生成能力包 -> 品牌资料知识库
- 公众号文章生成能力包 -> 飞书运营知识库

---

## 6. 与后续阶段的兼容性要求

本轮数据结构需要为后续能力留接口：

- 品牌级 override
- 用户级 override
- 运行时知识装配
- 版本快照纳入知识关系
- 模块默认知识空间反推

因此本轮要求：

- 关系表字段命名保持稳定
- 不在本轮过度绑定到某一个具体业务模块
- 优先使用能力包作为聚合入口

---

## 7. 本轮结论

第二阶段本轮的数据扩展应理解为：

- 新增一个能力包知识关系专用表
- 继续复用第一阶段知识库主表和桥接层
- 为后续运行时接线与多层 override 留足结构空间
