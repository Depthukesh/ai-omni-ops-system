# AI全域运营系统 第二阶段页面与接口对照表 v1

## 1. 文档目的

本文档用于明确第二阶段本轮 first pass 的页面与接口联调范围，避免出现：

- 页面做了但没有后端接口
- 后端接口落了但前台没有治理入口
- 第一阶段页面与第二阶段页面职责重叠

---

## 2. 页面清单

### 2.1 后台模块中心新增子页

页面：

- `知识关系`

建议位置：

- 后台模块中心左侧子菜单中，作为与：
  - `模块注册`
  - `能力包注册`
  - `模块绑定`
  - `技能绑定`
- 并列的新子页

页面职责：

- 展示能力包与知识空间关系表
- 支持筛选
- 支持创建关系
- 支持编辑关系
- 支持删除关系

### 2.2 第一阶段页面保持不变

本轮不替换：

- 统一技能中心详情页中的 `Knowledge` 区块

说明：

- 第一阶段详情页区块继续承担桥接式知识绑定维护
- 第二阶段新子页承担“能力包知识关系治理页”的职责

## 4. 接口清单

### 4.1 列表接口

- `GET /admin/skill-package-knowledge-spaces`

用途：

- 获取能力包知识关系总列表

建议查询参数：

- `packageKey`
- `knowledgeBaseId`
- `relationType`
- `enabled`

### 4.2 按能力包查询

- `GET /admin/skill-package-knowledge-spaces/by-package/:packageKey`

用途：

- 查看某个能力包下挂了哪些知识空间

### 4.3 按知识库查询

- `GET /admin/skill-package-knowledge-spaces/by-knowledge-space/:knowledgeBaseId`

用途：

- 查看某个知识库被哪些能力包使用

### 4.4 获取单条关系

- `GET /admin/skill-package-knowledge-spaces/:id`

用途：

- 获取单条关系详情

### 4.5 创建关系

- `POST /admin/skill-package-knowledge-spaces`

请求体建议：

- `packageId`
- `packageKey`
- `packageName`
- `knowledgeBaseId`
- `relationType`
- `priority`
- `retrievalMode`
- `isRequired`
- `enabled`
- `remarks`

### 4.6 更新关系

- `PATCH /admin/skill-package-knowledge-spaces/:id`

用途：

- 修改当前关系配置

### 4.7 删除关系

- `DELETE /admin/skill-package-knowledge-spaces/:id`

用途：

- 删除当前关系记录

## 6. 第一阶段页面与第二阶段页面职责拆分

### 6.1 第一阶段能力包详情 `Knowledge`

当前职责：

- 维护通用桥接型知识绑定
- 偏向能力包详情内的附属编辑区

### 6.2 第二阶段独立 `知识关系`

当前职责：

- 维护能力包与知识空间的长期治理关系
- 偏向统一治理、集中维护和双向检索

说明：

- 两者暂时并行存在
- 后续稳定后，再决定是否逐步收口为单一治理入口

---

## 7. 本轮联调结论

第二阶段本轮页面与接口的最小闭环应为：

- 后端关系接口可用
- 前端服务层可用
- 后台独立关系页可用
- 第一阶段现有页面不受影响
