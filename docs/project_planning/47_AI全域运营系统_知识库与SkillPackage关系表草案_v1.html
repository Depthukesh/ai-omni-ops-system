AI全域运营系统 知识库与SkillPackage关系表草案 v1

本草案用于把知识空间与能力包之间的长期关系单独建模，避免把知识空间直接塞进能力包主表。

核心结论： 知识空间与能力包更适合使用带业务属性的多对多关系表，而不是简单数组字段。

1. 关系模型

  • 一个 SkillPackage 可以绑定多个知识空间
  • 一个知识空间也可以被多个能力包复用
  • 关系表建议命名为 skill_package_knowledge_spaces

2. 关系结构示例

export interface SkillPackageKnowledgeRelation {
  id: string;
  packageId: string;
  knowledgeSpaceId: string;
  relationType: "DEFAULT" | "OPTIONAL" | "BRAND_OVERRIDE" | "USER_OVERRIDE";
  priority: number;
  retrievalMode: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired: boolean;
  enabled: boolean;
}

3. 与 KnowledgeBinding 的关系

KnowledgeBinding 是通用绑定协议，面向模块、能力包、Prompt、工作流步骤。

skill_package_knowledge_spaces 是能力包与知识空间长期关系的专用关系表。

第一阶段建议接口先继续走通用 KnowledgeBinding，但文档层提前把长期关系模型定下来。

4. 结论

单独建模后，知识空间才能真正成为能力包体系的一部分，而不是停留在松散外挂引用层。
