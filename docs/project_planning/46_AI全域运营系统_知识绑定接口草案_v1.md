# AI全域运营系统 知识绑定接口草案 v1

## 1. 文档目的

本文档用于把《知识库主数据层设计草案 v1》进一步下钻成知识绑定接口草案，用于第一阶段：

- 指导后端知识绑定接口设计
- 指导前端绑定关系页数据对接
- 统一模块、能力包、Prompt、工作流步骤绑定知识空间的接口边界

## 2. 接口定位

本接口面向后台“知识绑定关系页”。

建议它承担以下职责：

- 创建知识空间与目标对象的绑定关系
- 查询某个知识空间的所有绑定
- 查询某个模块或能力包当前绑定的知识空间
- 支撑后续检索时按优先级和启用状态读取知识空间

第一阶段不建议直接把复杂检索逻辑放进绑定接口。

## 3. 主查询接口建议

### 3.1 按知识空间查询绑定

```http
GET /api/admin/knowledge-bindings
```

查询参数建议：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `knowledgeSpaceId` | `string` | 否 | 按知识空间筛选 |
| `bindingType` | `string` | 否 | `MODULE` / `SKILL_PACKAGE` / `PROMPT` / `WORKFLOW_STEP` |
| `targetId` | `string` | 否 | 按目标对象筛选 |
| `enabled` | `boolean` | 否 | 是否仅查询启用绑定 |

### 3.2 查询单个目标对象的知识空间

```http
GET /api/admin/knowledge-bindings/by-target
```

查询参数建议：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `bindingType` | `string` | 是 | 目标对象类型 |
| `targetId` | `string` | 是 | 目标对象 ID |

## 4. 创建接口建议

```http
POST /api/admin/knowledge-bindings
```

请求体草案：

```ts
export interface CreateKnowledgeBindingRequest {
  knowledgeSpaceId: string;
  bindingType: "MODULE" | "SKILL_PACKAGE" | "PROMPT" | "WORKFLOW_STEP";
  targetId: string;
  targetKey?: string;
  priority: number;
  retrievalMode: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired?: boolean;
  enabled?: boolean;
}
```

## 5. 更新接口建议

```http
PATCH /api/admin/knowledge-bindings/:bindingId
```

请求体草案：

```ts
export interface UpdateKnowledgeBindingRequest {
  priority?: number;
  retrievalMode?: "SEMANTIC" | "HYBRID" | "MANUAL";
  isRequired?: boolean;
  enabled?: boolean;
}
```

## 6. 删除接口建议

```http
DELETE /api/admin/knowledge-bindings/:bindingId
```

第一阶段建议逻辑删除或停用优先，不建议物理删除作为唯一方案。

## 9. 页面映射关系

### 绑定关系页

- `knowledgeSpaceName`
- `bindingType`
- `targetKey`
- `priority`
- `retrievalMode`
- `isRequired`
- `enabled`

### 知识空间详情页中的绑定摘要

- `bindingType`
- `targetKey`
- `priority`
- `enabled`

## 10. 第一阶段最小返回集合

第一阶段建议先稳定返回：

- `id`
- `knowledgeSpaceId`
- `knowledgeSpaceName`
- `bindingType`
- `targetId`
- `targetKey`
- `priority`
- `retrievalMode`
- `enabled`

可延后返回：

- `targetName`
- `isRequired`
- 更多审计字段

## 11. 错误码建议

| 错误码 | 场景 |
|---|---|
| `KNOWLEDGE_SPACE_NOT_FOUND` | 知识空间不存在 |
| `KNOWLEDGE_BINDING_NOT_FOUND` | 绑定关系不存在 |
| `KNOWLEDGE_BINDING_DUPLICATED` | 同一目标对象重复绑定同一空间 |
| `INVALID_BINDING_TYPE` | 绑定类型不合法 |
| `FORBIDDEN` | 当前用户无权限操作 |

## 12. 业务校验建议

- 同一个 `knowledgeSpaceId + bindingType + targetId` 不应重复创建
- `priority` 必须为正整数
- `MODULE` 类型绑定建议校验目标模块是否存在
- `SKILL_PACKAGE` 类型绑定建议校验目标能力包是否存在
- 停用的知识空间不建议允许新建绑定

## 13. 后续扩展接口建议

后续可以继续拆出：

- `POST /api/admin/knowledge-bindings/reorder`
- `POST /api/admin/knowledge-bindings/batch-create`
- `GET /api/admin/knowledge-bindings/effective-by-context`

其中 `effective-by-context` 适合后续在执行期根据品牌、模块、能力包和工作流步骤计算有效知识空间集合。

## 14. 最终结论

知识绑定接口的第一阶段目标，不是直接承载完整检索执行逻辑，而是先稳定支撑三件事：

- 建立绑定
- 查询绑定
- 控制绑定优先级和启用状态

只要这三点跑通，知识空间就已经可以开始和模块、能力包、工作流逐步接轨。
