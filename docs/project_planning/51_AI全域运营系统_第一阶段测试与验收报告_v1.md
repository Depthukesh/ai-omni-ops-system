# AI全域运营系统 第一阶段测试与验收报告 v1

## 1. 文档目的

本文档用于说明第一阶段成果如何测试、如何验收，以及什么结果可以视为第一阶段收尾通过。

适用范围包括：

- 模块注册中心
- 能力包注册中心
- 统一技能中心
- 知识库与知识绑定第一批底座
- 第一阶段数据库真源化成果

---

## 2. 测试目标

第一阶段测试不追求一次性覆盖全部终态，而是验证以下 4 点：

1. 第一阶段核心底座已经可以正常使用  
2. 后台管理入口已经形成最小可维护闭环  
3. 数据库优先 / mock 兜底策略仍然成立  
4. 新底座没有明显影响现有业务模块运行  

---

## 3. 测试前准备

### 3.1 环境准备

在项目根目录执行：

```bash
npm install
```

如果是首次初始化数据库，执行：

```bash
npm run db:init
```

如果不是首次初始化，但希望刷新 Prisma Client 与当前表结构：

```bash
npm run prisma:generate
npm run prisma:db:push
```

### 3.2 启动服务

启动后端：

```bash
npm run dev:server
```

启动前端：

```bash
npm run dev:web
```

说明：

- 后端默认健康检查一般可访问 `http://127.0.0.1:3011/api/health`
- 前端地址以终端输出为准；本地开发通常按 Next.js 默认端口启动

### 3.3 基础编译检查

启动前或提交前，建议先执行：

```bash
npx prisma generate
npm --workspace apps/server exec tsc --noEmit
npm --workspace apps/web exec tsc --noEmit
```

通过标准：

- Prisma Client 正常生成
- 前后端 TypeScript 均无编译错误

## 4. 第一阶段测试清单

### 4.1 模块注册中心

### 测试项

- 打开后台模块注册中心
- 查看模块列表是否正常展示
- 使用关键词、状态、类型筛选列表
- 新建一个模块定义
- 编辑模块定义字段并保存
- 归档一个模块
- 删除一个测试模块

### 通过标准

- 列表、筛选、创建、编辑、归档、删除全流程可用
- 保存后页面数据刷新正常
- 不出现明显报错或白屏

### 4.2 能力包注册中心

### 测试项

- 打开能力包列表
- 查看能力包详情
- 修改基础信息并保存
- 查看模块绑定关系
- 查看技能绑定关系
- 创建版本并激活版本

### 通过标准

- 能力包主数据读写正常
- 版本创建与激活正常
- 列表与详情状态能同步刷新

### 4.3 统一技能中心详情页

### 测试项

- 打开某个能力包详情
- 编辑 `Basic`
- 编辑 `Prompt`
- 编辑 `Provider`
- 新增、编辑、删除 `References`
- 新增、编辑、删除 `Scripts`
- 查看 `Version`

### 通过标准

- 各区块都能独立保存
- 刷新后数据仍存在
- 没有出现保存成功但页面回退旧值的情况

### 4.4 模块与能力包关系

### 测试项

- 在模块默认能力包绑定页查看现有关系
- 新增一条关系
- 修改默认关系状态或排序
- 删除测试关系

### 通过标准

- 模块反查能力包、能力包反查模块均正常
- 后台页面与接口结果一致

### 4.5 技能与能力包关系

### 测试项

- 打开技能绑定页
- 查看技能挂载到哪些能力包
- 新增一条绑定
- 调整绑定类型 / 默认状态 / 启用状态
- 删除测试绑定

### 通过标准

- 技能归属关系可维护
- 后续能力包详情中的技能摘要不出现明显错乱

### 4.6 知识库与知识绑定底座

### 测试项

- 打开后台知识库页
- 查看知识库列表、文件列表、同步记录
- 创建一个知识库
- 创建一条知识绑定
- 更新和删除测试绑定

### 通过标准

- 知识库主表和知识绑定表的 CRUD 基本可用
- 数据库可用时优先走数据库

## 5. 回归测试建议

第一阶段收尾时，必须至少做一轮非回归检查，确认底座改造没有影响既有业务模块。

建议检查：

- 品牌增长
- 小红书
- 抖音
- 公众号
- 设计工作台
- 个人中心
- 后台登录与管理入口

### 最低检查方式

每个模块至少确认：

- 页面能打开
- 关键列表能加载
- 不出现新增的接口 500 / 页面崩溃

### 建议重点关注

- 后台左侧菜单与子菜单是否还能正常进入
- 技能中心相关页面是否还能正常读取旧数据
- 数据库不可用时 mock fallback 是否仍能展示基础演示数据

## 6. 验收分级

建议按 3 级问题判断是否允许第一阶段收尾。

### P0

示例：

- 无法启动
- 能力包详情无法打开
- 模块注册中心无法保存
- 保存后数据全部丢失

处理原则：

- 有任一 `P0`，不得收尾

### P1

示例：

- 某个 first pass 区块功能不稳定
- 刷新后个别摘要不同步
- 某个关系页可读但不可写

处理原则：

- 原则上收尾前应修复
- 如明确延期，必须在阶段文档中写清楚

### P2

示例：

- 文案不一致
- 样式细节不统一
- 某些页签仍为预留占位

处理原则：

- 可转入第二阶段

## 7. 第一阶段通过标准

满足以下条件，可判定第一阶段核心收尾通过：

- 模块注册中心可正常 CRUD
- 能力包主对象、模块关系、技能关系可正常读写
- 统一技能中心 `basic / prompts / providers / references / scripts / versions` 可正常操作
- 知识库与知识绑定底座可正常使用
- 前后端 TypeScript 校验通过
- 无新增 `P0`
- 既有主要业务模块无明显回归

---

## 8. 第二阶段开始前的测试建议

第二阶段启动前，不建议直接放弃第一阶段测试结果。

建议做法：

- 先把本文档作为第一阶段验收基线固定下来
- 第二阶段每新增一块能力时，都要至少回归本文档中的核心检查项

这样做的价值是：

- 保证第二阶段扩展不会把第一阶段底座打坏
- 保证阶段推进是“向上叠加”，而不是“边做边回退”

---

## 9. 最终结论

第一阶段的测试重点不是“所有未来能力都做完”，而是确认：

- 底座已经稳定
- 核心后台入口已经可用
- 数据真源开始统一
- 老模块没有被破坏

做到这些，就可以把第一阶段正式收口，并进入第二阶段。
