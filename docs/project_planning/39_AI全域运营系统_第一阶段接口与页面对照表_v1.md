# AI全域运营系统 第一阶段接口与页面对照表 v1

## 1. 文档目的

本文档用于把第一阶段已经规划出来的页面和接口进一步对齐成一张对照表，用于：

- 指导前后端联调顺序
- 指导第一阶段开发排期
- 判断哪些页面已经有接口草案，哪些还没有

## 2. 使用说明

阅读方式建议为：

- 先看页面
- 再看对应接口
- 再看依赖的主表
- 最后看优先级

## 4. 当前已经形成草案的接口

目前已经明确草案的接口包括：

- `GET /api/admin/skill-packages`
- `GET /api/admin/skill-packages/:packageId`
- `GET /api/admin/skill-packages/:packageId/versions`
- `POST /api/admin/skill-packages/:packageId/versions`
- `POST /api/admin/skill-packages/:packageId/activate-version`
- `GET /api/admin/skill-packages/:packageId/version-diff`

## 5. 当前已经形成草案的页面字段

目前已经明确字段清单的页面包括：

- 统一技能中心详情页
- 模块注册中心列表页
- 模块注册中心详情表单页

## 6. 仍待补齐的接口空白

第一阶段最值得继续补的接口空白有：

- 模块注册中心列表接口正式草案
- 模块注册中心详情接口草案
- 模块注册中心保存接口草案
- `skill_package_modules` 关系读写接口草案

## 7. 推荐联调顺序

### 第一步

- 统一技能中心列表页
- 统一技能中心详情页

### 第二步

- Prompt 页签
- Provider 页签
- 版本页签

### 第三步

- 模块注册中心列表页
- 模块注册中心详情 / 编辑页
- 模块默认能力包绑定

### 第四步

- references
- scripts
- 工作流步骤绑定

## 8. 最小闭环建议

如果第一阶段只先做一个最小闭环，建议是：

1. 模块注册中心能录入模块  
2. 统一技能中心能查看能力包  
3. 能力包能挂到模块上  
4. Prompt 和 Provider 能被查看  
5. 版本能创建和激活  

做到这 5 点，第一阶段核心闭环就已经建立起来。

## 9. 最终结论

这张接口与页面对照表的价值，在于把“哪些页面已经能做、哪些接口已经有、哪些地方还缺口”一眼看清楚。

第一阶段后续开发时，建议始终以这张表作为联调和排期的辅助底稿。
