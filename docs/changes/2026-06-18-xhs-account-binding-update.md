# 2026-06-18 小红书账号绑定与覆盖更新

## 背景

小红书收集数据页原本只有品牌账号改成了账号绑定式录入，竞品账号仍然保留旧的文本框批量提交形态。
同时，用户要求再次点击同一账号的提交按钮时，页面下面的结果列表应该表现为“更新”，也就是删除旧的重复记录，只保留最新结果。

## 本次调整

### 1. 竞品账号改成账号绑定逻辑

- 竞品账号信息现在和品牌账号信息一样，改成右上角“添加账号”入口。
- 支持逐条保存多个竞品账号。
- 每个竞品账号单独一行展示。
- 每行提供“提交”和“删除”按钮。
- 竞品账号不再区分品牌号、员工号、达人号，只维护账号入口本身。

### 2. 行级提交改成覆盖更新

- 品牌账号再次提交时，会识别同一账号之前的旧记录并清理，只保留最新一条。
- 竞品账号再次提交时，也会走相同的覆盖更新逻辑。
- 账号身份识别会综合使用 `sourceAccountId`、`sourceAccountLink`、`externalUserId` 等信息，避免同一账号因为入口形式不同而重复入库。

### 3. 已采集结果回填到绑定列表

- 页面加载后，会把已有的品牌账号结果回填到品牌账号绑定列表。
- 页面加载后，也会把已有的竞品账号结果回填到竞品账号绑定列表。
- 这样用户再次进入页面时，可以直接对已有账号继续点击提交完成覆盖更新。

## 影响文件

- `apps/web/src/app/(dashboard)/brand-growth/collection-workspace.tsx`
- `apps/web/src/app/(dashboard)/brand-growth/workspace.tsx`
- `apps/server/src/modules/collectors/collectors.service.ts`

## 结果

- 品牌账号：支持多账号绑定、账号类型区分、行级提交、删除、覆盖更新。
- 竞品账号：支持多账号绑定、行级提交、删除、覆盖更新。
- 同一账号再次提交时，下面结果列表会删除旧的重复记录，只保留最新结果。
