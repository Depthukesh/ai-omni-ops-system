# 2026-05-27 抖音热点找选题新增选题库

## 背景

在 `抖音工作台` 中新增独立的“选题库”页面，用于承接：

- 从热点找选题结果中勾选加入的选题
- 品牌管理员手动补充的选题

用户要求：

- 排版参考抖音采集页中的低粉爆款榜表格样式
- 选题库展示字段为：
  - 选题内容
  - 选题说明
  - 入选时间
- 页面一行展示两条选题记录
- 超过 20 行后进行分页
- 提供“添加选题”按钮，支持手动新增
- 后续开发中，这类数据必须按品牌独立存储
- 同城热点榜列表也要统一按 20 行分页

## 本次实现

### 前端

- 抖音工作台新增独立 section：`选题库`
- `热点找选题` 页面保留：
  - `加入选题库`
  - `查看选题库`
- `选题库` 独立页提供：
  - `刷新数据`
  - `添加选题`
- 选题库页面以双记录表格展示：
  - 一行两条选题记录
  - 每条记录展示 3 个字段：选题内容、选题说明、入选时间
- 超过 20 行时分页，每页固定 20 行，不再允许调整页大小
- 手动添加时填写：
  - 选题内容
  - 选题说明
- 从热点结果加入时，按当前勾选项批量入库
- `同城热点榜` 列表改为固定 20 行分页

### 后端

- 在 `reports` 模块新增品牌选题库保存接口
- 选题库作为 `BusinessAsset` 存储
- 存储形式：
  - `category = GENERATED_CONTENT`
  - `metadataJson.kind = DOUYIN_TOPIC_LIBRARY`
- 每个品牌独立保存一份抖音选题库，按 `brandId` 隔离
- 同一品牌下按选题内容做去重，避免重复入库

## 存储规则

### 当前选题库数据

选题库不是全局共享，不走文件，不走平台基线，而是：

- 归属到具体 `brandId`
- 与当前品牌工作台数据一起存于品牌业务资产层

### 为什么这么做

- 与“每个品牌独立管理自己的选题沉淀”一致
- 后续如果增加：
  - 选题筛选
  - 选题状态
  - 选题来源
  - 选题引用到脚本/笔记/任务
  都可以继续沿用这套品牌级资产存储结构

## 分页规则

- 当前本次涉及的列表统一采用固定分页：
  - 每页 20 行
  - 不提供 10/20 切换
- 选题库因为一行展示两条记录，因此单页最多展示 40 条选题
- 同城热点榜按单条记录一行，因此单页最多展示 20 条热点

## 影响评估

### 正向影响

- 热点找选题从一次性结果页，升级为“生成页 + 独立选题资产页”
- 选题沉淀开始具备品牌隔离能力
- 选题库已具备独立页面能力，后续可继续扩展字段与操作
- 同城热点榜开始具备固定页长分页，长列表可读性更稳定

### 控制范围

- 仅影响 `抖音 -> 热点找选题` 页面与 `reports` 模块
- 不改抖音营销策划方案链路
- 不改每日热点链路
- 不改素材库既有数据结构

## 后续建议

- 若后面将“选题库”升级为独立板块，可继续补充：
  - 选题状态
  - 负责人
  - 标签
  - 来源任务
  - 被引用次数
  - 最近使用时间
- 这些字段仍建议继续沿用品牌级独立存储原则
