# 2026-08-16 个人中心技能中心分组导航与固定内容壳收口

## 1. 背景

个人中心 `技能中心` 页面此前把技能列表直接按卡片平铺在左侧，右侧详情又会随着提示词编辑区不断向下增长，带来两个明显问题：

1. 左侧无法按板块分类，查找技能时只能在一长列里滚动
2. 右侧详情区会把整页不断撑长，浏览体验发散，不像一个受控工作台

用户明确要求：

- 左侧菜单要按各个板块分类
- 分类菜单支持展开和收缩
- 页面主体要有一个固定容器框，让内容在框内滚动，而不是整页一直往下伸

## 2. 本次改动

### 2.1 技能列表改为按分类分组的手风琴导航

文件：

- `apps/web/src/app/(dashboard)/personal-center/skills/page.tsx`

调整后：

- 左侧技能列表按 `baseSkill.category` 分组
- 每个分组支持展开 / 收缩
- 分组内展示技能名称、自定义状态和提示词数量
- 当前选中的技能会自动保持其所属分组展开

### 2.2 技能详情区改为固定壳层内滚动

文件：

- `apps/web/src/app/(dashboard)/personal-center/skills/page.tsx`
- `apps/web/src/styles/globals.css`

调整后：

- 技能中心主区域改成固定高度双栏壳层
- 左侧分组菜单在自己的框内滚动
- 右侧技能详情与提示词编辑区也限制在固定内容框内滚动
- 在窄屏下自动退回单栏自然布局，避免小屏被强行锁死高度

## 3. 影响面检查

### 3.1 影响范围

- 仅影响 `个人中心 -> 技能中心` 页面布局与交互

### 3.2 未改动范围

- 没有改技能数据接口
- 没有改品牌技能覆盖保存逻辑
- 没有改后台技能中心
- 没有改 OpenClaw / MCP / Skill 配置链

## 4. 验证

已执行：

- `npm run build:web`

建议联调检查：

1. 搜索与状态筛选后，左侧分组是否仍能正确展示
2. 展开 / 收起后，切换技能是否会自动保持当前分组可见
3. 右侧提示词较多时，是否只在内容框内滚动，不再把整页拉长

## 5. 结论

这次改动是一次页面结构收口，不是重做技能中心。

目标是让技能中心更像一个“账号配置工作台”：

- 左侧负责分组定位
- 右侧负责查看和编辑
- 长内容被限制在受控壳层里，而不是继续向整页外扩
