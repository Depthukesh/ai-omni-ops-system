# 2026-08-27 抖音采集视频预览与文案重试体验优化

## 背景

品牌增长策略里的抖音采集表格存在两类体验问题：

1. 用户能看到“打开预览”，但视频在站内弹窗里实际打不开，用户也不知道缓存后的视频到底落在了哪里。
2. 当上游 GLM API Key 余额不足时，视频文案提取容易长期停在灰色“提取中...”，即使后续充值，用户也缺少清晰的失败提示和重新提取入口。

## 本次改动

### 1. 抖音视频预览链路

- 抖音采集记录新增回传：
  - `videoSourceUrl`
  - `videoStoragePath`
- 抖音采集表格把“视频下载地址”改为“视频预览/存储”，直接显示：
  - 当前是否已有站内受控预览
  - 视频实际存储位置（本地 fallback 路径或 OSS key）
  - 缓存失败/过期时可回到原作品地址
- 品牌增长工作台弹窗不再把受保护 API URL 直接塞给 `<video>`
  - 当前先通过带鉴权的 blob 请求读取文件
  - 再用对象 URL 做站内视频预览
  - 避免浏览器媒体标签因未附带业务鉴权头而打不开

### 2. 视频文案提取状态收口

- 抖音采集记录新增 `transcriptStatusUpdatedAt`
- 手动提取与自动提取都会在状态变更时更新时间戳
- 后端增加超时回收：
  - 若文案提取长时间停在 `PENDING`
  - 会自动收口为可重试的失败态
  - 避免页面长期灰色“提取中...”
- 修复了文案提取源地址解析里的不可达 fallback
  - 当站内缓存视频不可用时
  - 会继续回退到原作品地址，而不是提前返回空值

### 3. 上游错误提示与重试体验

- GLM 上游错误当前会归一化为更可读的提示：
  - 余额不足 / 欠费 / quota / credit / balance
  - API Key 无效或未授权
  - 频率限制
- 前端表格补充：
  - `待充值后重试`
  - `重新提取`
  - `可重试`
  等状态提示
- 用户在充值后，可直接再次触发视频文案提取

### 4. OpenClaw / MCP / Skill 同步

- OpenClaw 新增 `extract_douyin_work_transcript`
- Skill/MCP 文档同步补充：
  - 抖音采集视频存储位置回显
  - 站内受控预览说明
  - 额度恢复后的重新提取路径

## 影响范围检查

- 影响板块：
  - `品牌增长 -> 收集数据 -> 抖音采集`
  - OpenClaw / MCP / Skill 的抖音采集路由说明
- 未改动：
  - 抖音采集 API 协议的核心输入结构
  - 数据库 schema
  - 其它采集平台的小红书/公众号链路
- 额外保护：
  - 受保护视频统一转 blob 预览，避免继续把鉴权 URL 直接交给浏览器媒体标签
  - 对卡住的 `PENDING` 状态做自动回收，降低旧任务长期卡死的副作用
