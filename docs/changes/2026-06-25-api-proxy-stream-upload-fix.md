# 2026-06-25 API 代理大文件流式转发修复

## 背景

- 用户在线上创建数字人时仍收到 `502 Bad Gateway`，同时任务中心没有任何记录。
- 结合当前前端架构，浏览器请求会先进入 `apps/web` 的 `/api/[...path]` 代理，再由 `3001` 转发到 `3011`。
- 代理实现原本会先执行 `await request.arrayBuffer()`，把整个上传请求完整读入 Next 进程内存后再转发。
- 对数字人训练视频这类大体积请求，这种做法容易在代理层出现断连、内存放大或网关 502，导致后端根本收不到请求，也就不会落任务记录。

## 变更

- 调整 `apps/web/src/app/api/[...path]/route.ts`
- 对带请求体的 API 调用改为直接复用 `request.body` 进行流式转发，不再整包缓冲到内存
- 为 Node 运行时补充 `duplex: "half"`，保证流式请求可被上游 `fetch` 正常接受

## 预期效果

- 数字人训练视频等大请求不再优先卡死在 `3001` 代理层
- 请求能更稳定地打到 `3011` 后端
- 若后端继续失败，也能返回更真实的业务错误，或在任务中心留下可见记录
