# 2026-08-16 local-single-user 升级心跳补强与默认品牌背景资料保护

## 1. 背景

用户在另一台笔记本上连续遇到两个问题：

1. 通过个人中心 `版本与升级` 做后台升级，长时间显示运行中，但最终版本没有切上去
2. 改用安装包安装后，原账号下的“品牌背景资料”被重置回默认内容，而产品资料库、品牌运营情况等其它资料仍在

这两个问题都发生在 `local-single-user` 安装态，且都直接影响用户对“可升级、可持久化”的基本信任。

## 2. 根因

### 2.1 慢机器升级时，`APPLYING` 心跳不够细

升级器虽然会在几个关键节点写状态，但最重的“执行安装脚本替换安装目录”阶段之前只写了一次：

- `正在替换本地安装目录`

之后会同步等待安装脚本执行完成。

如果机器较慢、磁盘压力较高或被杀软/Defender 扫描拖慢：

- 这一阶段可能持续很久
- `system-update-status.json` 的 `checkedAt` 长时间不刷新
- 后端会把它误判成“长时间没有新进展”

结果就是：

- 页面上看像“后台升级一直没成功”
- 用户会倾向重复点击
- `apply-runs/` 下不断生成新目录

### 2.2 启动期默认品牌初始化覆盖了已有品牌背景字段

`LocalSingleUserBootstrapService` 之前在每次启动时都会对默认品牌 `local_default_brand` 执行 `upsert`，并在 `update` 分支直接写回：

- `brandName`
- `industry`
- `storeCount`
- `foundedYear`
- `brandDescription`
- `enterpriseIntro`

如果用户当前实际就在默认品牌下工作，那么：

- 产品资料
- 品牌运营情况
- 第三方数据

这些关联数据仍然保留，因为它们是别的表记录；

但品牌背景资料本体就在 `Brand` 主记录上，于是会被启动期默认值直接覆盖。

这正好解释了“安装完后只有品牌背景资料变回去了，其它资料还在”的现场表现。

## 3. 本次改动

### 3.1 升级器安装阶段补周期性心跳

文件：

- `scripts/local-single-user-updater.ps1`
- `apps/server/src/modules/system-update/system-update.service.ts`

调整内容：

- 为安装脚本执行新增 `Invoke-PowerShellFileWithHeartbeat`
- 后台执行安装脚本时，每 5 秒刷新一次 `APPLYING` 状态
- 同步把安装脚本 stdout / stderr 重定向到当前 `apply-run` 目录，失败时会带上末尾日志摘要
- 等待新版本 API / Web 验活时也会周期性刷新状态文案
- `APPLYING` 的“长时间无进展”阈值从 10 分钟放宽到 30 分钟，降低慢机器误判失败的概率

这次没有改动升级协议、SHA256 校验或回滚机制，只是把“长步骤无心跳”这个口子补上。

### 3.2 默认品牌改为只补缺，不覆盖已有品牌背景

文件：

- `apps/server/src/local-single-user/local-single-user-bootstrap.service.ts`

调整内容：

- 默认品牌 `local_default_brand` 改为：
  - 不存在时创建
  - 已存在时不再覆盖已有业务字段

也就是说，后续：

- 首次安装仍会自动准备默认品牌
- 但升级、安装、重启不会再把用户已经保存的品牌背景资料重置回默认值

## 4. 影响面检查

### 4.1 受影响范围

- `local-single-user` 后台升级链
- `local-single-user` 启动期默认品牌初始化

### 4.2 为避免副作用做的保护

- 没有改数据库结构
- 没有改品牌资料库前端页面
- 没有改产品资料、运营情况、第三方数据等表的读写逻辑
- 没有取消安装态默认品牌与默认成员关系
- 保留默认成员关系兜底，只收紧“不要覆盖已有品牌背景资料”

## 5. 验证

已执行：

- `npm run build:server`
- `npm run build:web`

需用户现场继续验证：

1. 在较慢的笔记本上再次通过“版本与升级”执行后台升级
2. 观察升级状态是否持续刷新，不再很快回落到可重复点击
3. 用安装包安装或升级后，确认品牌背景资料不再被重置

## 6. 结论

这次不是简单的“机器配置低”。

更准确地说：

- 慢机器只是把升级链里“长步骤无心跳”的问题放大了
- 品牌背景资料被重置则是启动期默认品牌 `upsert` 的真实覆盖 bug

两处都已在代码层收口。
