# 2026-08-30 版本页 Git 更新分支指引修正

## 背景

个人中心 `版本与升级` 页面在标准运行态下，会根据当前仓库状态生成 Docker 更新步骤。此前这里默认按“本地当前分支名”直接拼接：

- `git pull origin <branch>`

当本地工作区仍停留在旧分支，例如 `main`，但远端默认分支已经切换后，页面就会给出一个看起来正常、实际执行会报 `couldn't find remote ref` 的错误指令。

## 本次修正

- 标准运行态更新命令不再盲目沿用本地当前分支
- 后端优先通过 `git ls-remote --symref origin HEAD` 解析远端有效默认分支
- 页面提示统一改成“执行页面生成的 Git 更新命令”，避免用户自行脑补成固定的 `origin main`
- 更新日志链接也同步改为跟随远端有效分支生成

## 影响面

- 仅影响个人中心 `版本与升级` 的标准运行态更新引导
- 不影响安装态一键升级链
- 不影响业务数据、数据库结构和 OpenClaw 链路

## 验证重点

- 标准运行态版本页是否先显示 `git fetch --all --prune`
- 后续 `git pull origin ...` 是否使用远端有效默认分支，而不是盲目使用本地旧分支
- 更新提醒文案是否不再写成容易误解为固定 `main` 的口径
