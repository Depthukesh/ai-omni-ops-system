# 2026-05-26 视频故事板重生成图片对齐与提速

## 背景

- 视频笔记第 2 阶段完成后，用户可以直接修改故事板提示词并重新生成故事板图片。
- 实测中，“修改重新生成”存在两个明显问题：
  - 生成出的故事板图片与用户当前编辑后的故事板提示词偏差很大，甚至接近无关。
  - 单次重生成耗时过长，可能接近 20 分钟。

## 根因

### 1. 视频故事板图片误用了图文海报式提示词包装

- 重新生成故事板图片时，前端会把当前编辑框中的 `storyboardPrompt` 正常提交给后端。
- 后端也会把这份新提示词写回 `metadata.storyboardPrompt`。
- 但在真正调用文生图 Provider 前，底层统一复用了图文笔记封面/配图的提示词包装函数。
- 该函数会追加不适用于视频故事板的强约束，例如：
  - 必须输出带清晰中文排版的社媒成品图
  - 必须按 1242x1660 的小红书图文比例构图
  - 必须把标题和标签直接排进画面主体版式
- 这些要求会把“视频分镜画面描述”带偏成“图文海报/封面图”，导致最终结果与故事板提示词失真。

### 2. 重生成链路的图片兜底过宽

- 旧逻辑会在 `providers -> baseUrls -> apiKeys -> models -> promptsToTry` 多层循环中串行尝试。
- 同时还会为同一提示词再构造一个 fallback prompt。
- 单次图片尝试默认超时时间较长，因此当多个 Provider / 模型依次失败时，总耗时会被明显拉长。

## 本次修复

### 1. 为视频故事板图片新增独立 prompt 模式

- 更新文件：
  - `apps/server/src/modules/works/works.service.ts`
- 新增 `ImagePromptMode`，区分：
  - `social_graphic`
  - `video_storyboard`
- 当生成“视频故事板图片”时，改走 `video_storyboard` 模式：
  - 明确要求输出短视频故事板单帧画面
  - 强调角色、场景、动作、镜头、情绪一致性
  - 明确禁止默认生成中文排版标题、角标、标签、海报式大字和 APP 界面元素
- 这样故事板图片会更接近视频分镜，而不是社媒海报。

### 2. 收紧视频故事板图片的重生成尝试范围

- 对首次生成和“修改重新生成”两条故事板图片链路同时收口：
  - 不再为故事板图片额外追加 fallback prompt
  - 最多只尝试前 2 个图片 Provider
  - 每个 Provider 最多只尝试 1 个模型
  - 单次图片尝试超时收紧到 120 秒
- 这样可以显著减少串行兜底轮数，避免故事板重生成被拖到十几分钟。

## 影响范围

- 视频笔记第 2 阶段首次生成故事板图片
- 视频笔记“修改重新生成”故事板图片
- `apps/server/src/modules/works/works.service.ts`

## 验证

- `GetDiagnostics`
  - `apps/server/src/modules/works/works.service.ts`
- `npm --workspace apps/server run build`

## 说明

- 本次修复不改图文笔记封面/配图生成链路，它们仍继续使用原来的 `social_graphic` 模式。
- 本次修复只把“视频故事板图片”从图文海报式 prompt 包装中剥离，避免影响原有图文能力。
