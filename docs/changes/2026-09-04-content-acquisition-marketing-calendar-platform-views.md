# 2026-09-04 内容获客营销日历平台视图接入

## 背景

内容获客里的某书、某音/某号、公众号已经分别有 OpenClaw `营销策划方案` 入口，但还缺少独立 `营销日历` 板块。用户要求这三个入口都复用 `品牌增长策略 -> 品牌增长报告 -> 营销日历` 的同一套呈现形式和编辑能力，只是在进入不同板块时按平台过滤字段：

- 某书：只展示小红书相关选题
- 某音/某号：只展示抖音相关选题
- 公众号：只展示公众号相关选题

同时要求这份营销日历既能由 OpenClaw 创建、编辑，也能由用户创建、编辑。

## 本次变更

### 1. 内容获客三端新增独立 `营销日历` 左侧入口

- 某书：位于 `营销策划方案` 下方
- 某音/某号：位于 `营销策划方案` 下方
- 公众号：位于 `营销策划方案` 下方、`配置初始化` 上方

三端都接到统一聚合壳层 `ContentAcquisitionWorkspace`。

### 2. 通用营销日历组件补齐平台视图过滤

- `apps/web/src/app/(dashboard)/xiaohongshu/calendar-workspace.tsx`
  - 新增 `platformView`
  - 月历卡片标题按平台选择对应主题
  - 详情弹窗按平台裁剪字段块：
    - 某书只显示品牌营销 + 小红书品牌号/员工号
    - 某音/某号只显示品牌营销 + 抖音品牌号/IP号/员工号
    - 公众号只显示品牌营销 + 公众号相关字段

### 3. 内容获客三端共用同一份营销日历真源

- 没有新增第二套营销日历数据库或接口
- 继续复用：
  - `getXiaohongshuMarketingCalendarWorkspace`
  - `generateXiaohongshuMarketingCalendar`
  - `upsertXiaohongshuMarketingCalendarItem`
- 用户和 OpenClaw 都继续写回品牌增长报告下的同一份营销日历记录

### 4. OpenClaw / MCP / Skill 说明同步

- 内容获客三端的 `营销日历` 入口继续复用品牌增长语义工具：
  - `get_brand_growth_marketing_calendar_workspace`
  - `generate_brand_growth_marketing_calendar`
  - `update_brand_growth_marketing_calendar`
- Skill 文档新增说明：
  - 当用户明确说“内容获客某书/某音/公众号的营销日历”时，仍读取同一份品牌增长营销日历真源
  - OpenClaw 填写时只补对应平台字段，不要误覆盖其它平台块

## 影响面说明

- 本次没有改营销日历后端协议、任务类型、Prompt、Provider 或数据库结构
- 本次没有新增第二套日历存储，避免内容获客和品牌增长之间出现双写分叉
- 某书与公众号原本已经在其它链路复用这份营销日历；本次只是把它们显式提升为独立入口并统一成月历视图

## 验证重点

- 某书 / 某音/某号 / 公众号左侧菜单下是否都能看到独立 `营销日历`
- 三端进入后是否仍是同一套月历视图与同一套详情编辑交互
- 某书是否只显示小红书字段
- 某音/某号是否只显示抖音字段
- 公众号是否只显示公众号字段
- 保存后是否仍能回写同一份品牌增长营销日历真源
