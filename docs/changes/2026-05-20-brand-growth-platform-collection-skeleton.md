# 2026-05-20 平台采集页三段骨架拆分

## 背景

- 原来的收集数据页将飞书配置、小红书同步入口、小红书结果展示混在同一个板块里。
- 新协作方案要求：
  - 将飞书配置从小红书结果区拆开，独立成单独板块；
  - 小红书板块只保留同步动作和结果展示；
  - 预先搭好抖音板块的页面骨架，等待 Tikhub 字段方案回填后再接真实数据。

## 本次调整

- 将原“小红书平台”采集页重组为 3 个连续板块：
  - `飞书配置`
  - `小红书`
  - `抖音`
- `飞书配置` 板块保留：
  - App ID / App Secret / Redirect URI / Scope
  - 飞书副本链接
  - 保存应用配置 / 连接飞书 / 保存绑定
- `小红书` 板块改为只保留：
  - 同步按钮
  - 四类结果切换与展示
- `抖音` 板块新增 4 个骨架卡位：
  - 品牌账号信息
  - 竞品账号信息
  - 品牌作品信息及数据
  - 对标作品信息及数据

## 风险边界

- 本次只调整前端页面组织和骨架展示。
- 不改 API 协议，不改数据库 schema，不接入抖音真实数据请求。
- 小红书现有同步与结果展示逻辑保持不变。

## 后续续接

- 等 Codex 在飞书协作文档里回传 Tikhub 字段甄别结果后：
  - 统一抽象抖音账号/作品展示模型；
  - 再接入抖音真实数据源；
  - 最后补充抖音卡片里的真实字段渲染与分页/操作能力。
