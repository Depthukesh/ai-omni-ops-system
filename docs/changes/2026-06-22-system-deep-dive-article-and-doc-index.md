# 2026-06-22 系统深度长文与文章资产索引补充

## 1. 变更背景

- 本轮需要产出一篇面向外部传播的深度长文，系统性讲清楚这套网站的技术架构、业务链路，以及 AI 参与复杂系统开发时如何通过文档和 AGENTS 规则避免失控。
- 长文要求同时覆盖技术维度和业务维度，且不是简单产品介绍，因此需要把仓库中的系统文档、工程规范、站点地图、数据库档案和 AGENTS 规则整理成可对外表达的内容资产。
- 除了正文，还同步生成了技术架构图和业务增长闭环图，并将整套文章资产落到仓库外层的 `文章/` 目录。

## 2. 变更目标

- 形成一篇不少于 1.8 万字的系统深度文章，作为对外讲解材料。
- 让仓库文档体系知道这次文章资产的存在，避免出现文章已交付但文档索引没有同步的情况。

  - AGENTS、系统文档、站点地图、工程规范如何构成防失控装置
  - 前后端、数据库、OSS、任务中心、部署链、OpenClaw / MCP 的真实结构

  - 使用真实文本而非 AI 生图文字
  - 适合缩放、截图和后续继续修改

### 3.2 文档索引

- 更新 `docs/README.md`
  - 在文档分层中补充 `../文章/` 的定位
  - 在“最近应优先关注的文档”中挂入本次变更记录

## 4. 修改意图

- 这次不是新增业务功能，而是把已有系统真相重新组织成一份可传播、可复用、可讲清楚的外部叙事资产。
- 单独保留在 `文章/` 目录，而不是混入 `docs/` 主体，是为了维持文档体系的边界：
  - `docs/` 继续承载开发真相、工程规则和变更记录
  - `文章/` 承载对外表达、深度解读和传播资产
- 同时在 `docs/README.md` 中建立索引，是为了保证这次资产不会脱离系统文档体系而孤立存在。

## 5. 影响范围

- 影响目录：
  - `文章/`
  - `docs/`
- 影响文档：
  - `docs/README.md`
  - `docs/changes/2026-06-22-system-deep-dive-article-and-doc-index.md`
- 不影响：
  - 前端路由
  - 后端接口
  - 数据库结构
  - 既有运行时配置

## 6. 验证方式

- 手工验证：
  - 检查长文文件已落到 `文章/` 目录
  - 检查 HTML 专题页已落到 `文章/` 目录
  - 检查两张配图已落到 `文章/` 目录
  - 检查技术架构 SVG 重绘图已落到 `文章/` 目录
  - 检查文章结构包含技术、业务、治理、边界与总结章节
  - 本地启动静态服务并实际打开 HTML 页面，确认首屏、导航、图片引用和长文内容可见
- 内容验证：
  - 以系统文档、AGENTS、宣传单页为事实来源完成交叉整理
  - 补齐尾章，确保正文结构完整，不是半成品
- 文档验证：
  - 检查 `docs/README.md` 已挂入 `文章/` 目录定位与本次变更记录入口

## 7. 风险与后续

- 旧版 `技术架构总览图.png` 仍保留作为概念图资产，但正式阅读和传播应优先使用 `技术架构总览图-重绘.svg`。
- 业务增长闭环图当前仍是生图版本，复杂文字信息如果后续也要做到完全可控，建议继续补一版 SVG 或程序化图表重绘。
- 长文已经能够完整讲清技术和业务主线，但如果后续系统结构继续大幅演化，仍需要周期性更新文章中的个别章节，避免外部叙事落后于真实系统。
