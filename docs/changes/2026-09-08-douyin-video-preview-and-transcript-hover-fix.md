# 2026-09-08 抖音采集视频预览与文案悬浮修复

## 背景

在 `品牌增长 -> 收集数据 -> 抖音` 的作品列表中，出现了三类体验问题：

1. 点击“提取文案”时，后端提示“视频地址无效，暂时无法提取文案”，但页面里的视频实际可以正常打开
2. “视频预览/存储”列把长视频地址或存储路径直接渲进表格，导致整行被明显撑高
3. “视频文案”列可见空间过小，用户难以快速查看完整文案

## 真实原因

### 1. 文案提取优先用了站内受控预览地址

- 抖音视频缓存完成后，页面会优先使用站内受控预览地址
- 该地址在前端页面中可以通过受控下载接口打开
- 但 `GLM` 视频转写接口要求传入可识别的 `http/https` 外部视频地址
- 之前文案提取链路优先取了站内预览地址，导致在某些机器上被判断成“视频地址无效”

### 2. 预览列把真实路径直接展示到表格文本里

- 当前列里除了“打开预览”外，还直接输出了 `videoStoragePath`
- 本地 Docker 环境下这会是较长的宿主机路径
- 因而把表格行高整体拉大

### 3. 视频文案只有单行截断，没有悬浮查看

- 当前视频文案只支持点击复制
- 单元格本身只保留一行视觉空间
- 长文案需要用户反复点击或依赖浏览器默认提示，查看效率较差

## 本次修复

1. 把抖音文案提取的优先地址调整为：
   - `videoSourceUrl`
   - `metadata.videoUrl`
   - 最后才回退到站内受控预览地址

2. 收紧“视频预览/存储”列展示：
   - 保留“打开视频/打开预览”
   - 不再把长存储路径直接渲染进单元格
   - 仅显示简短状态文案，如“站内存储已就绪”
   - 完整路径仍保留在鼠标悬浮提示里

3. 给“视频文案”增加鼠标跟随悬浮预览：
   - 鼠标进入视频文案单元格时，右侧附近显示完整浮层
   - 鼠标移动时浮层跟随
   - 鼠标离开或失焦后自动消失
   - 原有“点击复制文案”行为保留

## 影响范围

- 仅影响 `品牌增长 -> 收集数据 -> 抖音` 列表中的视频预览与文案提取交互
- 不改抖音采集数据结构
- 不改 OpenClaw 页面结构
- 不改素材存储路径真实落点

## 验证

1. `pnpm --filter server build`
2. `pnpm --filter web build`
3. 手工检查：
   - 视频预览列不再出现长路径撑高整行
   - 视频文案鼠标悬浮时出现完整浮层
   - 提取文案不再优先使用站内相对预览地址
