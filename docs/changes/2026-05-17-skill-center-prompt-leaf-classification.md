# 2026-05-17 技能中心提示词叶子项分类收口

## 背景

前一轮虽然已经把视频笔记相关提示词注册成 6 条独立 prompt，但前端个人技能中心和后台技能中心的展示仍残留“一个总技能 + 下方切换 prompt”的旧视角，界面上仍容易看到总技能名称 `小红书视频笔记 / short-video-api-studio`，不够直观，也不符合“所有提示词都要清晰显示并可修改”的要求。

## 本次调整

### 1. 抽离前后台共用技能中心分类树

- 新增前端共用配置 `apps/web/src/app/(dashboard)/skill-center-config.ts`
- 把技能中心目录树统一抽成：
  - 一级分类：品牌增长策略 / 小红书 / 抖音
  - 二级分类：业务模块
  - 三级叶子：可直接编辑的单条提示词
- 视频笔记明确拆成两组：
  - `视频笔记-剧本策划`
  - `视频笔记-视频生成`

### 2. 后台技能中心改成“当前提示词”视角

- 后台 `/admin` 技能中心继续保留左侧三层树
- 右侧详情卡不再把视频叶子项显示成总技能名
- 详情卡现明确区分：
  - 当前提示词
  - 所属执行技能
  - 提示词场景
  - 提示词内容
- 视频笔记 6 条提示词都按独立叶子项逐条进入、逐条保存

### 3. 前端个人技能中心改成“按提示词叶子项编辑”

- 个人中心 `/personal-center/skills` 左侧从“技能列表”改成“分类分组 + 提示词叶子项”
- 每条提示词都能独立看到：
  - 所属一级分类
  - 所属二级分类
  - 执行技能
  - 当前模型
  - 是否已自定义
- 右侧编辑区改为单条提示词详情，支持直接修改：
  - 模型
  - 温度
  - Max Tokens
  - 提示词内容
- 保存时仍复用原有用户覆盖层，不改变后端真实运行逻辑

## 结果

- 视频笔记相关 6 条提示词现在在前后台技能中心都能被清晰看到
- 分类口径前后台统一，不再出现“目录拆了但详情仍显示总技能”的混乱状态
- 后端继续复用同一 `skillSlug = short-video-api-studio` 运行，不影响现有调用链

## 验证

- `GetDiagnostics`
  - `apps/web/src/app/(dashboard)/admin/page.tsx`
  - `apps/web/src/app/(dashboard)/personal-center/skills/page.tsx`
  - `apps/web/src/app/(dashboard)/skill-center-config.ts`
- `npm --workspace apps/web run build`

## 后续关注

- 当前已把技能中心展示口径收口到“提示词叶子项”；若后续还要把更多业务链路拆成多 prompt 场景，优先继续往共用分类树里补，不要再在两个页面各自维护一套目录结构
