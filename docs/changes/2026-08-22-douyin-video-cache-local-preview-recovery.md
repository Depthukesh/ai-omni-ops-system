# 2026-08-22 抖音采集视频本地预览缓存恢复

## 背景

- 品牌增长策略 `收集数据 -> 抖音` 页面在 Docker 标准运行态、无 OSS 的本地受控存储模式下，视频预览需要先把第三方视频地址缓存到站内受控副本。
- 现场表现为：
  - 前端长期显示“缓存中”
  - 预览入口一直出不来

## 根因

本次确认有两层问题叠加：

1. 旧的抖音视频缓存任务在 `production` 环境默认不会在服务启动时恢复，导致历史 `PENDING` 任务会长期挂起。
2. 服务端拉取抖音视频源地址时没有带浏览器式请求头，部分源站直接返回 `403`，导致缓存任务失败。

## 本次改动

更新文件：

- `apps/server/src/modules/collectors/collectors.service.ts`

具体调整：

1. 本地受控存储模式下，服务启动时默认恢复抖音视频缓存任务。
2. `getDouyinWorkspace()` 读取到待缓存记录时，会自动补挂缓存任务，不再只依赖启动恢复。
3. 给抖音视频缓存队列增加进程内去重，避免同一条视频被重复排队。
4. 下载抖音视频时补充浏览器式请求头：
   - `User-Agent`
   - `Referer`
   - `Origin`
   - `Accept`
5. 错误文案从“缓存到 OSS 失败”改为“缓存到受控存储失败”，与当前本地模式一致。

## 验证

- `pnpm exec tsc --noEmit -p apps/server/tsconfig.json`
- 重建 `ai-omni-server`
- 运行态检查：
  - 历史 `PENDING` 记录恢复推进
  - `FAILED(403)` 记录重置后重新进入缓存流程
  - 当前统计已出现新的 `READY`，且 `FAILED` 为 `0`

## 影响范围

- 仅影响品牌增长策略里的抖音作品视频预览缓存与本地受控副本恢复。
- 不改数据库结构。
- 不改前端页面结构。
