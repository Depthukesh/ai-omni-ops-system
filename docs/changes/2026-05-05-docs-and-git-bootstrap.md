# 全站地图与 Git 记录体系启动

## 1. 变更背景

- 项目近期在真实联调中出现过代码损坏、启动异常、链路修复后难以系统回看等问题
- 当前仓库目录内尚未初始化 Git，无法用提交历史追踪问题演进
- `docs/` 目录已有零散复盘文档，但缺少“全站地图 + 每次修改留痕”的固定机制

## 2. 变更目标

- 建立结构化文档体系，让系统结构和主链路可被快速理解
- 建立变更记录模板，让后续每次代码修改都能同步记录逻辑和意图
- 为后续 Git 初始化与版本管理打基础

## 3. 修改内容

### 3.1 文档体系

- 新增 `docs/README.md` 作为文档总索引
- 新增 `docs/site-map.md` 作为全站地图
- 新增 `docs/changes/TEMPLATE.md` 作为变更记录模板
- 新增本文件，记录这次“文档 + Git”治理动作的启动原因与目标

### 3.2 当前系统地图整理

- 梳理了前端主入口：品牌增长、小红书、个人中心、后台管理
- 梳理了品牌增长工作台内部的三级结构：品牌资料库、收集数据、品牌增长报告
- 梳理了后端模块边界：`Auth / Brands / Collectors / Reports / Tasks / Media / Orders / Scheduler`
- 梳理了关键链路：品牌增长链路、小红书飞书同步链路、每日热点定时链路

## 4. 修改意图

- 把“代码改动”与“认知留痕”绑定，避免未来只能靠口头回忆系统结构
- 把“修过什么、为什么修”沉淀成固定模板，降低后续定位问题的成本
- 在 Git 还未初始化之前，先把文档规范定下来，避免后续提交虽然存在，但提交意图仍不清晰

## 5. 影响范围

- 影响 `docs/` 目录
- 不影响前后端运行逻辑
- 不影响数据库与接口数据

## 6. 验证方式

- 已确认 `docs/` 目录新增结构完整
- 新文档内容与当前前后端实际结构一致
- 当前项目目录内确认为未初始化 Git，后续可据此继续执行 Git 启动步骤

## 7. 风险与后续

- 当前只完成了文档体系落盘，还未执行 Git 初始化
- 下一步需要补充 `.gitignore`，避免把 `.runtime`、临时文件、日志直接纳入版本控制
- Git 初始化后，需要建立第一次基线提交
