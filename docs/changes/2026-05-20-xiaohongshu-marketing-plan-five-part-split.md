# 2026-05-20 小红书营销策划方案五段生成收敛

## 背景

- 小红书营销策划方案生成失败时，后端尝试轨迹里连续出现多个 Provider 的 `输出被截断`。
- 该错误来自模型返回 `finish_reason = "length"`，说明不是前端裁剪、也不是数据库字段长度，而是单次生成内容过重导致模型输出到达上限。

## 根因

- 原链路虽然已经做了分段生成，但仍然是 3 段大块输出：
  - 第 1 段：基础说明、账号与对标诊断、`## 一、`
  - 第 2 段：`## 二、`、`## 三、`
  - 第 3 段：`## 四、`、`## 五、`
- 后两段不仅要输出多个大章节，还要携带前文 Markdown 与完整输入数据一起进入上下文，导致单次请求的上下文和输出长度仍然过高。

## 本次修复

- 保持 API 协议、数据库结构和最终 Markdown 成品结构不变，只把生成颗粒度从 3 段细化为 5 段：
  - 第 1 段：基础说明、账号与对标基础诊断、`## 一、`
  - 第 2 段：`## 二、`
  - 第 3 段：`## 三、`
  - 第 4 段：`## 四、`
  - 第 5 段：`## 五、`
- 同步更新了以下配套逻辑：
  - 生成 phase 枚举与进度文案
  - 分段 system prompt / user prompt 约束
  - 分段结果 merge 逻辑
  - 最终 `modelName` 汇总

## 影响范围

- `apps/server/src/modules/reports/reports.service.ts`

## 验证

- `GetDiagnostics`
- `npm run build:server`

## 结果说明

- 这次修复解决的是“小红书营销策划方案单段输出压力过高”的问题。
- 如果后续仍出现截断，更可能是某个单章节提示词继续膨胀，或具体 Provider 的实际输出上限偏低，需要再针对单章节继续缩小生成颗粒度。
