# 2026-08-22 设计工作台图片卡片首屏内存保护

## 背景

- 用户反馈登录后打开 `更多功能 -> 设计` 时，桌面浏览器出现整机卡顿，甚至触发“虚拟内存爆满”。
- 前一轮已修复前端根布局中导致白屏的内联正则错误，但这并不能解释真实浏览器在图片设计场景下的内存飙升。
- 复核当前设计工作台实现后确认：
  - 列表虽然只按 21 个/页展示
  - 但图片模块会在首屏直接为每张卡片加载真实成品图
  - 若某品牌下存在较多高分辨率 PNG/JPEG 结果，浏览器会同时请求并解码多张大图，容易造成显著内存压力

## 本次改动

- `apps/web/src/app/(dashboard)/more-features/design/workspace-shell.tsx`
  - 设计结果列表中的图片卡片不再默认自动加载真实图片资源
  - 列表先回退为轻量占位卡片
  - 每张图片卡新增单独的“加载图”按钮，只有用户点击该卡时才按需加载缩略图
  - 已加载的图片卡会在当前会话内记住，不会因为列表刷新或局部重渲染又自动退回到占位态
  - 用户点击“查看”或点击卡片后，仍可在预览弹窗中加载真实资源

## 影响面

- 仅收紧设计工作台结果列表的首屏资源负载。
- 不改设计任务创建链路。
- 不改站内资源查看能力。
- 不改预览弹窗中的按需查看能力。

## 验证

- `pnpm exec tsc --noEmit -p apps/web/tsconfig.json`
- 浏览器联调重点：
  - 登录后打开 `http://localhost:13001/more-features/design`
  - 首屏不再为图片结果卡片批量加载真实图片
  - 单张图片卡点击“加载图”后可以在列表中查看缩略图
  - 点击单张作品时仍可在预览弹窗中查看真实成品图

## 说明

- 这次修复优先保证“打开页面先稳住”，避免首屏为了卡片预览一次性吃下大量图像解码内存。
- 当前折中方案是“单卡按需加载”，比“整页首屏全量缩略图”更稳。
- 如果后续还希望进一步提升列表观感，建议改为服务端生成固定尺寸缩略图，而不是直接使用原图做卡片封面。
