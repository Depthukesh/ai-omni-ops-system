# 2026-05-25 小红书二创飞书参考图出图失败修复

## 背景

- 小红书 `二创笔记` 页面在生成图片时持续报错，前台错误中可见：
  - `gpt-image-2 请求失败: 400`
  - `image upload failed, please check the image`
- 错误上下文里同时带有飞书附件下载地址：
  - `https://open.feishu.cn/open-apis/drive/v1/medias/.../download`

## 根因

- 二创笔记最终出图阶段会把素材库作品的 `imageList` 作为参考图输入传给图片模型。
- 当素材来自飞书时，`imageList` 中可能是需要鉴权的飞书受保护下载链接，而不是任何第三方图片模型都能直接读取的公网图片地址。
- 之前后端只是把这些飞书下载链接原样透传给 `gpt-image-2` 的 `image` 参数，导致上游在抓取参考图时失败，并返回 `image upload failed`。

## 修复

- 在二创图片生成链路中新增飞书参考图预处理：
  - 识别飞书受保护媒体下载链接
  - 先通过现有飞书鉴权下载能力把图片读回本地内存
  - 再转换为 `data URL`，作为上传型参考图传给图片模型
- 对非飞书受保护链接，仍保持原有 URL 透传方式。
- 如果飞书参考图读取失败，现在会在站内更早抛出更明确的错误，而不是等到上游模型返回模糊的 `image upload failed`。

## 影响范围

- `apps/server/src/modules/works/works.service.ts`
- 小红书 `二创笔记` 最终图片生成阶段

## 验证

- 代码走读：确认二创链路会先解析飞书受保护参考图，再进入 `generateImageAsset()`
- 代码走读：确认最终传给图片模型的参考图来源改为：
  - 飞书受保护图 => `data URL`
  - 其他普通图 => 原始 URL

## 后续建议

- 如果后续原创、视频或其他图像链路也开始直接消费飞书附件 URL，可复用同一套“先鉴权下载、再转 data URL”的处理方式，避免重复出现同类失败。
