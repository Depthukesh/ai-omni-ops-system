# 2026-06-25 数字人创建失败任务可见性修复

## 背景

- 用户反馈数字人训练视频上传后仍然报错，且任务中心为空，无法判断请求是否真正提交。
- 代码链路中，蝉镜凭证解析发生在定制数字人任务落库之前；如果凭证缺失或上游初始化失败，会直接报错，任务中心不会留下任何失败记录。

## 变更

- 调整 `apps/server/src/modules/works/works.service.ts` 中 `createDouyinDigitalHumanCustomPerson(...)` 的执行顺序。
- 先创建本地任务与本地待处理快照，再解析蝉镜凭证并继续上传/训练链路。
- 当蝉镜凭证缺失或后续上游步骤失败时，失败状态会正确回写到任务和本地数字人快照，避免出现“报错但任务中心为空”的黑盒体验。
- 结合蝉镜定制数字人文档，修正创建流程对异步任务的处理方式：
  - `create_customised_person` 只代表训练任务已提交，不代表训练已完成
  - 若详情接口返回仍在制作中，则本地任务保持 `RUNNING`，不再误标记为 `SUCCESS`
  - 只有蝉镜详情明确返回成功/失败状态时，本地任务才收口为成功/失败
