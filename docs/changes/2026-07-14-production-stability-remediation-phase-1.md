# 2026-07-14 生产稳定性治理第一阶段：文档落地与运行时调试收口

## 背景

最近连续出现以下问题：

1. 服务器重启或部署后，网站偶发不可达
2. GitHub Actions 部署链路偶发卡顿，容易误判为服务器挂死
3. 网站平时访问偏卡，尤其是大工作台和慢三方链路

经过对系统文档、部署链、运行架构和代码实现的交叉排查，确认问题不是单点故障，而是生产机职责过重、首屏请求过量、慢链路同步阻塞和生产调试残留共同造成的。

## 本次变更

1. 新增系统治理总文档
   - `docs/production-stability-and-performance-remediation-plan.md`
2. 将“生产稳定性与性能治理”纳入文档中心索引
3. 开始执行第一阶段整改：
   - 收口高频运行时 debug 上报
   - 生产环境默认关闭这些 debug 请求和 debug 文件写入
4. 补充开机自启动脚本与恢复手册入口
   - `scripts/ops/setup-pm2-aiops-startup.sh`
   - `docs/production-web-port-conflict-recovery.md`

## 为什么先做这一批

这一批改动不改变核心业务链路，但能立刻减少生产环境的额外负担，属于低风险、高收益的先手动作。

## 后续计划

1. 补 `systemd + pm2` 开机自启动
2. 将构建前移出生产机
3. 继续拆抖音和品牌增长工作台首屏加载
4. 将慢三方调用逐步迁为异步任务

## 验证要点

1. 文档入口可找到治理方案
2. 默认生产环境不再主动发送这批运行时 debug 事件
3. 构建与运行不受本次改动影响
