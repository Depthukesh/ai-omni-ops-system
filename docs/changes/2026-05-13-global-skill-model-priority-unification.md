# 2026-05-13 后台技能中心全技能模型优先级统一

## 背景

- 后台技能中心里用户已经可以为各个技能设置默认模型，但历史实现并不统一：
  - 部分链路只是把模型保存到了后台卡片或任务记录里，运行时第一跳并不一定先尝试这个模型。
  - 报错文案往往只显示“最后一次失败模型”，容易误以为那就是系统首先调用的模型。
- 该问题不只影响“生成品牌增长报告”，还同时影响：
  - 品牌增长可视化报告
  - 全年营销规划
  - 小红书营销策划方案
  - 原创笔记文案
  - 原创笔记配图提示词
  - 二创笔记文案
  - 二创笔记配图提示词
  - 视频笔记文案
  - 视频提示词

## 本次改动

- `ReportsService`
  - 将品牌增长报告、品牌增长可视化报告、全年营销规划、小红书营销策划方案的模型优先级统一为：
    - 先读后台技能中心当前 `SkillConfig.defaultModel`
    - 再合并 `PromptTemplate.modelName`
    - 再按兼容 provider 白名单重排运行顺序
  - 创建后台任务时，任务记录里的 `modelName` 改为写入本次真实首跑模型。
  - 失败提示统一输出：
    - 首选模型
    - 最后失败原因
    - 实际尝试顺序
- `WorksService`
  - 原创/二创/视频相关文本生成链路统一接入后台技能中心首选模型解析。
  - 原创笔记、二创笔记、视频笔记任务记录中的 `modelName` 改为真实首跑文本模型，不再固定写死 `deepseek-v4-pro`。
  - 原创文案、原创配图提示词、二创文案、二创配图提示词、视频文案、视频提示词的失败提示统一展示实际尝试顺序。

## 统一后的运行规则

- 后台技能中心里为某个技能设置的默认模型，会成为该技能运行时的真实第一优先。
- 若首选模型失败，系统才会继续按照兼容 provider / model 列表执行 fallback。
- 如果全部失败，错误提示会清楚显示系统真实尝试过的 provider/model/baseUrl 顺序。
