# 2026-06-07 Skill Package Semantics First Pass

## 背景

- 现有后台“技能中心”中，能力包与技能的职责边界仍有混用。
- 需要统一成新的产品语义：
  - 技能：主要功能实现单元
  - 能力包：系统里的最小功能实现单元，但本质上是多个技能按顺序编排后的组合容器

## 本次语义收口

### 1. 技能

- 技能被定义为具体功能执行单元。
- 一个技能内部重点围绕 3 个维度组织：
  - 输入项
  - 提示词及其他元素
  - 输出

### 2. 能力包

- 能力包不再承担技能级 Prompt、References、Scripts、Knowledge、Version 的管理职责。
- 能力包当前只保留：
  - 基础信息
  - 技能编排顺序
- 能力包页面不再突出版本管理，符合“能力包无需版本管理”的产品约束。

## 后台页面调整

### 能力包摘要

- 仅保留能力包本体字段与技能编排顺序。
- 列表表头改为偏编排视角：
  - 能力包
  - 模块
  - 技能编排数
  - 状态
  - 作用域
  - 更新时间

### 技能专区

- 保留左侧技能目录与右侧技能维护区。
- 右侧技能维护区按 3 个维度重组：
  - 输入项
  - 提示词及其他元素
  - 输出

## 当前实现边界

- 本次属于 first pass 语义重构，优先修正页面职责和操作入口。
- `References`、`Scripts`、知识库选择目前仍有继承型 / 预留型逻辑：
  - 页面上已经进入技能维度表达
  - 真正的技能级真源对象仍需后续继续落库

## 后续建议

- 为技能新增专用真源对象：
  - SkillInputSchema
  - SkillReferenceAsset
  - SkillScriptAsset
  - SkillOutputSchema
- 将“上游输出 -> 下游输入”的链路从展示逻辑升级为显式关系定义。
