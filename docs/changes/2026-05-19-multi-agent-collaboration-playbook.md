# 2026-05-19 多 Agent 协作开发手册

## 为什么补这份文档

- 当前仓库已经进入持续迭代状态，且经常需要在同一阶段内同时处理结构治理、功能补位、文档同步和 Git 收口。
- 如果后续接入第二个 AI Agent，没有统一的角色边界、交接格式和提交规则，很容易出现：
  - 两个 Agent 同时改同一文件
  - 方案口径不一致
  - 文档与代码脱节
  - 提交范围混入无关改动

## 本次新增内容

- 新增 `docs/ai-multi-agent-collaboration-playbook.md`
- 手册中明确了：
  - 主 Agent / 并行 Agent / 文档 Agent 的职责
  - 推荐协作模式
  - 任务拆分规范
  - 统一规范、进度、验证和文档的对齐方式
  - Git 协作标准
  - 冲突处理办法
  - 第二个 Agent 的接入提示词模板
  - 主 Agent 的调度清单

## 影响范围

- `docs/`
- `AGENTS.md` 作为协作入口说明文档

## 如何使用

1. 接入新的 AI Agent 前，先让其阅读 `AGENTS.md` 和这份协作手册。
2. 由主 Agent 先明确本轮总目标、子任务边界和验证方式。
3. 并行 Agent 仅处理指定边界，不直接提交和推送。
4. 主 Agent 统一完成验证、文档收口和 Git 提交。

## 后续建议

- 如果后续真的进入“双 Agent 常态化开发”，建议再把其中的最小必要规则同步提炼到 `AGENTS.md`。
- 如果将来接入 3 个及以上 Agent，建议追加“任务登记表”和“冲突仲裁日志”模板，降低并行写入时的协调成本。
