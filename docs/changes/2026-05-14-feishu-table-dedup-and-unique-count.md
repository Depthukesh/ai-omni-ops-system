# 2026-05-14 飞书表唯一分配与唯一计数修复

## 背景

- 品牌增长页执行“从飞书同步”时，页面提示会出现“命中 5 张数据表”，但用户实际飞书副本只有 4 张相关数据表。
- 根因是后端把表匹配结果按角色槽位计数，而不是按唯一表计数；当同一张飞书表被重复分配给多个角色时，`tableCount` 会被错误抬高。
- 同时，原有按表名匹配逻辑允许不同角色抢到同一张近名表，容易让 `品牌作品`、`对标作品`、`目标用户` 等角色出现重叠分配。

## 本次调整

- `apps/server/src/modules/collectors/collectors.service.ts`
  - `tableCount` 改为按唯一 `tableId` 去重后计数
  - 新增 `dedupeMatchedFeishuTables()`，同一张表只允许占用一个角色
  - 将按表名匹配改为“剩余表集合中的最优匹配”，避免多个角色重复命中同一张表
  - 新增表名评分逻辑，优先精确命中，其次前后缀命中，最后才是包含关系

## 影响

- 同步提示中的“命中 N 张数据表”将回到真实表数量，不再出现 4 张表被显示为 5 张的情况。
- 表名接近的飞书表不再被多个角色重复占用，有助于减少 `benchmarkNotes`、`targetUsers` 等角色被错误挤占的概率。

## 验证

- `GetDiagnostics` 检查 `collectors.service.ts` 无报错
- `npm run build:server`

## 后续说明

- 本次修复主要解决“重复分配”和“重复计数”。
- 若修复后“对标作品信息及数据”仍然为空，下一步需继续输出各角色实际命中的表名、表 ID 和每类 `syncedCount`，直接定位是命中错误还是行级写入为空。
