# 2026-05-09 小红书任务取消入口补齐

## 1. 变更背景

- 任务中心已经支持取消 `QUEUED` / `RUNNING` 任务
- 但用户在小红书原创、二创、视频工作区里看到任务运行时，仍然需要切到个人中心任务中心才能取消
- 这会打断当前创作流程，交互不够顺手

## 2. 变更目标

- 在原创笔记、二创笔记、视频笔记三个工作区的“创作状态”卡片里直接提供 `取消任务`
- 只针对当前工作区最近一条运行中任务提供入口，避免界面复杂化
- 让取消后的状态文案统一显示为 `已取消`

## 3. 修改内容

### 3.1 前端页面

- 更新 `apps/web/src/app/(dashboard)/xiaohongshu/page.tsx`
- 新增统一的 `handleCancelComposeTask()`
- 把最近一条原创 / 二创 / 视频任务的取消能力分别下发到三个工作区组件
- 取消成功后立即刷新工作区，并提示“任务已取消，当前工作区状态已刷新”

### 3.2 工作区组件

- 更新 `apps/web/src/app/(dashboard)/xiaohongshu/note-workspaces.tsx`
- 在原创、二创、视频的“创作状态”卡片中新增 `取消任务` 按钮
- 只在最近一条任务处于 `QUEUED` / `RUNNING` 时展示
- 取消后展示“最近一次任务已取消，本次创作流程已停止”提示

### 3.3 状态文案

- 更新 `apps/web/src/app/(dashboard)/xiaohongshu/task-status-text-helpers.ts`
- `CANCELLED` 状态统一显示为 `已取消`

## 4. 影响范围

- 页面：
  - `/xiaohongshu`
  - `/personal-center/tasks`
- 不新增后端接口，复用已有 `/api/tasks/:id/cancel`

## 5. 验证方式

- `npm run build:web` 通过
- 在原创 / 二创 / 视频工作区中，运行中任务可见 `取消任务`
- 点击后工作区状态刷新为 `已取消`

## 6. 风险与后续

- 当前仍是 `best-effort` 取消，不等于真正强杀外部执行器
- 当前只对“最近一条运行中任务”提供工作区内取消按钮；如果后续同类任务并行，需要再升级成任务列表级取消
