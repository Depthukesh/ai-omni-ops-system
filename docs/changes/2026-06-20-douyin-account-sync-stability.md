# 抖音账号同步稳定性修复

## 1. 变更背景

- 抖音采集页的品牌账号信息、竞品账号信息支持逐条提交账号，但当前逐条提交时存在已采集结果被后一次提交覆盖的问题。
- 品牌账号信息里手动维护的 `品牌号 / 员工号 / 达人号` 会在后续同步后被错误回写成 `品牌号`，导致下游“品牌作品信息及数据”的来源身份也跟着失真。
- 品牌作品信息及数据表虽然已有作者信息，但“作者昵称”列位置偏后，首屏不易看到，使用体验不符合运营同学的查看习惯。

## 2. 变更目标

- 保证抖音品牌账号、竞品账号逐条提交时，已采集账号不会被后续提交覆盖或挤掉。
- 保证品牌账号的账号类型在同步后仍然保持原值，不会自动漂移成 `品牌号`。
- 让品牌作品信息及数据表里的“作者昵称”进入更靠前的位置，打开列表即可直接看到。

## 3. 修改内容

### 3.1 后端

- 在 `apps/server/src/modules/collectors/collectors.service.ts` 修复抖音手动账号合并逻辑：
  - 手动抖音账号改为基于规范化 locator 生成稳定 ID，不再使用按序号递增的临时 ID。
  - 这样逐条提交第二个账号时，不会再因为匹配键复用而覆盖第一个账号。
- 修复品牌账号角色回写逻辑：
  - 当仅传入裸链接、未显式传 `accountRole`` 时，不再把已有角色强制改写成 `BRAND`。
  - 手动链接与显式角色条目的合并顺序调整为“先链接、后显式角色”，确保员工号/达人号等明确角色优先级更高。

### 3.2 前端

- 在 `apps/web/src/app/(dashboard)/brand-growth/collection-workspace.tsx` 中将 `DouyinMaterialReadyWorksTable` 的“作者昵称”列前移到 `作品 ID` 后方，提升品牌作品信息及数据表的首屏可见性。

## 4. 修改意图

- 抖音账号逐条提交的核心预期是“增量更新当前账号，而不是覆盖之前已采集账号”，因此匹配键必须稳定。
- 品牌账号的账号类型直接影响运营判断和后续作品来源解释，不能在同步过程中被默认值悄悄篡改。
- 作者昵称是品牌作品列表中的高频识别字段，比粉丝数、总获赞更适合放在前排展示。

## 5. 影响范围

- 影响页面：`/brand-growth` 下的抖音采集工作区。
- 影响模块：品牌账号信息、竞品账号信息、品牌作品信息及数据、竞品作品信息及数据。
- 是否影响已有数据：不会删除已有采集资产；后续重新同步时会按更稳定的匹配逻辑更新账号结果。

## 6. 验证方式

- 手工验证：
  - 在“竞品账号信息”里连续提交两个不同账号，确认下方结果列表保留两个账号，不会只剩最后一次提交的数据。
  - 在“品牌账号信息”里分别提交 `品牌号` 与 `员工号`，确认刷新或再次同步后角色仍保持原值。
  - 在“品牌作品信息及数据”列表中确认“作者昵称”进入靠前列，首屏即可看到。
- 编译/诊断验证：
  - 执行相关文件诊断。
  - 执行 `npm --workspace apps/server run build`。
  - 执行 `npm run build:web`。

## 7. 风险与后续

- 当前修复覆盖的是手动录入账号链路；如果后续要把账号角色长期持久化到独立配置表，还可以再补数据库级角色存储。
- 当前作品表的列较多，后续如果运营还要继续压缩横向滚动，可以再做“常用列优先 + 次要列折叠”。
