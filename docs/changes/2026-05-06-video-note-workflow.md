# 2026-05-06 视频笔记工作流

## 背景

当前 MVP 已经有原创笔记、二创笔记和发布链路，但“小红书 / 视频笔记”仍停留在脚本占位区，不符合真实作品流要求。

本次目标是把视频笔记收口到与原创/二创同一作品域，只保留与视频笔记创作直接相关的内容。

## 本次实现

### 1. 后端 `WorksModule` 增加视频笔记作品流

- 新增 `/works/brands/:brandId/xiaohongshu/video` 的列表、生成、编辑、删除接口
- 在 `works.service.ts` 新增视频笔记元数据与作品记录类型
- 生成链路拆为三段：
  1. 读取营销策划方案、营销日历、产品或参考图输入
  2. 基于 `rewrite_copy` 风格提示生成视频笔记标题与正文
  3. 基于 `short-video-api-studio` 风格提示生成短视频提示词，并调用第三方视频接口创建与轮询任务
- 作品保存字段覆盖：
  - 标题
  - 正文
  - 笔记分类：原创
  - 笔记类型：视频
  - 视频地址
  - 视频生成提示词
  - 创建时间

### 2. 前端 `/xiaohongshu` 的“视频笔记”改为真实工作区

- 移除原先仅展示“脚本”的占位卡片
- 新增视频笔记创作状态区
- 新增顶部按钮“添加视频笔记”
- 新增历史卡片列表，卡片以封面 + 标题为主，并保留编辑、删除、预览
- 新增创建弹窗，字段对应当前产品要求：
  - 营销日历
  - 产品
  - 参考图上传
  - 文案用户要求
  - 视频模型
  - 视频时长
  - 是否输出视频提示词
  - 短视频补充要求
- 新增编辑弹窗，可调整标题、正文和视频生成提示词

### 3. 视频生成链路补充自动降级与清晰报错

- 当用户首选的视频 provider 不可用时，后端不再直接停在单一 provider 内部失败，而会按稳定顺序继续尝试其他视频 provider
- 默认优先保留用户所选 provider，其后优先回落到 `seedance` 稳态链路，再尝试 `veo / wan / kling / hailuo`
- 网络请求异常不再只回显笼统的 `fetch failed`，而会尽量返回带请求地址和超时/网络失败语义的中文错误，便于前端状态区和日志直接定位

## 当前边界

- 视频生成时长会先保留用户请求值，同时按第三方 provider 当前支持范围选择最接近的时长执行
- 现阶段优先保证 `seedance / veo / wan / kling / hailuo` 五类 provider 的真实调用骨架一致，默认优先以 `seedance` 作为稳态入口
- 若用户手动指定了某个 provider，系统会先按该 provider 执行；只有在该 provider 请求或轮询失败时，才自动降级到后续 provider
- 视频笔记暂不接入站内“一键发布”，只先沉淀到“我的作品”
