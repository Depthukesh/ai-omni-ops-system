# 2026-06-12 个人中心第五批上线：移动端表格可读性收口

## 为什么改

- 个人中心前几批已经完成壳层、文案和整体视觉基线统一。
- 剩余体验问题主要集中在移动端表格阅读上，邀请页和团队页在手机宽度下信息列过多，阅读成本偏高。
- 本批继续遵守低风险原则，只处理 `personal-center` 范围，不改业务逻辑。

## 本次范围

- `apps/web/src/styles/globals.css`
- `apps/web/src/app/(dashboard)/personal-center/invites/page.tsx`
- `apps/web/src/app/(dashboard)/personal-center/team/page.tsx`

## 这次改了什么

### 1. 邀请中心表格移动端收口

- 给待处理邀请和邀请总览表格补充移动端字段标签。
- 在小屏下将表头式表格切换为逐行卡片阅读，不再依赖横向滚动才能理解每一列。
- 保留桌面端表格结构不变。

### 2. 团队协作表格移动端收口

- 给待处理邀请、当前品牌成员、审计日志三组核心表格补充移动端字段标签。
- 在手机宽度下将每一行转成卡片式信息块，减少横向挤压。
- 不改权限矩阵和现有操作逻辑。

### 3. 响应式样式补充

- 新增 `table-responsive-stack` 和 `mobile-table-label` 样式。
- 仅在移动端启用表格卡片化表现，桌面端仍维持现有布局。
- 保持现有品牌色、圆角和浅色内容面板体系一致。

## 明确不改的内容

- 不改登录、鉴权、接口协议和数据库结构。
- 不新增接口请求，不增加服务器负担。
- 不引入新依赖，不增加复杂动画。

## 验证

- `invites/page.tsx` 诊断通过
- `team/page.tsx` 诊断通过
- `globals.css` 诊断通过
- 新增响应式类只作用于显式标记的表格，不影响其他后台页

## 后续建议

- 下一批可以继续收按钮文案长度和空态引导动作，让移动端信息阅读和操作闭环更完整。
