基于现有系统文档的正式开发方案

OpenClaw 详细开发方案

这份方案以当前 AI 全域运营系统的真实架构、品牌上下文、权限体系、技能中心、知识库运行时、 正式任务体系和重构路线为前提，目标不是做一个临时机器人，而是做一个能随着网站持续优化而长期稳定演进的智能体接入层。

主结论 Skill 负责认知编排，MCP 负责正式执行，CLI 仅做后台受限执行器。
核心边界 品牌上下文、正式权限、知识运行时、Task 体系，四条边界必须完全复用现有系统。
演进目标 后续页面拆壳、服务拆分、工作台扩展时，OpenClaw 接入层不频繁返工。
产品目标 员工在权限内自由使用网站能力和读取数据，但所有自由都发生在受控边界之内。

系统真实约束

品牌上下文优先

  • 所有品牌域工作区都围绕真实 `brandId` 运行。
  • 后端已要求按品牌成员关系做访问校验，不能只信前端传值。
  • OpenClaw 必须显式感知品牌，不能默认跨品牌。

权限是多层模型

  • 系统同时存在后台身份、会员层、品牌角色和板块级权限。
  • OpenClaw 不能只判断是否登录或是否管理员。
  • 必须继承真实身份、品牌成员关系、动作权限和数据范围。

技能与知识已进入运行时

  • 技能中心已经成为能力包治理中心，而不只是 prompt 编辑页。
  • 知识绑定运行时已按“模块 → 能力包 → 技能”继承解析真实生效。
  • OpenClaw 必须复用这套治理与运行时边界。

系统仍在持续重构

  • 页面做薄、业务下沉、Feature 化、Service 分层仍会持续推进。
  • OpenClaw 不能绑页面结构、不能绑当前 service 文件位置。
  • 必须绑定稳定领域动作和工具协议。

推荐架构

1. 用户入口层 网站助手入口、OpenClaw 客户端、消息渠道入口。
2. 授权交换层 授权票据、会话交换、续期、撤权、设备绑定。
3. Skill 层 系统认知、品牌确认、工具路由、确认策略、输出风格。
4. MCP 主执行层 正式工具网关、参数 Schema、权限裁决、审计、限流、版本治理。
5. 领域适配层 对接现有后端模块、聚合接口、能力对象与数据裁剪逻辑。
6. 任务与知识运行时 复用正式 Task、知识绑定运行时、Provider 与模型治理规则。
7. 数据与基础设施 PostgreSQL、OSS、知识库主数据、任务记录、审计日志、媒体资产。

三种方式分工

必须有 不做最终裁决

Skill

  • 负责认知系统、理解意图、确认品牌、选择工具、组织回答。
  • 不负责最终权限放行，也不应直接承担高风险执行。
  • 适合承载领域知识和对话编排。
主执行层 推荐正式方案

MCP

  • 负责正式工具协议、上下文注入、权限裁决、审计、限流与错误码。
  • 是连接 OpenClaw 与网站稳定能力层的核心网关。
  • 最适合承接长期演进和多客户端接入。
仅内部受限 不宜直接给员工

CLI

  • 适合索引重建、诊断修复、批量同步、运维自动化。
  • 不适合作为员工网站主能力层，也不适合承担精细授权主通道。
  • 必须白名单化、隔离化、审计化。

长期可维护的关键设计

不绑页面

OpenClaw 绑定的是领域动作与工具协议，而不是当前页面按钮和 UI 结构。

不绑 service 文件

后端继续拆分 facade、gateway、repository 时，OpenClaw 通过稳定能力网关接入，不跟着大改。

围绕模块/能力包/技能

这三层已经是知识绑定和技能治理的真实运行维度，应成为 OpenClaw 的一等建模对象。

版本化协议

MCP 工具和结果契约从一开始就版本化，后续能力升级可增量发布，不破坏旧接入端。

权限设计

四层权限模型

  • 身份层：`userId`、后台身份、会员层、会话风险状态。
  • 品牌成员层：当前品牌、是否成员、品牌角色、是否管理员。
  • 动作层：`actionCode`、板块权限、是否可 view/edit/manage/export。
  • 数据视图层：只看摘要、看明细、脱敏明细、禁止导出等。

当前系统建议映射

  • 平台层继续沿用 `systemRole` 体系。
  • 品牌层优先沿用当前真实前台角色：`ADMIN / STAFF / TALENT`。
  • 再叠加动作码和数据视图策略，而不是重造一套前台角色。
  • OpenClaw 的能力开放必须与真实页面权限一致或更严。
风险等级 典型动作 控制方式
L1 读取品牌资料、任务状态、知识库列表、技能详情 自动执行，正常审计
L2 新增知识库、上传资料、创建草稿任务、更新个人偏好 简短确认，正常审计
L3 修改品牌技能覆盖、重置品牌基线、批量触发生成、删除资料 二次确认，强审计，可回滚或可恢复
L4 全量敏感导出、授权调整、后台修复作业、批量重置 管理员批准、审批流、强告警

模块映射

认证与品牌

  • 复用现有 `/api/auth/*` 体系。
  • 正式新增 OpenClaw 授权交换接口，不替代原登录体系。
  • 品牌切换保持显式动作。

技能中心

  • 围绕能力包模型接入，而不是只围绕 prompt 文件接入。
  • 区分平台基线、品牌覆盖、用户偏好。
  • OpenClaw 不应绕过技能治理层。

知识库运行时

  • 直接复用现有“模块 → 能力包 → 技能”继承式知识绑定运行时。
  • 不再额外造一套机器人专用知识层。
  • 调用记录继续走统一知识调用日志。

任务中心

  • 所有生成、发布、长耗时动作都进入正式 Task。
  • OpenClaw 只负责触发、读状态、解释结果。
  • 标准返回应包含 `taskId / status / stage / result`。

Provider 与模型治理

  • OpenClaw 读取当前技能中心与 Provider 治理结果。
  • 不自己写死模型名，也不绕过 fallback 规则。
  • 异常时返回真实尝试顺序和失败信息。

受限 CLI

  • 只对后台治理和修复场景开放。
  • 通过白名单作业执行器包装，不向普通员工暴露。
  • 全量审计，最小权限运行。

MCP 工具分组

会话与上下文

  • `get_my_identity`
  • `get_my_brands`
  • `get_current_brand`
  • `switch_brand`

品牌与资料

  • `get_brand_summary`
  • `get_brand_archive`
  • `get_brand_products`
  • `get_brand_members`

任务与知识库

  • `list_brand_tasks`
  • `get_task_detail`
  • `list_knowledge_bases`
  • `upload_knowledge_files`

工作台与治理

  • `generate_brand_growth_report`
  • `generate_xhs_original_note`
  • `update_brand_skill_override`
  • `reset_brand_skill_baseline`

安全方案

会话安全

授权票据替代密码长期保存

  • 采用网站内授权票据或 OAuth 风格交换。
  • Access Token 短期有效，Refresh Token 绑定设备和客户端。
  • 支持按品牌、按客户端、按设备撤权。
品牌隔离

品牌从服务端解析

  • 所有品牌工具由服务端会话解析当前 `brandId`。
  • 不默认跨品牌聚合，不允许模型自行猜品牌。
  • 品牌切换必须显式调用。
Prompt Injection

不可信内容不提升权限

  • 知识库文档、网页内容、OCR 文本统一视为不可信输入。
  • 不可信输入只能影响内容，不改变工具规则和权限边界。
  • 最终裁决始终由 MCP 和后端领域服务完成。
字段治理

Data View 与字段脱敏

  • 读取权限不等于明细权限，也不等于导出权限。
  • 字段分级：公开、内部、敏感、受限。
  • 对话默认优先摘要，高敏字段默认脱敏。
CLI 约束

白名单与隔离执行

  • 模型不得直接拼 Shell 命令。
  • CLI 只允许白名单模板，并在隔离环境执行。
  • 命令执行全量审计，最小权限运行。
导出控制

读取不等于导出

  • 大批量导出走审批。
  • 下载链接短期有效，支持水印和导出原因。
  • 高敏导出纳入告警与强审计。

实施路线

阶段 0

底座定义

先补 Action Code、Tool Registry、Data View、权限矩阵、授权时序图，明确稳定能力层。
阶段 1

只读 MVP

跑通授权、品牌切换、品牌资料与任务只读、知识库和技能中心只读。
阶段 2

MCP 主执行层

把散式 API 调用收口到正式工具协议、风险分级、统一错误码和审计模型中。
阶段 3

低风险写操作

开放新增知识库、上传资料、触发报告生成、内容生成等常用低风险动作。
阶段 4

高风险动作与审批

开放技能基线重置、高敏导出、批量操作和治理动作，并接入审批与强审计。
阶段 5

后台受限 CLI

仅面向内部后台开放索引重建、批量修复、同步诊断等白名单作业。

最终建议

OpenClaw 在当前系统中的正确落点，不是页面自动化，也不是数据库代理，而是建立在 品牌上下文、正式权限、统一技能中心、 知识绑定运行时 和 正式 Task 体系 之上的稳定能力层。 只要接入层绑定的是能力而不是页面，后续网站继续重构和扩展，OpenClaw 就能保持长期可维护。
