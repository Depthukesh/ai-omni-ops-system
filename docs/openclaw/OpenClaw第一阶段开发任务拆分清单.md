# OpenClaw 第一阶段开发任务拆分清单

## 1. 文档定位

这份文档不是再讲方案，而是直接面向开工。

它把《OpenClaw首批高频任务清单》进一步拆成开发视角的清单，重点回答四个问题：

1. 每个高频任务需要接哪些后端能力
2. 每个高频任务需要调用哪些历史数据
3. 每个高频任务最小渠道侧交互和网站侧配合应该是什么
4. 每个高频任务应该排在什么优先级

一句话目标：

> 让研发团队可以按“任务”而不是按“模块”来开工，让第一阶段真正做出用户能直接感知价值的能力。

---

## 2. 拆分原则

## 2.1 按用户任务拆，不按系统模块拆

不要把任务拆成：

- 品牌增长模块开发
- 小红书模块开发
- 知识库模块开发

而要拆成：

- 看最近任务情况
- 总结失败任务原因
- 生成品牌增长报告
- 查看知识库最近新增资料

## 2.2 优先打通最小闭环

每个任务优先做到：

- 能识别用户意图
- 能自动带入当前品牌
- 能调用必要数据
- 能输出摘要结果

而不是一开始就把所有边角能力做满。

## 2.3 首先复用已有系统能力

第一阶段优先复用现有：

- 认证与品牌上下文
- 任务中心
- 知识库
- 技能中心
- 品牌增长报告
- 小红书与公众号生成链路

不建议第一阶段为了 OpenClaw 重造业务底座。

## 4. 逐任务开发拆分

## 4.1 看最近任务情况

### 用户任务

- 帮我看看最近 7 天的任务情况

### 需要接的后端能力

- 当前品牌上下文读取
- 任务列表读取
- 任务状态聚合
- 任务类型聚合

### 需要调用的历史数据

- 近 7 / 30 天任务历史
- 任务状态
- 任务阶段
- 任务类型

### 最小渠道侧交互

- 渠道会话内直接发起
- 任务摘要卡片
- “展开失败任务”快捷按钮
- “打开任务中心”跳转入口

### 后端开发点

- 新增任务摘要聚合接口或 MCP 工具
- 统一时间范围默认值
- 任务摘要结果格式化

### 风险等级

- `L1`

### 优先级

- `P0`

## 5. 公共开发项

这些不是某一个任务独有，而是第一阶段所有任务都会共用的公共底座。

## 5.1 后端公共项

- Assistant 授权与会话
- 当前品牌上下文继承
- MCP 工具执行层
- 任务摘要输出层
- 历史数据聚合层
- Data View 裁剪层
- 审计日志

## 5.2 渠道侧公共项

- 飞书 / 企微等渠道接入与会话路由
- 首次绑定消息与账号关联流程
- 渠道内结构化消息模板
- 文件 / 图片 / 链接回传能力
- 错误提示与重试消息
- 深链接到网站结果页或管理页

## 5.3 网站侧最小配合项

- 账号绑定或授权回调页
- 受控 API / MCP 能力层
- 复杂结果查看页
- 配置与审计管理页
- 深链接落点页

## 5.4 体验公共项

- 默认使用当前品牌
- 默认时间范围策略
- 单次最多 1 到 2 次追问
- 高风险动作确认
- 结果先摘要

---

## 7. 一句话结论

> OpenClaw 第一阶段开发最重要的，不是先把所有能力都接上，而是先围绕 12 个高频任务打通最小闭环：能识别、能自动带入品牌、能调历史数据、能输出摘要、能顺滑完成；只要这 12 个任务做顺，用户就会明确感受到它不是一个聊天壳子，而是真正能帮忙完成工作的助手。
