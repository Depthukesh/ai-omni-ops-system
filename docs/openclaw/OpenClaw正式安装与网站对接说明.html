OpenClaw 正式安装与网站对接说明

本说明对应正式环境安装方式，目标是把本地联调阶段的账号密码方案升级成网站安装中心 + 品牌级安装令牌 + MCP HTTP 网关。

目标

正式交付时，品牌用户不需要理解 MCP、Skill、CLI 差异，也不需要暴露网站登录密码。用户只需要登录网站，切到目标品牌，打开安装中心，复制配置，粘贴到 OpenClaw 即可。

  • 当前真正需要安装的是网站 MCP。
  • 页面里的“品牌运营助手 Skill”目前是官方使用规范和示例，不是额外必须安装的执行包。
  • 后续如果要扩展更多网站能力，建议先补 MCP 工具，再按场景补正式 Skill。

为什么不再用本地联调方式

  • 会暴露网站账号密码
  • 会要求用户在本机运行脚本
  • 很难做品牌级权限隔离
  • 不利于后续审计、吊销、续期

正式安装方式

  1. 网站安装中心生成品牌级安装令牌
  2. OpenClaw 通过 MCP HTTP 地址连接网站
  3. 网站 MCP 网关再转调现有 OpenClaw 能力层

用户体验是：登录网站 -> 切品牌 -> 打开 OpenClaw 安装中心 -> 生成令牌 -> 复制配置 -> 粘贴到客户端 -> 直接开始对话。

当前正式落地点

  • 网站页面：`apps/web/src/app/(dashboard)/personal-center/openclaw/page.tsx`
  • 安装页内已聚合 MCP 配置复制、令牌状态、Skill 示例、交付检查清单与正式文档入口
  • 网站接口：`GET /api/openclaw/installation-hub`、`POST /api/openclaw/installation-hub/tokens/rotate`、`DELETE /api/openclaw/installation-hub/tokens/:tokenId`、`POST /api/openclaw/mcp`
  • 服务端核心：`openclaw-installation.service.ts`、`openclaw-installation.controller.ts`、`openclaw.service.ts`

安全原则

  • 不暴露网站账号密码
  • 令牌绑定当前品牌
  • 令牌复用生成者的品牌权限
  • 令牌可重置、可吊销、可过期
  • 支持记录最近使用时间与状态

MCP 安装片段

{
  "mcp": {
    "servers": {
      "ai-omni-ops-品牌名": {
        "enabled": true,
        "url": "https://你的域名/api/openclaw/mcp",
        "transport": "streamable-http",
        "headers": {
          "Authorization": "Bearer ocp_xxx",
          "x-brand-id": "br_xxx"
        }
      }
    }
  }
}

Skill 使用方式

Skill 不再要求用户自己写复杂 prompt。网站安装中心会同步给出品牌运营助手示例提问：

  • 帮我看当前品牌最近的增长报告重点
  • 帮我创建一个品牌知识库，并把这份资料加入进去
  • 帮我看最近 30 天失败任务主要卡在哪些问题上
  • 围绕这个品牌生成一份半年营销规划

MCP 与 Skill 的关系

  • 当前正式可交付的是 MCP 安装链路，用户安装 MCP 后已经可以直接调用网站暴露的品牌能力。
  • 页面里的 Skill 区块主要用于说明“品牌运营助手如何理解任务、如何编排调用 MCP”，不是额外必装插件。
  • 如果后面要增加更多网站技能，建议先沉淀新的 MCP tool，再为高频场景编写正式 Skill。
  • 如果用户自己安装了相似 Skill，比如也能做小红书原创笔记，OpenClaw 不一定天然优先调用我们这一方。
  • 正式场景应让官方 Skill 明确优先调用 ai-omni-ops MCP，避免能力重叠时路由漂移。
