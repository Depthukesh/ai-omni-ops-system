开发可拆任务的规格层文档

OpenClaw 接口与权限落地规格 v1

这份文档把方向方案继续压缩到可实施规格层，核心目标是先定义清楚 Action Code、MCP Tool Registry、 角色权限矩阵、Data View、 授权时序 和 审计日志结构， 让 OpenClaw 的后续开发建立在稳定底座上，而不是建立在零散接口和页面实现上。

主底座 Action Code + Tool Registry + Data View + 审计日志。
主执行层 MCP 工具网关是正式执行层，Skill 只做认知编排。
权限策略 复用现有品牌权限体系，再叠加动作码和数据视图策略。
长期目标 后续页面重构、工作台扩展和知识库演进都不需要重做整套接入。

核心结构

Action Code

定义系统能力动作，不按页面、不按组件、不按当前 service 文件命名。

MCP Tool

每个工具绑定主 Action Code、输入输出 Schema、风险等级和最小权限。

Scope

表达可执行动作范围，如 `task.retry`、`knowledge.file.upload`。

Data View

决定同一条数据在不同角色下是返回摘要、明细、脱敏明细还是受限结果。

Data View 与字段分级

Data View

  • `SUMMARY`：只返回摘要和关键业务字段
  • `DETAIL`：返回可见明细
  • `MASKED_DETAIL`：返回脱敏明细
  • `EXPORTABLE_DETAIL`：导出级完整明细
  • `RESTRICTED`：不返回内容，只返回权限说明

字段分级

  • `PUBLIC`：可直接对话返回
  • `INTERNAL`：内部业务字段，视角色返回
  • `SENSITIVE`：默认脱敏或摘要化
  • `RESTRICTED`：聊天不直接返回
实体 可直接返回 需脱敏 默认禁止
Brand 名称、行业、简介 联系电话 账单与结算信息
BrandMember 姓名、品牌角色 邮箱、手机号 无额外高敏认证信息
Product 产品名、定位、价格区间 供应成本 内部结算价
Task 标题、类型、状态、阶段 错误明细 原始输出 JSON
Skill Override 展示名、摘要 完整 Prompt、Provider 摘要 API Key

授权时序

Step 1

网站内发起授权

用户确认品牌、客户端名称、可用能力范围和有效期，网站生成一次性授权码。
Step 2

OpenClaw 交换会话

客户端提交授权码、`clientId` 和 `deviceId`，换取 `accessToken`、`refreshToken`、授权品牌范围和 Scope。
Step 3

工具调用

服务端从 token 中解析 `userId / brandId / scopes / dataView`，再执行 MCP 工具并记录审计。
Step 4

续期与撤权

通过 `refreshToken` 续期，用户或管理员可在网站内撤销授权，撤权后 token 立即失效。

审计与批准流

AssistantGrant

记录授权关系，包括用户、客户端、品牌范围、Scope、状态与有效期。

AssistantSession

记录当前会话、设备、最近品牌、过期时间与撤销状态。

AssistantToolExecutionLog

记录每次工具调用，包括 requestId、toolName、actionCode、riskLevel、taskId 与结果摘要。

AssistantApprovalRequest

记录 L3/L4 动作的确认与审批，包括审批模式、审批人、审批结果和载荷摘要。

REST 与 MCP 契约

授权接口

  • `POST /api/assistant/auth/authorize`
  • `POST /api/assistant/auth/exchange`
  • `POST /api/assistant/auth/refresh`
  • `POST /api/assistant/auth/revoke`
  • `GET /api/assistant/session`

统一响应信封

  • `success`
  • `requestId`
  • `brandId`
  • `actionCode`
  • `riskLevel`
  • `data / task / error`

典型错误码

  • `AUTH_REQUIRED`
  • `BRAND_CONTEXT_REQUIRED`
  • `ACTION_FORBIDDEN`
  • `CONFIRMATION_REQUIRED`
  • `DATA_VIEW_RESTRICTED`

最终建议

OpenClaw 的第一优先级不是先把聊天做得多聪明，而是先把 动作编码、工具注册、 权限矩阵、数据视图、 授权时序 和 审计日志 这六块底座定义清楚。底座一旦稳定，后续新增工作台、技能、知识绑定和页面重构都能低成本接入。
