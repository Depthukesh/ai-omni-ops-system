方案总览

OpenClaw 对接网站方案可视化

目标是把 OpenClaw 接成“品牌运营智能助手”：以用户身份登录网站，在品牌上下文中读取品牌资料、资产、任务、技能中心配置，并在权限允许时调用已有工作台能力。

单库多品牌 品牌上下文强约束 不直连数据库 通过 API / Tool / MCP 层接入 平台基线 + 品牌共享覆盖

一、核心结论

可以做

适合当前系统

现有网站已具备用户、品牌、任务、资产、技能中心和报告能力，非常适合做 OpenClaw 品牌助手。

关键原则

不要直接给数据库

OpenClaw 应该像一个“会用你网站 API 的智能客户端”，而不是直接操作 PostgreSQL 的超管脚本。

正确角色

品牌运营副驾

OpenClaw 负责理解系统结构、调用工具、回答问题、触发功能，而不是代替网站本身的业务层。

二、总体架构

第 1 层

OpenClaw

  • 接收用户自然语言
  • 维护会话与品牌上下文
  • 加载品牌运营助手 Skill
  • 调用网站工具层
→
第 2 层

网站助手工具层

  • 登录与品牌切换
  • 品牌资料读取
  • 品牌资产与任务读取
  • 工作台功能触发
  • 品牌技能中心读写
→
第 3 层

网站现有业务系统

  • 用户与品牌权限
  • 品牌资料库
  • 任务与媒体资产
  • 工作台与生成链路
  • 品牌技能中心覆盖
推荐顺序：先做“网站助手工具层”，再让 OpenClaw 接入；不要让 OpenClaw 直接连接数据库。

三、认证与品牌上下文流程

1

用户授权

  • 第一版可用账号密码直登
  • 正式版建议改为授权票据
2

获取会话

  • 换取 token / session
  • 绑定 OpenClaw 当前用户
3

拉取品牌列表

  • 读取可访问品牌
  • 默认当前品牌或提示选择
4

进入品牌上下文

  • 后续所有请求强带 brandId
  • 不允许默认跨品牌
5

问答与执行

  • 读问题走只读工具
  • 写操作先确认再执行

四、品牌数据分层

层级 数据类型 典型数据 给 OpenClaw 的接入方式
全局共享 平台基线配置 SkillConfig、PromptTemplate、ApiProviderConfig、ThirdPartyPlatformConfig 只读或受控读写；不直接下发数据库权限
品牌隔离 品牌业务数据 Brand、Product、BrandSurvey、PlatformAccount、CompetitorAccount、IndustryReport、BusinessAsset 按 brandId 通过助手工具层读取
品牌隔离 品牌工作台与任务 Task、MediaAsset、每日热点、抖音选题、营销策划方案、营销日历 按工作台能力暴露高语义工具
品牌隔离 品牌技能中心 BrandSkillProfile、BrandPromptOverride、BrandSkillResetLog 品牌管理员受控写入，成员只读
文件 / OSS 源码与媒体文件 提示词源文件、SKILL.md、图片、视频、HTML、归档文件 通过文件 URL / storageKey / 元数据间接读取

六、OpenClaw Skill 应该知道什么

系统认知

  • 这是品牌运营系统，不是通用数据库
  • 当前是单库多品牌
  • 所有品牌业务数据都必须按 brandId 读取
  • 平台基线与品牌覆盖是两层结构

行为规则

  • 没品牌就先问品牌
  • 只通过工具取真实数据
  • 写操作前必须复述影响
  • 权限不足时不能绕过系统
Skill 负责“认知规则和调用策略”，真实数据由工具层实时提供，不应把业务真实数据硬编码进 Skill。

七、你最关心的能力映射

问答能力

OpenClaw 可以回答品牌资料、产品、人群、竞品、资产、任务、技能中心配置等问题。

执行能力

OpenClaw 可以在权限允许时帮助用户调用热点找选题、任务查询、品牌技能中心恢复平台基线等功能。

解释能力

OpenClaw 可以基于 Skill 知道数据是什么、彼此怎么关联、什么时候该用哪个工具回答问题。

八、安全边界

禁止

  • 不给 OpenClaw 数据库直连权限
  • 不允许默认跨品牌取数
  • 不允许返回密码、密钥、第三方平台敏感凭据
  • 不允许无确认执行高风险写操作

必须有

  • 用户身份绑定
  • 品牌上下文绑定
  • 权限校验
  • 操作确认
  • 审计日志

九、推荐实施顺序

1

整理工具层

  • 先把品牌助手 API / MCP 工具定义出来
  • 统一受控读写边界
2

接入登录与品牌切换

  • 先跑通登录、品牌列表、当前品牌
  • 保证多品牌不串数据
3

做首版 Skill

  • 把系统认知、数据关系、工具规则写清楚
4

先做只读问答

  • 品牌档案、资产、任务、技能中心查询
5

再开低风险写操作

  • 热点找选题
  • 恢复平台基线
  • 品牌提示词调整

十、最终建议

最适合你的实现方式是：把 OpenClaw 做成“带品牌上下文和权限控制的品牌运营智能客户端”， 它通过网站助手工具层访问真实数据和功能，借助 Skill 理解系统结构与关系，再把答案和执行结果交付给用户。
