OpenClaw 第一阶段 MCP 工具字段草案

这份文档把第一阶段 MCP 工具从“能力清单”继续收口到“接近可实现的字段契约”，重点明确请求参数、返回字段、服务端自动补齐字段和不应暴露的内部字段。

目标让 MCP 更接近可实现字段设计。
原则身份和权限由服务端解析，不依赖客户端裸传。
输出优先摘要、结构化字段和深链接。
边界不暴露数据库主键、错误堆栈和内部服务细节。

统一字段原则

服务端自动解析

  • `userId`
  • `role`
  • `scopes`
  • 默认品牌
  • 默认时间范围

统一响应层

  • `title`
  • `summary`
  • `status`
  • `highlights`
  • `links`

通用结构

请求结构

{
  "context": {
    "brandId": "optional-if-user-specified",
    "timeRange": "optional",
    "platform": "optional"
  },
  "input": {}
}

响应结构

{
  "status": "success",
  "title": "最近 7 天任务摘要",
  "summary": "最近 7 天共有 12 个任务，8 个已完成，2 个进行中，2 个失败。",
  "highlights": [],
  "data": {},
  "links": [],
  "allowed": true,
  "requiresConfirmation": false
}

重点控制建议

不要裸传身份

用户身份、角色、scopes 应统一由服务端绑定关系解析。

不要返回内部细节

不要暴露原始主键、错误堆栈、Provider 内部配置和服务名。

兼容渠道消息

字段结构要让 Skill 能稳定消费，也要便于后续做飞书、企微结构化消息模板。

第一阶段字段设计不追求“接口完整性”，而优先追求“对话可消费性”和“网站侧实现可控性”。
