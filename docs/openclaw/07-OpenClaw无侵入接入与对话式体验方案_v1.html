无侵入上线 + 极简对话体验

OpenClaw 无侵入接入与对话式体验方案 v1

这份方案专门解决两个实施中最容易跑偏的问题：一是 OpenClaw 不能影响网站正常运行， 必须可灰度、可降级、可回滚；二是用户授权后应尽量通过对话完成权限范围内的所有功能和数据查看， 只有真正高风险或缺少关键参数时才追问或确认。

系统底线 OpenClaw 故障不能拖垮主站，关闭 OpenClaw 后原功能必须完整可用。
体验底线 授权一次后，大部分场景主要靠对话完成，而不是频繁跳页和填表。
上线策略 先只读、后低风险写、再高风险治理；先内测、再灰度、再全量。
交互策略 能自动推断就自动推断，只在真正必要时追问，且追问数量最小化。

两条硬约束

强约束

不能影响网站正常运行

  • OpenClaw 接入失败，网站原功能仍必须正常可用。
  • OpenClaw 异常不能拖慢主站核心页面和主 API。
  • 必须支持快速开关、灰度、降级和回滚。
强约束

用户使用必须足够方便

  • 授权后，尽量通过对话完成权限内的所有功能和数据查看。
  • 不要求用户学习系统 ID、slug、targetKey 等内部字段。
  • 不把低风险动作做成层层确认和重复填表。

无侵入接入原则

不改主链路

OpenClaw 是新增辅助入口，不替代原页面主入口，不劫持原有提交流程。

独立 Gateway

通过 Assistant Gateway / MCP Gateway 承接模型、审计、限流和风险控制，避免把压力直接压到主站。

三层解耦

把现有网站能力、稳定能力接口层、对话入口层分离，避免 UI 或 service 变动波及 OpenClaw。

只做加法

首期只新增授权入口、助手入口和受控工具，不做危险替换，不强迫所有用户改用对话流程。

不影响主站的技术策略

功能开关

  • 平台级总开关
  • 品牌级开关
  • 工具级开关
  • 渠道级开关

灰度发布

  • 内部只读灰度
  • 内部低风险写灰度
  • 小范围品牌灰度
  • 验证后再全量

熔断与降级

  • 先禁写，只保留只读
  • 再禁模型，只保留结构化查询
  • 再禁外部客户端，只保留站内入口
  • 最后可完全关闭 OpenClaw

限流与配额隔离

  • OpenClaw 请求单独限流
  • 模型调用单独配额
  • 高成本工具单独并发上限
  • 任务提交速率单独限制

Shadow Mode

  • 正式放量前先做影子模式
  • 模拟理解和路由，但不真正写入
  • 用来校验 Skill 路由和工具选择准确率

审计先于放量

  • 每次工具调用可追踪
  • 每次品牌切换可追踪
  • 每次高风险确认可追踪
  • 没有审计不应大范围灰度

对话式体验原则

体验核心

授权一次，后续少打断

  • 自动记住当前身份、当前品牌、可用能力、数据范围。
  • 用户不应每次重复说明自己是谁、在哪个品牌。

只在必要时追问

  • 能自动推断的就自动推断。
  • 只有影响结果、权限或高风险执行时才追问。
  • 单次追问尽量 1 到 2 个问题内解决。

低风险动作直接做

  • 只读查询尽量单轮完成。
  • 常见低风险生成尽量 1 到 2 轮完成。
  • 不要把系统做成每一步都再确认一次。

高风险动作明确确认

  • 删除知识资料
  • 重置品牌技能基线
  • 导出完整敏感数据
  • 触发后台 CLI 作业

不暴露系统字段

  • 用户用品牌名、知识库名称、任务标题说话即可。
  • 底层 `slug`、`targetId`、内部任务 ID 由系统自动映射。

对话优先，页面补充

  • 只读和低风险执行优先在对话内完成。
  • 只有复杂编辑、审批或大表大图场景才跳页。

授权后的理想体验

用户第一次授权后

  • 明确反馈已授权成功
  • 展示默认品牌
  • 展示当前可用能力
  • 标明哪些能力需要额外权限或审批

用户后续可直接说

  • “看看我们品牌最近的任务情况”
  • “帮我生成一份品牌增长报告”
  • “把企业知识库里上周新传的资料列出来”
  • “给我做一版小红书原创图文”
理想状态应接近：授权一次，打开就能问，问了就能看，说了就能做，做完就有结果，只有风险高时才需要确认。

对话策略

当前品牌默认策略

  • 优先使用当前网站品牌上下文。
  • 外部客户端优先使用最近一次品牌。
  • 无法判断时再单次追问，不默认跨品牌汇总。

默认参数策略

  • 默认最近 7 天
  • 默认当前品牌
  • 默认当前工作台
  • 默认最近一次同类任务配置

结果呈现策略

  • 先给摘要
  • 再给关键指标
  • 再给后续操作建议
  • 必要时再提供“展开详情”或“打开页面”

推荐上线顺序

阶段 1

只读优先

先开放身份读取、品牌切换、品牌摘要、任务读取、知识库读取、技能中心读取。
阶段 2

低风险写操作

再开放新建知识库、上传资料、触发报告生成、触发内容生成。
阶段 3

高风险治理动作

最后开放技能覆盖更新、基线重置、高风险导出和后台治理工具。

观测指标

指标类型 建议观察项
无侵入指标 主站核心页面 P95 延迟、OpenClaw 故障时主站是否可用、5 分钟内是否可关闭
体验指标 首个成功任务轮数、只读查询单轮完成率、非必要追问率
业务指标 对话触发任务成功率、对话完成率、跳页补充率、高风险确认通过率

最终建议

OpenClaw 要真正好用，必须同时满足两个条件：技术上与主站低耦合、可灰度、可降级、可回滚； 产品上授权一次后主要靠对话完成，只有真正必要时才追问或确认。缺少任何一边，最终都很容易做成“系统不稳”或“体验很重”的半成品。
