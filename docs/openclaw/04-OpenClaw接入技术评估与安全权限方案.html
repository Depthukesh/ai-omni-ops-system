OpenClaw 对接增强方案

OpenClaw 接入技术评估与安全权限方案

目标不是做一个只能回答问题的聊天机器人，而是做一个真正能代表员工、在权限内自由调用网站能力、 同时又不会越权、不会串品牌、不会泄露敏感数据的品牌运营智能体体系。

推荐接入 Skill 负责认知与路由，MCP 负责受控执行，CLI 仅作为后台受限执行器。
权限目标 员工在权限内尽量自由使用全部可用功能和可见数据，而不是被 AI 接入方式额外限制。
安全目标 不越权、不串品牌、不泄密、高风险动作有确认、有审计、有追踪。
实施路线 先统一权限模型，再做 Skill + 聚合 API，随后升级为 MCP 主执行层。

技术评估结论

起步快 需要配合工具层

Skill

  • 适合承载系统认知、品牌上下文规则、工具路由、写操作确认规则。
  • 可以显著提升自然语言体验和多轮协作质量。
  • 本身不是权限系统，也不是最终安全边界。
  • 必须和受控执行层配合，不能单独承担高风险能力开放。
推荐主执行层 结构化强

MCP

  • 最适合作为网站智能体的统一工具网关和能力注册中心。
  • 便于统一注入用户、品牌、角色、Scope、数据可见性策略。
  • 便于做限流、审计、错误码治理、灰度发布和工具版本管理。
  • 长期最利于多客户端、多品牌、多角色的持续扩展。
适合内部 不宜直接开放给员工

CLI

  • 适合内部运维、批量处理、诊断修复、后台自动化。
  • 不适合作为网站级主能力层，员工体验、权限治理和返回结构都不理想。
  • 一旦隔离不严，命令注入和主机扩权风险远高于 API 或 MCP。
  • 应被 MCP 或后台服务白名单封装，而不是直接暴露给普通员工。

推荐架构

1. 入口层 网站前端、消息渠道、OpenClaw 客户端，负责用户自然语言请求入口。
2. Skill 层 负责系统认知、品牌上下文规则、工具选择策略、风险提示和输出风格。
3. MCP 层 负责工具注册、结构化调用、鉴权、审计、限流、错误码和版本治理。
4. 领域服务层 复用现有网站业务服务与聚合 API，真正执行品牌数据读取和业务操作。
5. 数据层 数据库、对象存储、任务系统、知识库、现有工作流与业务基础设施。

权限设计

四层权限模型

  • 身份层：你是谁，是否有效登录，是否风险会话。
  • 品牌成员层：你属于哪个品牌，在该品牌下是什么角色。
  • 能力层：你能调用哪些动作，如读取资产、触发生成、修改技能。
  • 数据范围层：你能看到哪些记录、哪些字段、是否能导出明细。

推荐授权模型

  • RBAC：定义 OWNER、ADMIN、EDITOR、OPERATOR、VIEWER 基础边界。
  • Scope：定义 `brand.asset.read`、`task.run`、`skill.reset.baseline` 等动作。
  • Policy：定义“仅可读本部门”“仅可导出摘要”“敏感字段脱敏”等限制。
  • 所有 MCP 工具必须自动继承 `userId / brandId / role / scopes / policies`。
员工的“自由使用”不等于取消限制，而是让系统自动代替员工携带权限边界，使其无需记住复杂菜单和规则，也不会因为 AI 接入而被额外阉割能力。

自由使用但不越权

能力发现

  • 进入助手即返回当前品牌、当前角色、可用能力列表。
  • 不可用能力也说明原因，避免员工反复试错。

自动上下文

  • 每次工具调用自动带上用户、品牌、组织、角色和数据范围策略。
  • 员工可以自然表达需求，系统负责边界收口。

风险分级

  • L1 只读直接执行。
  • L2 低风险写操作简短确认。
  • L3 高风险操作二次确认、审计、可回滚。
  • L4 敏感操作要求管理员批准或双人确认。

安全威胁与方案

身份风险

身份冒用与会话劫持

  • 授权码一次性、短时有效，Access Token 短期有效，Refresh Token 绑定设备与客户端。
  • 高风险操作要求最近一次强认证或二次确认。
  • 支持按品牌、客户端、设备撤销授权。
数据隔离

跨品牌数据泄露

  • 所有工具从服务端会话解析 `brandId`，不只信前端传值。
  • 品牌切换必须显式调用，默认不做跨品牌聚合。
  • 返回结果统一附带品牌标识，便于审计和用户感知。
权限风险

越权调用

  • 页面权限不能代替服务端权限，所有裁决都在 MCP 与领域服务层完成。
  • 每个工具绑定最小权限要求，权限失败返回结构化拒绝原因。
  • 定期检查页面权限与工具权限的一致性。
模型风险

Prompt Injection 与内容诱导

  • 外部网页、知识库文档、OCR 文本全部标记为不可信内容。
  • 不可信内容只能影响回答内容，不能提升权限或改变工具规则。
  • MCP 层执行最终权限裁决，不接受模型文本越权。
批量风险

工具滥用与批量破坏

  • 高风险和批量工具需要展示影响摘要后再确认。
  • 对单用户、单品牌、单工具做限流与熔断。
  • 批量删除、批量恢复、批量导出走管理员批准。
泄密风险

敏感数据与导出失控

  • 建立字段分级：public、internal、sensitive、restricted。
  • 聊天默认返回摘要，导出权限独立于读取权限。
  • 短期签名下载、导出审计、水印和原因记录。
执行风险

CLI 命令注入与扩权

  • 模型不得直接拼 Shell 命令。
  • CLI 只允许白名单命令模板，并在隔离环境中执行。
  • 运行身份使用最小权限账户，命令执行全量审计。
治理风险

审计缺失与成本失控

  • 统一记录 `requestId / userId / brandId / tool / riskLevel / traceId`。
  • 高成本工具返回预计消耗并要求确认。
  • 对异常用量、异常失败率、异常导出自动报警。

实施路线

阶段 1

统一权限与能力模型

先定义角色、Scope、Policy、风险等级、审计字段，这是后续开放能力的基础。
阶段 2

MVP：Skill + 聚合 API

快速跑通授权登录、品牌切换、只读问答和少量低风险操作，验证员工使用体验。
阶段 3

升级为 MCP 主执行层

把查询、分析、执行、管理类能力全部纳入 MCP，统一接审计、限流、风险控制和版本治理。
阶段 4

引入受限 CLI 执行器

只面向内部后台，用于索引重建、批量修复、同步诊断，不直接暴露给员工。
阶段 5

产品化前端与审批流

补齐授权管理页、能力展示页、高风险确认、导出审批和审计回放能力。

最终建议

对网站员工开放的 OpenClaw 类智能体，最佳落地方式不是只做 Skill，也不是直接开放 CLI， 而是以 Skill 作为认知编排层、MCP 作为主执行层、 CLI 作为后台受限执行器 的组合架构来实现。
