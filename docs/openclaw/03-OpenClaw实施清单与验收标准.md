# OpenClaw 实施清单与验收标准

## 1. 实施目标

将 OpenClaw 接入当前品牌运营网站系统，使其能够在用户授权后：

- 识别当前用户和品牌上下文
- 查询品牌资料、品牌资产、品牌任务、品牌技能中心配置
- 帮助用户触发低风险网站功能
- 在多品牌场景下保持品牌隔离和权限安全

## 2. 推荐实施阶段

### 阶段一：只读问答 MVP

目标：

- 用户可授权 OpenClaw 登录
- 可获取品牌列表和当前品牌
- 可查询品牌基础资料
- 可查询品牌资产与任务
- 可查询品牌技能中心当前配置

交付物：

- 登录与品牌切换接口
- 品牌资料工具
- 资产与任务工具
- 首版 OpenClaw Skill

### 阶段二：低风险写操作

目标：

- 可触发热点找选题
- 可查询生成任务状态
- 可恢复品牌技能平台基线
- 可修改品牌技能中心提示词

交付物：

- 品牌工作台工具
- 品牌技能中心写操作工具
- 写操作确认机制
- 操作审计日志

### 阶段三：深度品牌运营助手

目标：

- 支持多轮运营问答
- 支持更多工作台能力
- 支持消息渠道内完成问答与操作回传

交付物：

- 更多业务工具
- 更完善的 Skill 路由规则
- 渠道级助手接入

## 3. 后端开发清单

### 3.1 认证与会话

- 梳理现有登录接口是否可供 OpenClaw 直接使用
- 设计 OpenClaw 会话保持机制
- 设计刷新 token 或长期授权票据机制
- 明确 OpenClaw 如何感知当前品牌

### 3.2 品牌上下文

- 提供品牌列表接口
- 提供当前品牌读取接口
- 提供品牌切换接口
- 所有助手接口统一校验品牌上下文

### 3.3 聚合工具层

建议新增一组 `assistant` 聚合接口或 MCP 工具：

- 品牌基础数据工具
- 品牌资料库工具
- 品牌资产工具
- 品牌任务工具
- 品牌技能中心工具
- 品牌工作台工具

### 3.4 权限与审计

- 所有工具统一复用现有品牌权限
- 写操作统一打审计日志
- 明确哪些角色可执行哪些工具
- 明确哪些字段要脱敏返回

## 4. OpenClaw 侧开发清单

### 4.1 接入方式

- 确定是走 REST API、MCP 还是混合模式
- 配置 OpenClaw 到网站的认证方式
- 配置 OpenClaw 的品牌上下文切换逻辑

### 4.2 Skill

- 创建 `brand-ops-assistant` Skill
- 写入系统定位和品牌上下文规则
- 写入数据字典和关系
- 写入工具路由规则
- 写入写操作确认规则

### 4.3 使用体验

- 默认优先问当前品牌
- 未选品牌时先引导用户选品牌
- 所有执行动作前复述影响
- 对失败和权限不足给出明确解释

## 5. 前端网站配合清单

如果后续要做正式产品化接入，建议网站前端补：

- “授权 OpenClaw” 页面或入口
- OpenClaw 集成状态展示
- 当前品牌授权状态展示
- 品牌管理员可查看或撤销 OpenClaw 授权
- 操作日志展示入口

## 7. 风险清单

### 风险 1：直接数据库访问导致越权

说明：

- 如果 OpenClaw 直接连库，很容易绕过品牌权限和业务边界。

控制：

- 禁止直连数据库
- 统一通过助手工具层访问

### 风险 2：跨品牌串数据

说明：

- 多品牌共享一库，查询漏加 `brandId` 会串数据。

控制：

- 工具层所有接口都强制带品牌上下文
- 审查所有查询都必须按品牌隔离

### 风险 3：高风险写操作误触发

说明：

- OpenClaw 若直接执行修改或恢复动作，容易影响业务配置。

控制：

- 写操作前确认
- 执行后记录日志
- 支持撤销或恢复机制

### 风险 4：账号密码方案长期不安全

说明：

- 长期保存密码会放大安全风险。

控制：

- 第一版可临时使用
- 正式版切到授权票据机制

## 8. 验收标准

### 8.1 品牌上下文验收

- 用户登录后，OpenClaw 能正确列出用户可访问品牌
- 切换品牌后，后续问答只读取该品牌数据
- 没有品牌上下文时，OpenClaw 不会直接回答品牌数据

### 8.2 数据读取验收

- 能读取品牌档案
- 能读取产品、账号、竞品、行业资料
- 能读取业务资产和任务
- 能读取品牌技能中心配置

### 8.3 写操作验收

- 能触发热点找选题生成
- 能恢复品牌技能平台基线
- 能修改品牌技能提示词
- 所有写操作都有确认和审计记录

### 8.4 安全验收

- 不返回敏感密钥
- 不跨品牌读数
- 不允许越权修改
- 非品牌管理员无法执行品牌级写操作

## 9. 推荐排期

### 第 1 周

- 梳理现有认证与品牌上下文
- 确定助手工具层接口设计
- 输出 OpenClaw Skill 初稿

### 第 2 周

- 开发只读工具
- 接 OpenClaw 登录与品牌切换
- 跑通只读问答 MVP

### 第 3 周

- 开发低风险写操作工具
- 开发确认机制与审计日志
- 跑通工作台功能触发

### 第 4 周

- 联调消息渠道
- 补监控与错误处理
- 进行小范围内测

## 10. 建议的开发顺序

1. 先做 API / Tool 层
2. 再做 OpenClaw Skill
3. 先做只读
4. 再开放低风险写操作
5. 最后才做更复杂的渠道化产品集成
