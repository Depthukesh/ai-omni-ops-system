OpenChatCut 独立 Docker 部署与双 MCP 集成说明

当前推荐口径：OpenChatCut 独立 Docker 部署，不并入本站主 compose；OpenClaw 同时连接本站 MCP 与 OpenChatCut MCP，形成“本站产素材 -> OpenChatCut 剪辑导出”的闭环。

推荐架构

  • 本站负责品牌、权限、任务、素材、作品与 OpenClaw MCP。
  • OpenChatCut 负责工程、时间线、导入素材、时间线编辑与导出。
  • OpenClaw 作为编排层，同时调用两套 MCP。

为什么独立部署

  • OpenChatCut 当前是 local-first、工程型、单用户倾向的视频编辑器。
  • 上游公开说明以源码运行和桌面包为主，不是官方 Docker 标准发布链。
  • 剪辑、预览、导出、FFmpeg、GPU 与本站品牌后台属于两类不同运行时负载。
  • 独立容器、独立端口、独立持久化目录更容易控制边界与排障。

目录建议

  • OpenChatCut：OpenChatCut 源码目录。
  • docker/local-data/openchatcut/home：承接容器内 HOME 和 ~/.openchatcut。
  • docker/local-data/openchatcut/media：承接本站导出的图片、视频、音频副本。

Docker 样板

仓库内已补充：

  • docker/docker-compose.openchatcut.yml
  • docker/openchatcut.env.example
  • docker/openchatcut.Dockerfile
  • docker/openchatcut-start.sh

当前定位是实施样板，优先服务内网单用户验证闭环；会用自定义启动镜像补齐 Docker 开发态缺失的系统依赖。

services:
  openchatcut:
    build:
      context: ..
      dockerfile: docker/openchatcut.Dockerfile
    image: local/openchatcut-dev:latest
    container_name: openchatcut
    working_dir: /workspace
    init: true
    ports:
      - "${OPENCHATCUT_HTTP_PORT:-15199}:5199"
    environment:
      HOME: /data/home
      MEDIA_DIR: /data/media
      OPENCHATCUT_MCP_TOKEN: ${OPENCHATCUT_MCP_TOKEN:-change-me}
      OPENCHATCUT_EDITOR_URL: ${OPENCHATCUT_EDITOR_URL:-http://127.0.0.1:15199}
      RESOURCE_PREVIEW_TOKEN: ${RESOURCE_PREVIEW_TOKEN:-change-me}
      BROWSER: none
      VITE_CONFIG_NATIVE_IGNORE_WARNING: "true"
    volumes:
      - ${OPENCHATCUT_SOURCE_DIR:-../OpenChatCut}:/workspace
      - openchatcut_node_modules:/workspace/node_modules
      - ${OPENCHATCUT_HOME_DIR:-./local-data/openchatcut/home}:/data/home
      - ${OPENCHATCUT_MEDIA_DIR:-./local-data/openchatcut/media}:/data/media
    restart: unless-stopped

volumes:
  openchatcut_node_modules:

启动步骤

  1. 检出 OpenChatCut 源码。
  2. 复制 docker/openchatcut.env.example 为 docker/openchatcut.env，并改成真实路径、端口和 Token。
  3. 执行带 --build 的独立 compose。
  4. 首次启动会先安装依赖并同步 MediaPipe / whisper-cli，耗时会明显更长。
  5. 确认 15199 页面可打开，再验证 MCP 地址。
  6. 最后让 OpenClaw 同时绑定本站 MCP 与 OpenChatCut MCP。
docker compose --env-file "docker/openchatcut.env" -f "docker/docker-compose.openchatcut.yml" up -d --build

首次启动说明

  • 当前 Docker 样板会先执行 npm install --ignore-scripts --package-lock=false，避免 onnxruntime-node 的原生安装链直接炸掉。
  • 随后会执行 sync-mediapipe、sync-whisper-cli 和工具目录校验，再进入 OpenChatCut 开发态。
  • 启动镜像内已额外安装 git 和 unzip，以满足 dev-profile 与 sync-whisper-cli 的运行要求。
  • 当前额外挂了 openchatcut_node_modules 卷，避免每次重启都全量重装依赖。

双 MCP 口径

  • 本站 MCP：生成图片、视频、音频、字幕、BGM、音效等素材。
  • OpenChatCut MCP：创建工程、导入素材、组织时间线、导出成片。
  • OpenClaw：同时调用两边，不把视频剪辑逻辑塞回本站后台。

OpenChatCut 统一模型网关

如果希望 OpenChatCut 的 Agent、图片、音频、视频、音乐能力统一走本站，而不是在 OpenChatCut 内分别保存品牌级模型 Key，当前推荐直接接本站新增的 OpenChatCut 专用网关：

https://你的域名/api/openclaw/openchatcut-gateway

统一请求头继续使用 OpenClaw 安装中心导出的品牌安装令牌：

Authorization: Bearer ocp_xxx
x-brand-id: br_xxx

当前已暴露的路径包括：

  • 文本 / Agent：GET /v1/models、POST /v1/chat/completions、POST /v1/responses、POST /v1/messages
  • 图片 / 音频：POST /v1/images/generations、POST /v1/audio/speech、POST /v1/audio/transcriptions、POST /v1/audio/translations
  • 视频 / 音乐：POST /v1/videos、GET /v1/videos/:taskId、POST /suno/submit/:action、GET /suno/fetch、GET /suno/fetch/:taskId

这层网关背后会先校验 OpenClaw 安装令牌与品牌一致性，再读取当前品牌在“个人中心 - 第三方平台”里配置的多元探索共享 Key，最后由服务端代 OpenChatCut 转发给多元探索。

OpenChatCut 里怎么填

建议优先按下面四组口径填写，先跑通，再决定是否细分到更多厂商页。

  • A 类：Agent 大脑
    页面：设置 -> API 密钥 -> Agent 模型 -> OpenAI
    填写：API URL = https://你的域名/api/openclaw/openchatcut-gateway、API Key = OpenClaw 安装令牌、接口格式 = Chat Completions API、模型 = gpt-4o
  • B1 类：生图 / 图生图
    页面：设置 -> API 密钥 -> AI 生成 -> 生图 -> OpenAI
    填写：Base URL = https://你的域名/api/openclaw/openchatcut-gateway、API Key = OpenClaw 安装令牌、模型 = gpt-image-2
  • B2 类：配音 / TTS 与转写
    第一阶段先统一指向 OpenAI 兼容页。配音：Base URL = https://你的域名/api/openclaw/openchatcut-gateway、模型 = tts-1 或 tts-1-hd；转写：Base URL = https://你的域名/api/openclaw/openchatcut-gateway、模型 = whisper-1
  • C 类：生视频 / 生音乐
    视频：Base URL = https://你的域名/api/openclaw/openchatcut-gateway、模型 = omni-fast；音乐：Base URL = https://你的域名/api/openclaw/openchatcut-gateway、模型 = chirp-v4

可替换模型示例：文本可用 claude-sonnet-4-6、gemini-2.5-pro；生图可用 gemini-3.1-flash-image-preview、jimeng-4.5；视频可用 Kling-3.0-Omni、Hailuo-2.3。

先打 curl 再回到页面

建议先用安装令牌验证两条最小命令，确认安装令牌、品牌头和多元探索共享 Key 都已连通。

curl -X GET "https://你的域名/api/openclaw/openchatcut-gateway/v1/models" \
  -H "Authorization: Bearer ocp_xxx" \
  -H "x-brand-id: br_xxx"
curl -X POST "https://你的域名/api/openclaw/openchatcut-gateway/v1/chat/completions" \
  -H "Authorization: Bearer ocp_xxx" \
  -H "x-brand-id: br_xxx" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"gpt-4o\",\"messages\":[{\"role\":\"user\",\"content\":\"你好，请返回一个 ok\"}]}"

验证清单

  • OpenChatCut 独立容器可启动。
  • 15199 页面可打开。
  • OpenChatCut MCP 可连通。
  • OpenClaw 可同时挂本站 MCP 与 OpenChatCut MCP。
  • 本站生成的一张图、一个音频、一个视频片段可导入 OpenChatCut。
  • OpenChatCut 可完成一次最小时间线编辑并导出测试成片。

当前边界提醒

  • 这里提供的是本站实施样板，不是 upstream 官方标准 Docker 发布物。
  • 第一阶段按单用户 / 单工作区联调，不把 OpenChatCut 当多租户共享剪辑服务。
  • 外部 MCP 偏编辑会话与时间线草稿；导出、删除工程等副作用动作要单独确认工具面与审批策略。
