OpenClaw 正式安装与网站对接说明

截至 2026-06-12，安装链路已基本完成，但按最新产品口径，MCP 还不能定义为“全部开发完成”。

当前结论

  • 安装中心、品牌令牌、MCP HTTP 网关已经打通。
  • 当前 MCP 工具面已扩到约 54 个，覆盖品牌、任务、知识库、内容生成、发布接力和技能配置治理。
  • 但“生成结果反馈、反馈分析、提示词优化闭环”尚未落地。
  • 因此当前不建议定义为 MCP 全部开发完成，也不建议马上进入正式 Skill 开发。

目标

正式交付时，品牌用户不需要理解 MCP、Skill、CLI 差异，也不需要暴露网站登录密码。用户只需要登录网站，切到目标品牌，打开安装中心，复制配置，粘贴到 OpenClaw、WorkBuddy、Cursor 或 Claude Desktop 即可。

  • 当前真正需要安装的是网站 MCP。
  • 页面里的“品牌运营助手 Skill”目前仍是官方说明和示例，不是正式执行包。
  • 后续正式 Skill 也应调用网站 MCP，而不是复制网站原生功能。

安装片段示例

{
  "mcp": {
    "servers": {

        "transport": "streamable-http",

          "Authorization": "Bearer ocp_xxx",

      }
    }
  }
}

当前 MCP 开发状态

  • 已完成：品牌上下文、任务、知识库、小红书、抖音、设计、公众号、发布接力、技能配置治理等主线。
  • 未完成：生成结果反馈、反馈与技能/提示词绑定、反馈分析、提示词优化建议、完整调用审计。
  • 结论：MCP 已基本可用，但还没到“全部开发完成”。

Skill 与 MCP 的关系

  • 网站里的技能和提示词，是唯一生产内核。
  • MCP 负责把网站能力、配置、数据和状态暴露出来。
  • 未来正式 Skill 的主要职责应是编排、跟踪、反馈回流和优化建议，而不是复制网站功能。
  • 在反馈闭环落地前，不建议进入正式 Skill 开发。

进入 Skill 开发前的条件

  1. 已支持提交生成结果反馈
  2. 已能把反馈与任务、作品、技能、提示词绑定
  3. 已能查看某个技能最近的问题分布与失败模式
  4. 已能输出提示词优化建议
  5. 已补充关键调用日志和效果统计

当前阶段结论

  • MCP 安装链路：已完成
  • MCP 核心业务能力：已完成大半
  • MCP 技能治理能力：已开始接入
  • MCP 反馈优化闭环：未完成
  • 正式 Skill 开发：暂缓
