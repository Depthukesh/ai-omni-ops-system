# AI 全域运营系统页面调研

## 调研范围

本次只基于真实前端路由与页面入口文件做调研，不改正式代码，不更新 `docs/` 基线文档。

调研目标：

1. 梳理当前有哪些真实页面
2. 明确每个页面的主要作用
3. 判断哪些页面更像导航壳层，哪些页面是真正的业务操作页
4. 为后续 `finesse-brief` 和 `finesse-ui` 方案提供真实依据

## 总体判断

- 当前系统的页面问题，不是“功能不够”，而是“同层级入口过多、语义层级不够清晰”
- 顶部导航、工作台侧导航、页面内 tab、列表页、详情页，常常同时出现
- 用户很容易知道“系统很大”，但不容易一眼知道“下一步先做什么”
- 适合本轮优化的，不是继续加卡片，而是做入口减法、分层收口、统一页面气质

### 三、品牌增长页内结构

`/brand-growth` 当前是系统信息架构最完整的一页，主要分为 4 组：

1. `品牌资料库`
   - 品牌背景资料
   - 产品资料库
   - 品牌运营情况
   - 第三方数据
   - 企业知识库
2. `收集数据`
   - 小红书
   - 抖音
   - 公众号
   - 每日热点
3. `品牌增长报告`
   - 机会洞察
   - 生成品牌增长报告
   - 品牌增长可视化报告
   - 半年营销规划
   - 营销日历
   - 选题库
   - 素材库
4. `OpenClaw 专区`
   - 每日计划
   - 每日复盘

判断：

- 它更像整个系统的“经营总台”
- 但由于模块较多，当前首屏很容易显得重
- 后续最适合承担“系统内首页”的角色

### 四、平台工作台结构

#### 1. `/xiaohongshu`

- 原创笔记
- 二创笔记
- 视频笔记
- OpenClaw 每日计划 / 每日复盘

判断：

- 已经相对收口
- 更像“创作执行工作台”
- 不适合再承担系统首页角色

#### 2. `/douyin`

- 营销策划方案
- 原创文案
- 二创文案
- 复刻短视频
- AI 生视频（故事板）
- AI 生视频
- 数字人
- RunningHub 应用
- 广告预审
- OpenClaw 创作素材 / 每日计划 / 每日复盘 / 视频作品

判断：

- 当前最重、最复杂
- 功能很多，但层级跨度也最大
- 非常需要“浅层入口 + 深层资源页”两级结构

#### 3. `/wechat`

- 配置初始化
- 创作工作流
- 发布历史
- OpenClaw 每日计划 / 每日复盘

工作流当前分为：

1. 输入
2. 文章
3. 生图
4. HTML
5. 发布确认
6. 结果

判断：

- 典型流程型页面
- 适合做成分步工作流，不适合塞太多总览卡片

#### 4. `/more-features/design`

- 图片设计
- HTML 设计
- PPT 设计
- 视频设计

判断：

- 属于“能力工坊”
- 模块边界清楚，但当前仍偏功能列表式
- 更适合工具台气质，而不是大而杂的综合页

## 当前界面问题归纳

### 1. 入口过多，但优先级不清

- 用户能看到很多入口
- 但不知道今天应该先去哪个

### 2. 业务页和配置页视觉权重过于接近

- 执行型页面
- 配置型页面
- 安装说明页
- 测试链路页

当前整体还没有形成足够清晰的视觉分层。

### 3. 页面更像“模块集合”，不够像“操作台”

- 很多页面能说明系统很强
- 但不能快速推动用户进入下一步动作

### 4. 顶部导航承担过多

- 当前顶栏同时负责品牌跳转、系统认知和板块切换
- 在工作台越来越多后，信息负担偏重

## 适合本轮优化的方向

1. 让 `/brand-growth` 承接真正的系统内首页角色
2. 平台页回到“执行工作台”定位，不再承担总入口解释任务
3. 个人中心改成“账户与配置驾驶舱”
4. 后台保持高密度，但视觉上与前台系统分层
5. 所有页面统一减少说明型文案，强调：
   - 当前状态
   - 下一步动作
   - 最近结果
