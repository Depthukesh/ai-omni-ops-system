# 系统内页优化方案

本次按 `finesse-brief` 的方法，先基于真实页面结构做减法，再给出 3 套可落地的页面优化方向。

共同目标：

- 页面简洁
- 信息清晰
- 一眼知道下一步做什么
- 更符合现在的产品审美，而不是传统后台堆叠

---

## 方案 A：总控首页型

### 核心判断

把 `/brand-growth` 明确提升为“系统内首页”。

它不是普通工作台，而是整套系统的总控台，负责：

- 看品牌状态
- 看今天重点
- 决定先做采集、报告、创作还是发布

### 结构

1. 顶部极简导航
2. 今日经营主卡
3. 三个核心入口
   - 数据采集
   - 报告洞察
   - 内容执行
4. 最近结果
5. 次级入口收纳区

### 适合页面

- `/brand-growth`
- 顶部全局导航
- 登录后的默认第一页

### 优点

- 最容易一目了然
- 最适合作为系统入口
- 对用户认知最友好

### 风险

- 要求对现有入口做明显裁剪
- 次级模块必须收纳，不能继续平铺

---

## 方案 B：工作台指挥舱型

### 核心判断

把系统内页做成“指挥舱”，首页不是介绍系统，而是直接显示：

- 当前任务
- 当前运行状态
- 当前资源
- 当前待处理事项

更适合高频使用者。

### 结构

1. 左侧主导航
2. 中间主工作区
3. 右侧轻量状态栏
4. 顶部只保留搜索、品牌切换、个人入口

### 适合页面

- `/brand-growth`
- `/personal-center`
- `/douyin`

### 优点

- 专业感更强
- 更像成熟工作台
- 对高频用户效率更高

### 风险

- 首次进入的用户理解成本略高
- 需要更强的状态设计，而不是简单卡片堆叠

---

## 方案 C：流程地图型

### 核心判断

把系统信息架构从“按板块分”改成“按动作流程分”。

用户进入系统后先看到：

1. 采集
2. 洞察
3. 规划
4. 生产
5. 发布
6. 复盘

平台页只是这些步骤的执行面板。

### 结构

1. 首屏展示当前流程阶段
2. 中部展示每个阶段的状态
3. 下方展示进入对应平台的入口
4. 右侧展示今日重点和阻塞项

### 适合页面

- `/brand-growth`
- 跨平台总览页
- 多团队协同场景

### 优点

- 非常贴合系统真实业务闭环
- 更容易让用户理解整个系统的逻辑
- 有利于后续扩展更多平台

### 风险

- 需要更强的信息建模
- 首屏不是传统后台，需要更精细的交互设计

---

## 结论建议

如果只选一个方向作为正式改版起点：

### 推荐顺序

1. 方案 A：总控首页型
2. 方案 C：流程地图型
3. 方案 B：工作台指挥舱型

### 推荐原因

- 方案 A 最稳，最适合先落地
- 方案 C 最符合系统长期业务结构
- 方案 B 视觉最成熟，但对信息组织要求最高

## 对各类页面的匹配建议

### 首页 `/brand-growth`

- 优先用 A 或 C

### 平台工作台 `/xiaohongshu` `/douyin` `/wechat`

- 采用 B 的壳层逻辑
- 但内容仍按各平台自己的执行链组织

### 个人中心 `/personal-center/*`

- 用 B
- 做成轻量配置驾驶舱

### 后台 `/admin`

- 保持高密度
- 不跟前台共用同一种首屏表达

### 帮助页 `/help/*`

- 统一成简洁教程模板
- 不再混入前台业务页风格
