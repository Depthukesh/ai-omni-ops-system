# 结构的精细化处理（骨架）

## 一、资料来源

本专题主要依据以下资料提炼：

- `021_进阶篇：结构的精细化处理(骨架)`
- `015_基本功篇：大纲架构与材料组织思维`
- `018_进阶篇：信息效率思维`

## 二、骨架的本质

骨架不是文案格式，而是内容推进逻辑。  
它解决的问题是：

- 用户为什么愿意继续看
- 你准备按什么顺序说服对方
- 你的信息如何层层推进，而不是平铺直叙

如果钩子解决“停留”，骨架解决的就是“看下去”。

## 三、骨架失败的典型表现

- 讲到一半跑题
- 内容点太多，没有主次
- 观众不知道你想证明什么
- 前后重复
- 结尾收不住

## 四、常见高效骨架模型

### 1. 三点式

最适合知识型、判断型、建议型内容。

结构：

- 结论或问题
- 三个关键点
- 总结与动作

### 2. 对比式

适合帮助用户做选择。

结构：

- 两种情况对比
- 差异说明
- 如何判断适合哪一种

### 3. 错误 - 代价 - 正解

适合避坑与转化内容。

### 4. 场景 - 冲突 - 解决

适合同城服务类、生活场景类、门店经营类内容。

### 5. 案例推进式

适合用客户故事、老板经历、真实服务过程说服用户。

## 五、骨架设计的实操原则

### 1. 先有主判断，再有结构

如果你连主判断都没有，骨架再完整也会空。

### 2. 一个视频最好只解决一个主问题

不要一条视频里试图解决所有问题。

### 3. 每个段落都要承担任务

- 这一段是解释
- 这一段是举例
- 这一段是证明
- 这一段是推动行动

### 4. 骨架应服务用户理解顺序，而不是作者写作顺序

你自己想到什么先后，并不等于用户最适合怎么接收。

## 六、同城商家最适合的骨架

对于同城品牌商家，最稳的骨架往往是以下几种：

- 问题 - 判断 - 建议
- 场景 - 错误 - 后果 - 正解
- 客户情况 - 判断原因 - 解决方案
- 人群点名 - 三个关键标准 - CTA

因为这些骨架更容易和“咨询”“预约”“到店”形成连接。

## 七、AI Agent 调用要求

调用本专题时，AI Agent 应至少输出：

- 内容主判断
- 骨架类型
- 分段结构
- 每段任务
- 段落间推进逻辑
- 结尾动作

## 八、骨架质检清单

- 是否存在清晰主判断
- 是否一条内容只围绕一个主问题
- 是否段落任务明确
- 是否没有重复解释
- 是否能自然进入 CTA

## 九、使用提醒

- 不要把“分段”误当成“有骨架”
- 不要堆信息代替结构
- 不要骨架很整齐，但缺乏真实证明
- 不要结尾突然结束，没有行动引导

本专题适合所有脚本型任务，尤其适合需要做“结构重写”和“脚本诊断”的场景。
