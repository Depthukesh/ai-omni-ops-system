# 公众号创作文章

基于 `baoyu-post-to-wechat` 技能中的文章工作流拆分而来，当前平台限定为 `API-only` 公众号文章链路，不允许走 browser 发布。

## 适用范围

- 用于公众号创作工作流中的“生成或编辑文章内容”阶段。
- 输入可以来自营销日历、品牌资料、产品资料、用户补充要求、已有 markdown/html/plain text 内容。
- 输出必须服务于后续“生图”和“API 发布确认”阶段。

## 工作流上下文

原始技能主链路为：

1. 加载 `EXTEND.md` 偏好
2. 多账号解析
3. 判断输入类型
4. 解析发布方式与凭证
5. 解析标题 / 摘要 / 作者 / 主题
6. 生成公众号可发布内容
7. 调用 `draft/add` 完成 API 发布

在本项目中，本技能只负责第 3-6 步里的文章生成部分，不负责真实发布。

## 输入要求

至少综合以下上下文：

- 文章主题
- 品牌名 / 品牌调性 / 品牌故事
- 营销节点或活动标签
- 产品卖点 / 产品标签
- 作者名
- 主题色
- 账号信息（若有）
- 用户指定的风格、篇幅、结构和禁用词
- 当前输入类型：`plain-text` / `markdown` / `html` / `calendar`

## 生成目标

输出一份适合微信公众号草稿箱 API 的文章草稿，要求：

- 保留公众号阅读习惯，开头直接进入主题
- 标题清晰，不夸张，不过度营销
- 自动补齐摘要，控制在适合草稿箱摘要字段的长度
- 自动补齐作者，优先级遵循：用户输入 > frontmatter > 工作流偏好 > 账号默认作者
- 正文结构适合后续生成封面图与正文配图
- 为后续 API 发布保留封面图位和图文层次

## 结构规范

文章建议输出以下结构：

1. 标题
2. 摘要
3. 导语
4. 2-4 个主体章节
5. 品牌/产品/场景植入段
6. 行动建议或结尾总结

同时要求：

- 合理使用二级标题和三级标题
- 段落长度适中，避免连续大段文字
- 允许使用引用块、列表、强调句
- 每个主体章节都要给出一个适合配图的场景锚点

## 链接与引用规则

参考原技能 `article-posting.md`：

- markdown 输入默认将普通外链转换为文末引用更友好的表达
- 如果输入中已有 HTML，则尽量保持原有结构不做破坏性重写
- 不要输出无法在微信公众号中稳定呈现的复杂脚本或交互结构

## HTML 输出要求

输出必须是适配公众号长文的 HTML 草稿，要求：

- 语义结构清晰
- 段落、标题、引用、列表完整
- 不插入脚本
- 不写浏览器自动化相关内容
- 不包含最终发布 API 请求体

## 生图协同要求

文章输出时必须同时为后续生图阶段留出明确依据：

- 提炼 1 条封面图主视觉说明
- 提炼 2-4 条正文配图说明
- 每条说明需对应到具体章节或段落主题
- 场景描述、主体对象、情绪、色彩风格要明确

## 禁止事项

- 禁止输出“请手动去浏览器发布”之类指令
- 禁止假设 browser/CDP 可用
- 禁止直接生成 `draft/add` 最终请求结果
- 禁止省略摘要、作者、章节结构
- 禁止生成与公众号审核风险高的夸张营销文案、医疗承诺、收益承诺

## 推荐输出格式

按以下逻辑组织结果：

1. `title`
2. `summary`
3. `author`
4. `htmlContent`
5. `coverImageBrief`
6. `bodyImageBriefs`

其中：

- `coverImageBrief` 用一句话概括封面图核心视觉
- `bodyImageBriefs` 为数组，每项对应一个章节配图需求
