# 公众号HTML渲染

用于公众号工作流中的“生成 HTML”阶段，当前平台限定为 `API-only` 公众号文章链路，不允许走 browser 发布。

## 适用范围

- 输入来自已确认的标题、摘要、作者、正文纯文本、封面图、正文配图、主题色，以及 `htmlStyleConfig` 风格参数。
- 输出必须服务于后续“API 发布确认”和真实发布阶段。
- 生成逻辑必须像成熟公众号排版工具一样，以“输入参数 -> 结构映射 -> 样式输出”的方式工作，不能只做轻微配色差异。

## 结构目标

输出一份最终可发布的公众号 HTML，要求：

- 保持公众号长文阅读习惯，开头直接进入主题
- 结构清晰，包含标题区、摘要区、正文区和结尾总结
- 将封面图和正文配图自然植入对应章节
- 使用适合公众号的段落、标题、引用、列表、强调块、步骤块、提示块和轻量画廊
- 兼顾移动端阅读与 API 发布稳定性
- 必须服从 `htmlStyleConfig`，根据主题风格、布局方式、字体、字号、密度和引用方式生成明显不同的排版效果

## 参数映射

- `themePreset`
  - `magazine`：更强标题区、摘要卡、章节分隔，适合品牌专题与长文
  - `newspaper`：更克制的专栏结构和更高信息密度
  - `tech`：信息卡、步骤块、方法论分组更明显
  - `ink`：低彩度、留白和叙事感更强
  - `notion`：规整、轻卡片、知识整理感
  - `minimal`：尽量接近微信原生、风险最低
- `layoutPreset`
  - `hero-card`：标题与摘要形成明确头图卡片区
  - `standard`：稳定长文结构
  - `magazine`：章节模块化更明显
  - `immersive`：更强调导语、引用与叙事流动
- `fontFamily` / `fontSize` / `density`
  - 必须真实影响正文、摘要、引用、列表和卡片间距
- `citationMode`
  - `inline`：普通外链保留正文内联
  - `footnote`：普通外链转成文末 `引用链接` 区块，微信公众号链接可保留直链

## 内容增强

在不破坏原文结构的前提下，应主动识别并增强适合公众号的片段：

- 连续短句或问答：可整理成对话块
- 核心观点、提醒、方法论：可整理成强调块或提示块
- 多张正文图片：可整理成轻量画廊
- 步骤型内容：可整理成编号步骤块

## 输出要求

- 只输出 `htmlContent`
- `htmlContent` 必须是完整 HTML 文档或结构完整的单页 HTML
- `htmlContent` 必须是单行字符串，不能在 JSON 字符串里直接输出原始换行
- HTML 属性统一使用单引号
- 如果已给出 `coverImageUrl` 和 `bodyImageUrls`，必须直接使用真实图片 URL
- 图片必须紧跟对应正文段落或章节出现，图文之间只允许紧凑留白，常规上下间距控制在 `12px-20px`
- 禁止为图片额外创建大面积空白容器、占位块或超高 section / figure
- 禁止使用过大的 `margin-top`、`margin-bottom`、`padding-top`、`padding-bottom`、`min-height` 来制造图片区留白
- 禁止附加“营销日历资料 / 产品资料 / 品牌资料 / 原文链接 / 创作来源 / 素材说明 / 附录”等尾部区块
- 必须让不同 `htmlStyleConfig` 组合产生肉眼可见的差异，不能只是颜色深浅变化
